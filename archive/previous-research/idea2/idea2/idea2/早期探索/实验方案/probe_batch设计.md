# Probe Batch 设计方案

> 创建时间：2026-09-02
> 用途：设计 idea2 实验中 probe batch 的挑选策略与任务分类方案

---

## 一、目标

从 Vision-OPD-6K 训练集中挑选一组**固定的 probe batch**（100-200 条样本），在整个训练过程中用这同一批样本探测对齐度，保证跨 step 的可比性。

**关键要求**：
1. **覆盖不同任务类型**：视觉 grounding / 图表理解 / OCR / 常识问答等
2. **样本质量稳定**：不能选太简单（所有方法都对）或太难（所有方法都错）的样本
3. **可复现**：随机种子固定，确保每次实验用同一批样本

---

## 二、任务分类方案

### 2.1 任务类型定义

根据 Vision-OPD 的数据特点，定义以下任务类型：

| 任务类型 | 描述 | 典型样本 | 预期对齐模式 |
|---------|------|---------|-------------|
| **视觉 Grounding** | 需要定位图中特定区域 | "图中红色的车在哪里？" | 预期：VL 教师优势大，对齐度可能较低（Text 教师没看图） |
| **图表理解** | 解读图表、表格 | "这个柱状图显示的趋势是什么？" | 预期：两教师都强，对齐度可能较高 |
| **OCR** | 读取图中文字 | "图中招牌上写的是什么？" | 预期：VL 教师优势大（Text 看不见） |
| **常识问答** | 需要世界知识 | "这个人可能在做什么？" | 预期：Text 教师可能更强（有语言知识） |
| **细粒度识别** | 识别细节特征 | "这只鸟是什么种类？" | 预期：VL 教师优势大 |
| **推理** | 多步推理 | "根据图中线索，接下来会发生什么？" | 预期：两教师互补，对齐度中等 |

### 2.2 分类方法

**方案 A：人工分类**
- 随机抽 200 条，人工标注任务类型
- 优点：准确
- 缺点：耗时（~2 小时）

**方案 B：自动分类（推荐）**
- 用 Text 教师（Qwen2.5-7B-Instruct）对每条样本的 prompt 做分类
- Prompt：
  ```
  请将以下问题分类到以下任务类型之一：
  - 视觉Grounding
  - 图表理解
  - OCR
  - 常识问答
  - 细粒度识别
  - 推理
  
  问题：{prompt}
  分类：
  ```
- 优点：快（几分钟跑完）
- 缺点：可能不准确，需要人工抽查

**方案 C：混合**
- 先用方案 B 自动分类
- 再人工抽查 20% 样本，验证准确率
- 如果准确率 < 80%，调整 prompt 或改用人工

**建议**：先用方案 B，快速得到初版；Week 2 再做人工验证。

## 三、样本挑选策略

### 3.1 分层抽样

按任务类型分层，每类抽 30-40 条，总计 ~200 条。

| 任务类型 | 计划数量 | 挑选标准 |
|---------|---------|---------|
| 视觉 Grounding | 35 | 中等难度（VL 教师准确率 40-80%） |
| 图表理解 | 35 | 中等难度 |
| OCR | 35 | 中等难度 |
| 常识问答 | 35 | 中等难度 |
| 细粒度识别 | 30 | 中等难度 |
| 推理 | 30 | 中等难度 |
| **总计** | **200** | |

### 3.2 "中等难度"的定义

**避免的样本**：
- **太简单**：所有教师都能答对（对齐度天然高，没信息量）
- **太难**：所有教师都答错（对齐度也高，但没信息量）

**目标样本**：
- VL 教师和 Text 教师**表现不一致**（一个对一个错，或两个都对但置信度不同）
- 这类样本的对齐度最有分析价值

**挑选方法**：
1. 先用 VL 教师和 Text 教师分别跑推理（不需要训练，直接用基座模型）
2. 对每条样本，记录两教师的准确率和置信度
3. 挑选"两教师表现差异大"的样本
4. 按任务类型分层，每类挑 30-40 条

### 3.3 随机种子

- 固定 `random_seed = 42`
- 所有抽样操作用这个种子
- 确保可复现

## 四、Probe Batch 文件格式

### 4.1 数据结构

```python
{
    'sample_id': int,                    # 样本 ID（在 Vision-OPD-6K 中的 index）
    'prompt': str,                        # 原始 prompt
    'image_path': str,                    # 图片路径
    'task_type': str,                     # 任务类型（人工或自动分类）
    'gt_answer': str,                     # ground truth 答案（如果有）
    'vl_teacher_accuracy': float,         # VL 教师基座模型的准确率（预计算）
    'text_teacher_accuracy': float,       # Text 教师基座模型的准确率（预计算）
    'difficulty': str,                    # 'easy' / 'medium' / 'hard'
}
```

### 4.2 存储格式

- **JSONL**：每行一个样本，方便流式读取
- 文件名：`probe_batch_200.jsonl`
- 存放路径：`research/main/idea2/实验方案/data/probe_batch_200.jsonl`

## 五、实施步骤

### Step 1：准备基座模型推理脚本（Week 2 Day 1-2）

- 加载 VL 教师（Qwen3.5-4B-VL）和 Text 教师（Qwen2.5-7B-Instruct）
- 对 Vision-OPD-6K 全集跑推理，记录准确率和置信度
- 保存结果到 `teacher_predictions.jsonl`

### Step 2：自动分类任务类型（Week 2 Day 3）

- 用 Text 教师对每条样本的 prompt 做分类
- 保存结果到 `task_classification.jsonl`

### Step 3：挑选 probe batch（Week 2 Day 4-5）

- 按任务类型分层
- 每类挑 30-40 条"中等难度"样本
- 总计 ~200 条
- 保存到 `probe_batch_200.jsonl`

### Step 4：人工验证（Week 2 Day 6-7）

- 随机抽 20% 样本，人工验证任务分类
- 如果准确率 < 80%，调整分类 prompt 或改用人工

### Step 5：集成到训练流程（Week 3）

- 在 verl 训练循环里加载 probe batch
- 每 N 步对 probe batch 跑 probe（两个教师的 forward）
- 记录对齐度 metric

## 六、风险与对策

| 风险 | 对策 |
|------|------|
| **任务分类不准** | 人工验证 20% 样本；如果不准，改用人工分类 |
| **找不到"中等难度"样本** | 放宽标准，允许部分简单/困难样本；或增加 probe batch 大小 |
| **probe 开销太大** | 减少 probe 频率（从每 10 步改为每 20 步）；或减少 probe batch 大小（从 200 改为 100） |
| **任务类型覆盖不全** | 先跑一轮自动分类，看有哪些任务类型；如果发现新类型，调整分类方案 |

## 八、备注

- Probe batch 一旦选定，**整个训练过程都用同一批**，保证跨 step 可比性
- 如果训练超参变了（如 learning rate），需要**重新跑一组**，但 probe batch 可以复用
- 建议把 probe batch 的挑选过程也记录下来（写个 script），方便复现
