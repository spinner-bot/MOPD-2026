## 一、硬件环境：两台机器，两种角色

### 1.1 你的本地机器：Windows 11 + RTX 5060 Laptop (8GB)

| 组件 | 规格 | 能做什么 | 不能做什么 |
|------|------|---------|-----------|
| CPU | Intel/AMD 笔记本处理器 | 运行编辑器、git、轻量 Python | 大规模并行计算 |
| GPU | RTX 5060 8GB | 跑几行测试代码、`import torch` 检查语法 | 训练/推理大模型（需 20-80GB 显存） |
| RAM | 16/32GB | 开多个程序 | 加载大模型权重 |
| 磁盘 | SSD 512GB/1TB | 存代码、文档、小数据集 | 存所有模型权重（一个就要几十GB） |

**本地机器只用来做三件事**：
1. 写代码和文档（用 VS Code 或任何编辑器）
2. 用 git 管理版本
3. 通过 SSH 连接到 H200 服务器

**绝对不要在本地跑训练** —— RTX 5060 的 8GB 显存连最小的 Qwen3.5-4B 模型都加载不了（需要约 8-16GB）。

### 1.2 远程服务器：8×H200 (80GB × 8 = 640GB 总显存)

H200 是 NVIDIA 的**数据中心级 GPU**，2024年发布。和你的 RTX 5060 对比：

| 特性 | RTX 5060 Laptop | H200 |
|------|----------------|------|
| 定位 | 消费级游戏/轻薄本 | 数据中心训练/推理 |
| 显存 | 8GB GDDR7 | 80GB HBM3e（10倍） |
| 显存带宽 | ~256 GB/s | 4.8 TB/s（~19倍） |
| 张量核心 | 有，但少 | 密集，专为 Transformer 优化 |
| 价格 | 笔记本的一部分 | ~$30,000/张 |
| 你拥有的数量 | 1 张 | **8 张** |

**8×H200 能做什么？**
- 加载 Qwen3.5-9B（需要 ~18GB）+ vLLM 推理服务
- 用 FSDP 分片训练 4B-9B 的多模态模型
- 同时跑多个实验

**为什么是 8 张？** 因为分布式训练会把模型切分到多张卡上。8 张 H200 用 FSDP（Fully Sharded Data Parallel）可以高效训练 9B 参数的模型。

## 二、网络环境：你怎么连上 H200

### 2.1 SSH 是什么？

SSH（Secure Shell）是一种**加密的远程登录协议**。简单说：你在笔记本上打字，命令在 H200 上执行，结果传回来显示。

```
你在 MobaXterm 输入 → SSH 加密传输 → H200 执行 → 结果加密传回 → MobaXterm 显示
```

### 2.2 你的连接路径（跳板机架构）

大学服务器通常不直接暴露在公网。你需要先连到一个"跳板机"（jump host），再从跳板机跳到 H200。

```
你的笔记本 (家里/宿舍)
    │
    │ SSH (端口 22)
    ▼
跳板机 (210.45.76.135:22, 用户 2001ljy)
    │
    │ SSH (内网转发)
    ▼
H200 服务器 (114.214.244.8:22, 用户 shiqiushi)
```

你的 SSH 配置（`C:\Users\han\.ssh\config`）已经配好了这个路径：

```
Host H200
    HostName 114.214.244.8
    User shiqiushi
    Port 22
    IdentityFile C:\Users\han\.ssh\id_rsa
    ProxyCommand ssh -q -W %h:%p jump   ← 这一行实现"先过跳板机"
```

**连接方式**：在 MobaXterm 中新建 Session，选择 Host = `H200`（或直接在终端输入 `ssh H200`）。

### 2.3 SSH 密钥是什么？

SSH 密钥是一对文件：
- **私钥** (`id_rsa`)：你保管，绝对不要发给任何人（相当于你的密码）
- **公钥** (`id_rsa.pub`)：放在服务器上（相当于门锁）

连接时，服务器用公钥加密一段随机数据，只有拥有私钥的你才能解密并回应。这样就不需要每次输入密码了。

**当前状态**：你的公钥 (`C:\Users\han\.ssh\id_rsa.pub`) 需要服务器管理员添加到 H200 的 `~/.ssh/authorized_keys` 文件中。这应该是你已经解决了的（你提到用 MobaXterm 成功连上了）。

### 2.4 GitHub SSH 密钥

GitHub push 也需要 SSH 密钥认证。你的 `id_rsa.pub` 内容需要添加到 GitHub 账户的设置中：

1. 打开 https://github.com/settings/keys
2. 点击 "New SSH Key"
3. 粘贴 `C:\Users\han\.ssh\id_rsa.pub` 的全部内容
4. 保存

**当前状态**：⚠️ 尚未添加，导致 `git push` 失败（Permission denied (publickey)）。需要你登录 GitHub 账户 `spinner-bot` 手动添加。

## 三、Python 环境：为什么不能"装一个 Python 就跑"

### 3.1 Python 版本冲突问题

不同论文依赖不同版本的 Python 和库：

```
Vision-OPD:  Python 3.12 + torch 2.10.0 + transformers 5.5.0 + flash-attn
V-Zero:      Python 3.12 + torch (latest) + verl + liger-kernel
PRISM:       Python 3.12 + torch (latest) + patched transformers 4.57.0
DiffusionOPD: Python 3.12 + torch 2.6.0 + diffusers 0.33.1
```

如果你把所有库装在同一个 Python 里 → 版本冲突 → 各种奇怪的报错 → 浪费时间 debug。

### 3.2 Conda：独立环境的解决方案

Conda 给每个论文创建**完全独立的 Python 环境**：

```
H200 服务器
├── conda 环境: vision-opd    (python 3.12, torch 2.10.0, vllm 0.18.0)
├── conda 环境: v-zero        (python 3.12, torch latest, uv)
├── conda 环境: prism         (python 3.12, patched transformers 4.57.0)
└── conda 环境: diffusion-opd (python 3.12, torch 2.6.0, diffusers 0.33.1)
```

激活哪个环境，就是在哪个"小厨房"里工作。环境之间完全隔离，不会互相影响。

**常用命令**：
```bash
conda create -n 环境名 python=3.12 -y   # 创建环境
conda activate 环境名                     # 激活（进入）
conda deactivate                         # 退出
conda env list                           # 列出所有环境
conda remove -n 环境名 --all              # 删除环境（出问题时的重置方法）
```

### 3.3 关于本地 venv

你在本地也创建了 venv（`python -m venv venv`），但这些 venv **只装了个 CPU 版本的 torch**，纯粹用来验证代码没有语法错误。它们**不能用来跑模型**。

```
本地 venv 的作用：
✅ import torch（检查 torch 语法正确）
✅ import transformers（检查导入路径正确）
❌ 加载模型权重
❌ 训练/推理
❌ GPU 计算
```

## 四、GPU 相关概念：你需要知道的关键术语

### 4.1 显存（VRAM / GPU Memory）

显存是 GPU 上的"工作台"。模型权重、优化器状态、中间激活值都存在显存里。

**模型需要多少显存？（粗略估算）**
- 1B 参数 ≈ 2GB（fp16）或 4GB（fp32）
- Qwen3.5-4B ≈ 8GB（仅权重）→ 训练时需要 2-4倍（优化器+梯度+激活） ≈ **24-32GB**
- Qwen3.5-9B ≈ 18GB（仅权重）→ 训练时 ≈ **50-80GB**
- SD3.5-Medium ≈ 5GB（仅权重）→ 训练时 ≈ **20-40GB**

这就是为什么需要 H200（80GB）：单张卡就能装下整个训练过程。

### 4.2 CUDA

CUDA 是 NVIDIA 的 GPU 编程平台。简单理解：PyTorch 里的 `tensor.cuda()` 就是把数据从 CPU 内存搬到 GPU 显存，然后用 CUDA 加速计算。

```python
x = torch.randn(1000, 1000)     # 在 CPU 上
x = x.cuda()                     # 搬到 GPU 上 → 矩阵乘法快 100+ 倍
```

`nvidia-smi` 命令可以查看 GPU 使用情况（显存占用、温度、利用率）。

### 4.3 分布式训练：多张 GPU 一起工作

8 张 H200 不是各自独立跑不同的任务，而是**协同完成同一个训练任务**。主要有几种策略：

#### FSDP (Fully Sharded Data Parallel)
- 把模型参数切碎，每张卡存一份碎片
- 前向/反向传播时，按需从其他卡拿参数
- Vision-OPD 和 V-Zero 主要使用 FSDP

```
模型有 9B 参数 ≈ 18GB
不用 FSDP: 每张卡都要存完整的 18GB → 浪费
用 FSDP:  每张卡只存 18÷8≈2.25GB → 省显存
```

#### DeepSpeed ZeRO
- 微软开发的优化库，比 FSDP 更细粒度
- ZeRO-1：切分优化器状态
- ZeRO-2：切分优化器+梯度
- ZeRO-3：切分优化器+梯度+参数（等同于 FSDP）
- PRISM 使用 DeepSpeed ZeRO-2

#### 梯度累积 (Gradient Accumulation)
论文里说的 "batch size 96" 不代表一次喂 96 个样本。通常：
- 每张卡一次只能处理 1-2 个样本（显存限制）
- 跑 1 步，累积梯度，不清零
- 累积到 96 个等效样本后，才更新一次参数

```
真实 batch size = per_device_batch_size × num_gpus × gradient_accumulation_steps
96 = 2 × 8 × 6
```

### 4.4 vLLM：高效推理引擎

训练是"学习"，推理是"使用学到的知识回答问题"。

vLLM 是一个专为大模型推理优化的引擎。核心创新：
- **PagedAttention**：像操作系统的虚拟内存一样管理 KV-cache，大幅节省显存
- **Continuous Batching**：动态合并请求，提高 GPU 利用率

Vision-OPD 和 V-Zero 的训练代码都使用 vLLM 做 rollout（训练过程中让模型生成回答的步骤）。

## 五、包管理：pip vs conda vs uv

### 5.1 pip
Python 官方包管理器。从 PyPI（python.org 的包仓库）下载并安装库。
```bash
pip install torch               # 安装最新版
pip install torch==2.10.0       # 安装指定版本
pip install -r requirements.txt # 按清单批量安装
```

### 5.2 conda install
Conda 自带的包管理器，从 Anaconda 的仓库下载。**优先使用 pip**，除非 pip 装不上（某些包只有 conda 渠道有）。

### 5.3 uv
Rust 写的极速 pip 替代品。V-Zero 的 H200 部署脚本使用 `uv pip install`。速度比 pip 快 10-100 倍。如果服务器上有 uv 就用，没有就用 pip —— 结果一样。

### 5.4 `pip install -e .` 是什么？
`-e` 代表 editable（可编辑模式）。不会把代码复制到 Python 库目录，而是创建一个指向当前目录的"符号链接"。

好处：**你改了代码 → 不需要重新 pip install → 改动直接生效**。

四个论文的代码都使用这种安装方式（`pyproject.toml` 或 `setup.py` 定义了包名）。

## 七、Git 工作流

### 7.1 基本原则

```
写代码 → git add <文件> → git commit -m "消息" → [积累一些后] git push
```

- **commit** = 保存一个"快照"，记录你做了什么改动
- **push** = 把本地的所有 commit 上传到 GitHub（远程备份）
- **每个最小可运行单元完成后立刻 commit**（例如：写完一个函数、修好一个 bug）

## 九、常见问题速查

| 问题 | 答案 |
|------|------|
| 为什么不在本地跑？ | RTX 5060 8GB 显存不够加载任何模型 |
| H200 上能同时跑多个论文吗？ | 可以但建议一次一个，避免显存冲突 |
| 怎么把代码传到 H200？ | MobaXterm 自带 SFTP 拖拽上传，或 `scp` 命令，或 `git clone` |
| 环境装坏了怎么办？ | `conda remove -n 环境名 --all` 然后重跑 H200部署.sh |
| HuggingFace 下载太慢？ | `export HF_ENDPOINT=https://hf-mirror.com` 使用国内镜像 |
| 训练要多久？ | Vision-OPD ~2-3h, V-Zero ~1-2h, PRISM ~4-6h, DiffusionOPD ~12h |
| 训练中能关 MobaXterm 吗？ | 用 `tmux` 或 `screen` 保持会话，否则关了终端训练就断了 |
| 怎么看 GPU 使用情况？ | `nvidia-smi` 或 `watch -n 1 nvidia-smi`（每秒刷新） |
