Vision-OPD 复现学习指南

这份指南不是"复制粘贴命令就能跑"，而是解释每一步在干什么、为什么这么干。 适合第一次做论文复现的新手。

前置知识速查

Q1: 什么叫"复现一篇论文"？

复现（Reproduction）是指：按照论文描述的方法，自己跑一遍代码，验证论文报告的结果是否可信。复现有三个层次：

层次 做什么 难度
L1: 推理验证 下载作者提供的预训练权重，跑推理，看指标是否和论文一致 🟢
L2: 训练复现 从零开始用作者代码+数据训练，看是否得到相似结果 🟡
L3: 代码自写 不看作者代码，仅根据论文描述自己实现并跑出结果 🔴

我们这次做 L1+L2。

Q2: 复现需要哪些基础技能？

  • Git：clone 仓库、commit、push
  • Conda：创建隔离的 Python 环境
  • pip：安装 Python 包
  • Bash：在终端执行脚本命令
  • HuggingFace：下载模型权重和数据集

阶段1详解：环境搭建

为什么需要 Conda 环境？

不同论文可能依赖不同版本的 Python、PyTorch、CUDA。如果所有项目共用一个环境，版本冲突会让你陷入"依赖地狱"。

conda create -n vision-opd python=3.12 -y
  • -n vision-opd：环境名（可自定义）
  • python=3.12：论文要求 Python 3.12
  • -y：自动确认，不问你"是否继续"

为什么装 flash-attn 和 causal-conv1d？

  • flash-attn：Flash Attention，大幅减少注意力计算的显存占用和加速推理。LLaMA/Qwen 系列模型几乎必装。
  • causal-conv1d：Mamba 架构的高效卷积实现。Qwen3-VL 内部可能用到。

这两个包需要从源码编译（--no-build-isolation），所以安装比较慢，正常现象。

什么叫 pip install -e .？

-e 表示 editable（可编辑模式），相当于把当前目录的代码"软链接"到 Python 的包路径里。好处是： - 修改代码后立刻生效，不需要重新 pip install - 可以直接 import vision_opd（取决于仓库的 setup.py 配置）

阶段2详解：预训练权重推理

为什么先做推理而不是先训练？

这是复现的"安全网"原则： 1. 训练可能出各种问题（OOM、loss不收敛、数据不对……） 2. 推理用作者的预训练权重，环境正确+权重正确=一定能出结果 3. 先拿到一组数据，即使训练失败，今晚也有成果可以汇报

vLLM 是什么？

vLLM 是一个高性能 LLM 推理引擎，核心优化是 PagedAttention（把 KV cache 像操作系统的虚拟内存一样分页管理）。相比直接用 transformers 推理，vLLM 通常快 10-20 倍。

vllm serve yuanqianhao/Vision-OPD-9B \
    --gpu-memory-utilization 0.85 \
    --tensor-parallel-size 8
  • --gpu-memory-utilization 0.85：最多用 85% 显存，留一点给系统
  • --tensor-parallel-size 8：把模型切到 8 张卡上并行（你有 8×H200）
  • yuanqianhao/Vision-OPD-9B：HuggingFace 上的模型 ID，vLLM 会自动下载

评估脚本做了什么？

eval/run_eval.sh 会： 1. 加载测试数据集（如 V* Bench 的图片+问题） 2. 调用 vLLM 的 API 让模型回答问题 3. 用一个 Judge 模型（如 GPT-oss-120B）给模型的回答打分 4. 输出每个 benchmark 的分数

注意：评估需要一个 Judge 模型来打分。如果没有 GPT-oss-120B 的 API，可以换用其他模型。

阶段3详解：训练数据

Vision-OPD-6K 的数据是"造出来"的

这不是人工标注的数据，而是用更大模型（Qwen3.5-397B）自动合成的。这叫"合成数据"（Synthetic Data），近年来非常流行：

  1. 用目标检测找出图片中的小物体
  2. 让大模型针对小物体出题
  3. 多次生成答案，只保留一致性高（>0.75）的题

关键理解：这是论文的核心工程贡献之一——不需要昂贵的人工标注。

prepare_data.py 做了什么？

  • 从 HuggingFace 下载原始图片和 JSON 标注
  • 解压图片压缩包
  • 把 JSON 转成 Parquet 格式（pandas/训练框架的标准格式）

阶段4详解：训练

什么叫"On-Policy"？

传统 SFT（监督微调）是"Off-Policy"的： - 教师先生成一批"标准答案" - 学生在这批固定答案上学习

OPD/ OPSD 是"On-Policy"的： - 学生先用自己的当前策略生成回答 - 教师在这些学生自己生成的回答上提供监督 - 学生基于监督更新参数 - 然后重新生成……循环

好处：学生不会只学到"背答案"，而是学到"如何正确推理"。

训练脚本里通常有哪些关键超参数？

超参数 含义 调大/调小的影响
learning_rate 学习率，每次更新参数步长 太大→loss震荡不收敛；太小→训练太慢
batch_size 每步用多少样本 太大→显存不够(OOM)；太小→梯度噪声大
max_length 序列最大token数 太大→显存不够；太小→截断回答
num_epochs 整个数据集重复几遍 太多→过拟合；太少→欠拟合
warmup_steps 前N步线性增加学习率 防止训练初期不稳定

阶段5详解：结果对比

为什么合并 checkpoint？

训练时通常用 FSDP（Fully Sharded Data Parallelism）把模型切分到多张卡上，每张卡只存一个分片。训练结束后需要把分片合并回一个完整的模型文件，才能用 vLLM 加载。

怎么判断"复现成功"？

一般标准： - 极严格：所有指标在 ±1% 以内 - 正常：趋势一致，数值在 ±3% 以内 - 宽松：趋势方向一致（都涨了），但绝对值有差距

初次复现不强求极严格——硬件（H200 vs A100）、CUDA版本、PyTorch版本都可能导致微小差异。

常见踩坑点（提前知道）

  1. CUDA 版本不对：flash-attn 编译需要 CUDA 11.8+，先 nvcc --version 确认
  2. HuggingFace 下载慢：设置镜像 export HF_ENDPOINT=https://hf-mirror.com
  3. OOM（Out of Memory）：减小 batch_size 或用 gradient_accumulation_steps
  4. 端口被占用：vLLM 默认 8000 端口，被占了就换 --port 8001
  5. Judge 模型没 API：评估需要 Judge 打分，确保 API key 配置好了
