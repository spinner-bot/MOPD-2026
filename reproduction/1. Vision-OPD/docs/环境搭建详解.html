Vision-OPD 环境搭建详解

一、为什么要做环境搭建？

用一个比喻来理解

想象你要做一道菜——"番茄炒蛋"。

做菜 跑代码
厨房 服务器
菜谱 论文/README
锅碗瓢盆 Python 环境
食材 模型权重、数据集
调味料 各种 Python 库
火候 GPU 计算

"环境搭建"就是准备锅碗瓢盆和调味料。没有这一步，你有食材（模型权重）和菜谱（论文）也做不了菜。

为什么不能直接 python run.py？

因为不同的项目需要不同版本的 Python 和库。举个例子：

论文A：需要 torch 2.1.0 + transformers 4.35.0 + python 3.10
论文B：需要 torch 2.6.0 + transformers 4.57.0 + python 3.12

如果全装在同一个环境里，这些库会互相冲突，导致： - 代码报奇怪的错误 - 跑一半崩溃 - 结果和论文对不上

解决方案：用 Conda 给每个论文一个独立的"小厨房"。

二、核心工具介绍

2.1 Conda 是什么？

Conda 是一个环境管理器。你可以把它理解为：

你的电脑
├── Conda
│   ├── 环境A（python 3.10, torch 2.1）  ← 给论文A用
│   ├── 环境B（python 3.12, torch 2.6）  ← 给论文B用
│   └── 环境C（python 3.9, tensorflow）  ← 给论文C用

每次激活一个环境，就像走进一个独立的小厨房——里面的工具和调料都是独立的，不会跟其他厨房搞混。

2.2 pip 是什么？

pip 是 Python 的包安装器（package installer）。

pip install torch

这条命令的意思是：去互联网上的 Python 包仓库（PyPI），下载 torch 的最新版本，装到当前 Conda 环境里。

2.3 什么是依赖（Dependency）？

你的代码 import torch  ← torch 是"依赖"
                import transformers  ← transformers 也是"依赖"
                from flash_attn import ...  ← flash_attn 还是"依赖"

一个项目通常有几十到上百个依赖。作者会把所有依赖列在 requirements.txt 文件里，这样你不需要自己一个一个装。

2.4 requirements.txt 是什么？

就是个清单文件，长这样：

torch>=2.6.0
transformers==4.57.0
accelerate==1.5.0
vllm>=0.8.0
flash-attn>=2.7.0
...

一行一个包名和版本号。当你执行 pip install -r requirements.txt，pip 会按清单逐个安装。

>= 表示"至少这个版本"，== 表示"必须是这个版本"。

三、具体怎么做？（一步步来）

环境搭建总共 5 个命令，逐个解释：

命令①：创建环境

conda create -n vision-opd python=3.12 -y

这条命令做了什么？ - conda create：Conda，请创建一个新环境 - -n vision-opd：这个环境的名字叫 vision-opd - python=3.12：在这个环境里装 Python 3.12 - -y：不用问我"确认吗"，直接做

执行后，Conda 会在系统里创建一个独立的文件夹，里面有全新的 Python 3.12。

命令②：激活环境

conda activate vision-opd

这条命令做了什么？ - 让当前终端"走进"vision-opd 这个小厨房 - 从现在开始，你运行的所有 python、pip 都作用于这个环境内 - 终端提示符前面会出现 (vision-opd) 标志

命令③：升级 pip

pip install --upgrade pip

新环境自带的 pip 可能版本比较旧，先升级到最新版。旧版 pip 可能在安装某些包时报错。

命令④：安装依赖清单

pip install --no-deps -r requirements.txt
  • -r requirements.txt：按照这个文件里的清单装
  • --no-deps：只装清单里列的包本身，不要自动装它们的依赖项

为什么要 --no-deps？因为有些依赖项需要特殊的安装方式（见命令⑤），先让作者控制的东西装上，后面手动补。

命令⑤：安装项目本身

pip install -e . --no-deps
  • . 表示当前目录（即 Vision-OPD 的代码目录）
  • -e（editable）：可编辑模式。意思是不把代码复制到 Python 的库目录，而是做一个"快捷方式"。好处是——你改了代码，不需要重新安装，直接生效。
  • --no-deps：同理，不自动装依赖

命令⑥⑦：安装特殊包

pip install flash-attn --no-build-isolation
pip install causal-conv1d==1.6.1 --no-build-isolation

这两个包是加速推理用的： - flash-attn：Flash Attention，加速大模型的注意力计算，节省显存。Qwen 系列模型需要它。 - causal-conv1d：Mamba 架构的高效卷积实现，Qwen3-VL 内部用到。

--no-build-isolation 的意思是：编译时使用当前环境已有的包，不要创建临时隔离环境。因为这两个包需要从 C++/CUDA 源码编译成可执行文件（类似把源代码翻译成机器能直接跑的指令），这个过程需要找 CUDA 编译器（nvcc），如果隔离了就找不到了。

验证环境

全部装完后，验证一下：

python -c "import torch; print('PyTorch版本:', torch.__version__); print('GPU可用:', torch.cuda.is_available()); print('GPU数量:', torch.cuda.device_count())"

如果输出 GPU可用: True 和 GPU数量: 8，说明环境搭好了。

四、常见问题

Q: 装 flash-attn 报错怎么办？

通常是 CUDA 版本不对或缺少 nvcc 编译器。先检查：

nvcc --version    # 确认 CUDA 编译器存在
nvidia-smi        # 确认 GPU 驱动正常

Q: HuggingFace 下载太慢？

设置国内镜像：

export HF_ENDPOINT=https://hf-mirror.com

Q: "conda command not found"？

说明你的机器上没装 Conda。需要先装 Miniconda 或 Anaconda。在服务器上通常已经预装了，可以用 which conda 检查。

Q: 为什么不用 Docker？

Docker 是另一种环境隔离方式（更彻底，连操作系统都隔离）。对于这篇论文： - 作者没提供 Dockerfile → 自己写 Dockerfile 比直接装还麻烦 - Conda 足够用，且更灵活 - 学习曲线：Conda 比 Docker 简单很多

五、环境搭建在整个复现流程中的位置

[现在要做的] 环境搭建     ← 30分钟，一次性
     ↓
[接下来]    下载预训练权重 → vLLM 推理 → 评估跑分
     ↓
[最后]      下载训练数据 → 训练 → 评估 → 对比

环境搭好之后，后面的步骤就不会再因为"缺包"而报错了。
