Vision-OPD 代码详解（对照讲解）

论文：Vision-OPD — Learning to See Fine Details for Multimodal LLMs via On-Policy Self-Distillation

arXiv 2605.18740 · 中科院软件所 + 国科大 + 小红书 · 复现代码路径：1. Vision-OPD/code/

〇、一句话理解整篇论文与代码

论文发现一个现象：多模态大模型看「完整大图」时，比看「裁剪出的关键区域」准确率低 18~22 个百分点——不是看不清，是「不知道该往哪看」。

于是提出区域→全局自蒸馏：让同一个模型同时扮演两个角色——

教师（Teacher）= 输入裁剪证据区域（精读，准确率高，权重被 EMA 冻结）
学生（Student）= 输入完整大图（泛读，要学「该聚焦哪里」，权重被梯度更新）
损失 = 学生分布 与 教师分布 的广义 JSD 散度（token 级）

下面按「数据 → 配置 → 教师机制 → 核心损失」四层，逐一对照代码讲。

一、数据准备 scripts/prepare_data.py

核心：把每个样本打包成「一张完整大图 + 一张裁剪证据图」，这正是「区域→全局」的物质基础。

def build_record(item, data_dir): image_rel = item["images"][0] # 完整大图 teacher_rel = item["teacher_images"][0] # 裁剪证据区域 image_path = os.path.join(data_dir, image_rel) teacher_path = os.path.join(data_dir, teacher_rel) question = clean_question(item["problem"]) return { "prompt": [{"role":"user","content":item["problem"]}], "images": [{"path": image_path}], # 学生看的图 "bbox_images": [{"path": teacher_path}], # 教师看的图 "reward_model": {"style":"none", "ground_truth": item["answer"]}, "extra_info": {"answer": item["answer"], "question": question}, }
核心概念

关键就在这两个字段的命名：

images → 完整大图，喂给学生（Student）。

bbox_images → 裁剪出来的证据区域（即论文里的"红框标注区域"），喂给教师（Teacher）。

为什么这样设计？教师只看那块关键小区域，所以它「自然就知道答案」；学生要看完整大图自己「找」那个区域。两者的行为差异，就是蒸馏要消灭的差距。

reward_model.style = "none" 表示没有真正的奖励模型——这正是论文卖点之一：不需要外部奖励模型或验证器，ground_truth 只作为辅助信息存在。

记忆点：数据集里每个样本是「一对图」——images（大图，学生）+ bbox_images（裁剪，教师）。理解这个「一对图」结构，后面全部代码都通了。

二、训练启动 scripts/run_vision_opd.sh

这是一个 bash 脚本，把所有超参数拼成一条 verl 训练命令。不用逐行看，抓关键几个：

配置项值含义 / 为什么
MODEL_PATHQwen/Qwen3.5-4B基座模型（训练从这里开始）
policy_loss.loss_modevopd启用 Vision-OPD 自蒸馏损失（而非普通 PPO）
teacher_regularizationema教师权重用 EMA 平滑更新
teacher_update_rate0.05EMA 系数 α，教师「慢慢跟着学生动」
alpha0.5广义 JSD 的混合系数（学生/教师各占一半）
distillation_topk100只对词表里 top-100 的概率做蒸馏，省显存
is_clip2.0重要性采样权重裁剪上界
adv_estimatorgrpo用 GRPO 做优势估计（不需要 critic）
teacher_image_keybbox_images教师读哪张图 → 就是刚才数据的裁剪图字段
param_offload / optimizer_offloadTrueFSDP 把参数/优化器卸载到 CPU，省显存
注意：TRAINER_N_GPUS_PER_NODE=8 表示需要 8 张卡，FSDP 把 4B 模型切到 8 卡上。这就是为什么我们要等 GPU 全空。

三、教师机制 verl/workers/actor/dp_actor.py — EMA 更新

这是「自蒸馏」里「自」字的实现：教师和学生是同一个模型的两份权重，教师不直接学，而是靠 EMA 慢慢「追」学生。

def _update_teacher(self): ... if teacher_regularization == "ema": update_rate = getattr(cfg, "teacher_update_rate", 0.0) if update_rate == 0.0: return for teacher_param, student_param in zip( self.teacher_module.parameters(), # 教师权重（被更新） self.actor_module.parameters(), # 学生权重（来源） ): student_data = student_param.data.to(teacher_param.device) teacher_param.data.mul_(1.0 - update_rate) \ .add_(student_data, alpha=update_rate) return
EMA 公式

核心就是这一行：

θ_teacher ← (1 − α)·θ_teacher + α·θ_student
其中 α = 0.05

拆解这行代码：

mul_(1.0 - 0.05) → 先把教师权重整体乘以 0.95（保留 95% 旧值）。

.add_(student_data, alpha=0.05) → 再加上 5% 的学生当前权重。

为什么教师「慢半拍」？因为 EMA 让教师成为学生的「历史平均」——它比学生更稳定、更平滑，能提供一个高质量、低噪声的蒸馏目标。教师不直接做梯度下降，所以它「不会跑偏」。

只有学生收梯度：注意这段只改 teacher_param，反向传播时教师权重 requires_grad=False，梯度只流回学生。这就是「自蒸馏」——同一个模型教自己。

记忆点：教师 = 学生权重的 EMA（滑动平均）。教师「稳定但落后」，学生「激进但前进」，两者形成良性循环。

四、核心损失 verl/trainer/ppo/core_algos.py — 广义 JSD

这是全代码的心脏：compute_self_distillation_loss 函数。它计算学生分布与教师分布的差异，作为训练信号。

def compute_self_distillation_loss( student_log_probs, teacher_log_probs, response_mask, self_distillation_config, ... ): loss_mask = response_mask if self_distillation_mask is not None: loss_mask = loss_mask * self_distillation_mask.unsqueeze(1) if self_distillation_config.full_logit_distillation: # ... 取 top-k 或全词表 log prob ... if self_distillation_config.alpha == 0.0: kl_loss = F.kl_div(student, teacher, log_target=True) elif self_distillation_config.alpha == 1.0: kl_loss = F.kl_div(teacher, student, log_target=True) else: # alpha=0.5 → 广义 Jensen-Shannon 散度 mixture = torch.logsumexp( torch.stack([ student + log(1-alpha), teacher + log(alpha) ]), dim=0) kl_teacher = F.kl_div(mixture, teacher, log_target=True) kl_student = F.kl_div(mixture, student, log_target=True) kl_loss = torch.lerp(kl_student, kl_teacher, alpha) raw_per_token_loss = kl_loss.sum(-1)
三种散度

代码用参数 alpha 统一了三种散度：

alpha损失含义
0.0KL(学生‖教师)正向 KL，学生「追」教师
1.0KL(教师‖学生)反向 KL，学生「抄」教师
0.5广义 JSD正反 KL 各一半，最均衡

广义 JSD 的核心数学：先构造一个「混合分布」M = (1−α)·学生 + α·教师（代码里用 logsumexp 在 log 空间实现混合，数值更稳），然后分别算 M 到学生、M 到教师的 KL，再用 lerp（线性插值）按 α 加权。

JSD_α = (1−α)·KL(M‖学生) + α·KL(M‖教师)，α=0.5

为什么用 JSD 而不是 KL？KL 不对称、且当两个分布不重叠时会发散到无穷大（梯度爆炸）。JSD 对称、有界、更平滑，训练更稳定。论文正是用它做 token 级蒸馏。

# 重要性采样裁剪（IS clipping） is_clip = self_distillation_config.is_clip if is_clip is not None: negative_approx_kl = (student_log_probs - old_log_probs).detach() negative_approx_kl = clamp(negative_approx_kl, -20, 20) ratio = torch.exp(negative_approx_kl).clamp(max=is_clip) weighted_per_token_loss = weighted_per_token_loss * ratio # 按 token 聚合求最终损失 loss = agg_loss( loss_mat=weighted_per_token_loss, loss_mask=loss_mask, loss_agg_mode="token-mean", ...) return loss, metrics
IS 裁剪

为什么要裁剪？训练是 on-policy（在线采样），但一个 batch 会复用几次（off-policy 程度增大）。新旧策略差异过大时，需要限制每个 token 的贡献权重，防止单步更新过猛。

ratio = exp(student - old_log_prob) 是重要性采样比，.clamp(max=2.0) 把它压在 2.0 以下。

聚合：token-mean 表示把所有有效 token 的损失求平均，得到标量 loss，反传给学生。

metrics：函数还会输出 raw_jsd_token_mean 等指标，供 tensorboard 画曲线监控。

五、整体数据流（把四块串成一条链）

① 数据(prepare_data.py)：每个样本 = 大图(images) + 裁剪(bbox_images)
    ↓
② 前向：学生吃大图 → 输出 logits；教师吃裁剪图 → 输出 logits
    ↓
③ 损失(core_algos.py)：算学生/教师的广义 JSD（α=0.5, top-100）
    ↓
④ 反传：梯度只更新学生（教师 requires_grad=False）
    ↓
⑤ 教师更新(dp_actor.py)：θ_teacher ← 0.95·θ_teacher + 0.05·θ_student
    ↓
⑥ 循环 ②~⑤，直到学生学会「看完整大图也能自动聚焦关键区域」
给导师讲时的主线：一句话讲清「区域→全局自蒸馏」→ 用数据的一对图结构做铺垫 → 用 EMA 解释「自」→ 用 JSD 解释「蒸馏」→ 用 IS 裁剪解释「稳定」。
