## 三、评估流程（连接恢复后照此执行）

设环境变量（每次新开终端都要设）：

```bash
conda activate vision-opd
export WORLD_SIZE=1
export HF_ENDPOINT=https://hf-mirror.com
export LD_LIBRARY_PATH=$CONDA_PREFIX/lib:$LD_LIBRARY_PATH
export LIBRARY_PATH=/usr/local/cuda-11.8/targets/x86_64-linux/lib/stubs:$LIBRARY_PATH
export LD_LIBRARY_PATH=/usr/local/cuda-11.8/targets/x86_64-linux/lib/stubs:$LD_LIBRARY_PATH
```

### 步骤 1：合并 checkpoint
```bash
cd ~/vopd/code
BASE_DIR=~/vopd/checkpoints/Vision-OPD-Qwen3.5-4B/global_step_XX   # XX 用实际步数
bash scripts/merge_checkpoint.sh "$BASE_DIR"
# 成功标志：输出 Merge completed.
```

### 步骤 2：起 vLLM 服务（tmux 保护，防断开）
```bash
nvidia-smi --query-gpu=index,memory.used --format=csv,noheader,nounits   # 找空闲卡
tmux new -s eval
CUDA_VISIBLE_DEVICES=<空闲卡> vllm serve <步骤1合并后的模型目录> \
  --served-model-name Vision-OPD-4B \
  --gpu-memory-utilization 0.7 \
  --trust-remote-code \
  --dtype bfloat16
curl http://localhost:8000/v1/models   # 验证服务
```

### 步骤 3：配置 judge 模型
- 方式 A（推荐）：另起本地 vLLM judge
  ```bash
  tmux new -s judge
  CUDA_VISIBLE_DEVICES=<另一张卡> vllm serve Qwen/Qwen2.5-7B-Instruct \
    --served-model-name judge --gpu-memory-utilization 0.7 --trust-remote-code
  ```
- 方式 B：OpenAI API judge（`JUDGE_API_BASE` / `JUDGE_API_KEY` / `JUDGE_MODEL`）

### 步骤 4：跑评估
```bash
cd ~/vopd/code/eval
API_BASE="http://localhost:8000/v1/" \
OPENAI_MODEL_ID="Vision-OPD-4B" \
JUDGE_MODEL_PATH="Qwen/Qwen2.5-7B-Instruct" \        # 或 JUDGE_API_BASE/KEY/MODEL
BENCHMARK="vstar,zoombench,hrbench-4k,hrbench-8k,mme-realworld,mmstar,pope,cv-bench,mmvp" \
bash run_eval.sh
```

> 建议：先跑 1 个 benchmark（如 `vstar`）验证链路通，再跑全量（每个 benchmark 走 4 步，全量数小时）。

### 步骤 5：收集结果
```bash
ls ~/vopd/code/eval/model_answer/
ls ~/vopd/code/eval/judge/
```
把每个 benchmark 的准确率记下来，反馈给 Claude，填入《评估执行指南.md》"九、与论文对照"的复现值列。

## 五、若连接恢复后仍失败

- checkpoint 目录找不到：`find ~/vopd -name "global_step*" -type d`
- vLLM 起不来（显存不足）：换空闲卡或降 `--gpu-memory-utilization`
- judge/数据下载失败：`export HF_ENDPOINT=https://hf-mirror.com` 重试
