# Vision-OPD 训练后评估执行指南

> 分支：repro  
> 用途：训练完成后，在 H200 服务器上执行评估，与论文结果对照  
> 状态：训练已完成，待评估

---

## 一、评估流程概览

```
检查 checkpoint → 合并 checkpoint → 起 vLLM 服务 → 配置 judge → 跑评估 → 收集结果
```

评估链 4 步（由 `code/eval/run_eval.sh` 自动完成）：
1. `prepare_data.py`：从 HuggingFace 下载 benchmark 数据
2. `infer.py`：用 vLLM 服务跑模型推理
3. `judge_qwenlm.py`：用 judge 模型评分
4. `cal_acc.py`：计算准确率

## 三、步骤 0：检查训练 checkpoint

```bash
# 查看训练 checkpoint 目录
ls ~/vopd/checkpoints/Vision-OPD-Qwen3.5-4B/
# 应该看到 global_step_XX/ 目录（XX 是实际训练步数）
```

**重点**：
- 记住实际的 `global_step_XX` 数字，后续合并脚本要用
- 如果训练没跑满 260 步，用实际步数对应的目录

---

## 四、步骤 1：合并 checkpoint

```bash
cd ~/vopd/code
# 用实际的 global_step 目录
BASE_DIR=~/vopd/checkpoints/Vision-OPD-Qwen3.5-4B/global_step_XX
bash scripts/merge_checkpoint.sh "$BASE_DIR"
```

**成功标志**：输出 `Merge completed.`，且 `$BASE_DIR` 下出现合并后的权重文件。

---

## 五、步骤 2：起 vLLM 服务

用一张空闲卡起 vLLM 服务（评估训练后的模型）：

```bash
# 先看哪张卡空闲
nvidia-smi --query-gpu=index,memory.used --format=csv,noheader,nounits

# 在 tmux 里起服务（防止断开）
tmux new -s eval

CUDA_VISIBLE_DEVICES=<空闲卡> vllm serve <合并后的模型目录> \
  --served-model-name Vision-OPD-4B \
  --gpu-memory-utilization 0.7 \
  --trust-remote-code \
  --dtype bfloat16
```

**注意**：
- `<合并后的模型目录>` = 步骤 1 的 `$BASE_DIR`
- `--served-model-name` 填模型名，评估脚本用这个名字
- 服务起好后，记录 API 地址：`http://localhost:8000/v1/`

**验证服务**：
```bash
curl http://localhost:8000/v1/models
```

---

## 六、步骤 3：配置 judge 模型

`judge_qwenlm.py` 支持两种 judge 方式：

### 方式 A：本地 vLLM judge（推荐）
用一张空闲卡本地部署一个 judge 模型（如 Qwen2.5-7B-Instruct）：

```bash
# 另起一个 vLLM 服务当 judge
tmux new -s judge
CUDA_VISIBLE_DEVICES=<另一张卡> vllm serve Qwen/Qwen2.5-7B-Instruct \
  --served-model-name judge \
  --gpu-memory-utilization 0.7 \
  --trust-remote-code
```

### 方式 B：OpenAI API judge
如果你有 OpenAI API（或代理），直接用：
```
JUDGE_API_BASE=<你的API地址>
JUDGE_API_KEY=<你的key>
JUDGE_MODEL=<如 gpt-4o>
```

---

## 七、步骤 4：跑评估

```bash
cd ~/vopd/code/eval

# 方式 A：本地 vLLM judge
API_BASE="http://localhost:8000/v1/" \
OPENAI_MODEL_ID="Vision-OPD-4B" \
JUDGE_MODEL_PATH="Qwen/Qwen2.5-7B-Instruct" \
BENCHMARK="vstar,zoombench,hrbench-4k,hrbench-8k,mme-realworld,mme-realworld-lite,mmstar,pope,cv-bench,mmvp" \
bash run_eval.sh

# 方式 B：OpenAI API judge
API_BASE="http://localhost:8000/v1/" \
OPENAI_MODEL_ID="Vision-OPD-4B" \
JUDGE_API_BASE="$JUDGE_API_BASE" \
JUDGE_API_KEY="$JUDGE_API_KEY" \
JUDGE_MODEL="$JUDGE_MODEL" \
BENCHMARK="vstar,zoombench,hrbench-4k,hrbench-8k,mme-realworld,mme-realworld-lite,mmstar,pope,cv-bench,mmvp" \
bash run_eval.sh
```

**注意**：
- `prepare_data.py` 会从 HF 下载数据（需网络，第一次较慢）
- 每个 benchmark 跑 4 步（准备→推理→评分→算准确率）
- 全部跑完需要较长时间（数小时）

## 十、常见问题

### 1. checkpoint 目录找不到
```bash
find ~/vopd -name "global_step*" -type d 2>/dev/null
```

### 2. vLLM 服务起不来（显存不足）
换空闲卡，或降低 `--gpu-memory-utilization`。

### 3. judge 模型下载失败
```bash
export HF_ENDPOINT=https://hf-mirror.com
python -c "from huggingface_hub import snapshot_download; snapshot_download('Qwen/Qwen2.5-7B-Instruct', local_dir='models/Qwen2.5-7B-Instruct')"
```

### 4. 数据下载慢/失败
```bash
export HF_ENDPOINT=https://hf-mirror.com
# 重跑 run_eval.sh 会续传
```
