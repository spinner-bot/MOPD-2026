# Idea1 各分支代码模块速览

> 用途：快速了解 5 个分支各自的核心算法模块和测试，接手时定位代码。

---

## 各分支核心模块

| 分支 | 方法 | 核心模块 | 关键函数 | 核心思想 |
|------|------|---------|---------|---------|
| `mcd` | 模态可信度动态控制 | `code/mcd_distillation.py` | `mcd_distillation_loss` | 置信度+优势差 → softmax+门控动态权重 |
| `mbd` | 模态平衡蒸馏 | `code/mbd_distillation.py` | `mbd_distillation_loss` | 加平衡惩罚 `λ\|w_vl-w_text\|` 防坍缩 |
| `tamr` | 任务感知模态路由 | `code/tamr_distillation.py` | `task_routing_weights` | 任务分类器 → 任务级权重 |
| `modd` | 模态解耦蒸馏 | `code/modd_distillation.py` | `modd_stage_*` | 分阶段：视觉→语言→整合 |
| `amf` | 自适应模态融合 | `code/amf_distillation.py` | `fuse_logits` | 贝叶斯融合两个教师 logits |

## 代码位置

各分支代码在各自分支的 `research/main/idea1/分支/<N.分支名>/code/` 下。

**mcd**（基座）有完整训练框架：
```
分支/1.mcd/code/mcd/            # 完整 verl 训练框架
  verl/workers/actor/mcd_distillation.py   # MCDC 核心模块
  verl/workers/actor/dp_actor.py           # 集成 MCDC（已改）
  scripts/run_vision_opd.sh                # 训练脚本（已配 MCDC）
```

**其他分支**目前只有独立的蒸馏模块（`.py`），还未集成到 `dp_actor.py` 训练框架。

## 运行单元测试

测试需服务器环境（含 torch）。上传对应 `code/` 目录到服务器后：

```bash
cd code/
python test_mcd_distillation.py    # 或对应分支的测试
```

每个测试验证：模块能运行、形状正确、核心逻辑（权重/损失/掩码）符合预期。

## 各分支测试内容

| 分支 | 测试文件 | 验证点 |
|------|---------|--------|
| `mcd` | `test_mcd_distillation.py` | 置信度[0,1]、权重和=1、门控下限 |
| `mbd` | `test_mbd_distillation.py` | 平衡惩罚、不平衡时权重被拉近 |
| `tamr` | `test_tamr_distillation.py` | 任务路由权重、分类器、各任务损失 |
| `modd` | `test_modd_distillation.py` | 三阶段损失、掩码过滤、阶段切换 |
| `amf` | `test_amf_distillation.py` | 融合权重[0,1]、logits融合、损失 |

## sync 部署包

每个分支的 `sync/` 目录是一键部署包，包含：
- `code/`：该分支的蒸馏模块 + 单元测试
- `deploy.sh`：部署脚本（把蒸馏模块复制进 verl 框架）
- `指令集.txt`：服务器操作指令

**使用方式**（以 mbd 为例）：
```bash
# 1. 上传 sync 到服务器
# 2. 进环境
conda activate vision-opd
# 3. 部署（CODE_DIR 指向 mcd 基座完整框架，默认 ~/mcd/code）
bash deploy.sh
# 4. 跑单元测试
python test_mbd_distillation.py
```
