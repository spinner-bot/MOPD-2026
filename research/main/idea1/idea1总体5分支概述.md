# Idea 1：多模态在线策略蒸馏（MOPD）各分支概述

> 研究方向：多模态在线策略蒸馏  
> 核心问题：多模态教师可信度不一致，被动接纳导致 OPD 质量下降  
> 创建时间：2026-08-28

---

## 一、研究动机

在多模态在线策略蒸馏（MOPD）中，不同模态的教师（如视觉-语言教师 VL、纯文本教师 Text）在同一推理轨迹的不同 token 处具有不同的可信度。被动接纳所有教师的监督信号会导致：

- **模态坍缩**：学生过度依赖强势模态教师（如 VL 教师），忽视弱势模态教师的互补信号
- **熵崩塌**：模型过早收敛，失去探索能力
- **效果退化**：训练后期性能不升反降

**解决思路**：主动控制不同模态教师在策略收拢过程中的参与程度。

## 三、各分支详细介绍

### 1. `1.mcd` - 模态可信度感知的动态控制（Multimodal Confidence-aware Dynamic Control）

**核心思想**：
- 在每个 token 处，计算每个教师的可信度分数（置信度 + 优势差）
- 基于可信度动态计算参与权重（softmax + 门控）
- 加权蒸馏损失

**公式**：
```
score_k(t) = α * confidence_k(t) + β * advantage_k(t)
w_k(t) = softmax(score_k(t) / τ)
w_k'(t) = max(w_k(t), ε)  # 门控
loss = Σ w_k(t) * JS(student || teacher_k)
```

**创新点**：
- 模态可信度感知：不仅考虑置信度，还考虑优势差
- 双重动态控制：既选教师，又控制强度
- 门控机制：防止弱势模态被忽视

**实现状态**：✅ 实现中
- 代码：`research/ideas/1/code/mcd/`
- 部署包：`research/ideas/1/sync/`
- 训练：已在 H200 上启动（预计 40-50 小时）

**预期结果**：
- 相比 Vision-OPD（单一 VL 教师），性能提升 5-10%
- 相比 Static-Multi（固定权重），性能提升 3-5%

---

### 2. `2.mbd` - 模态平衡蒸馏（Modal Balanced Distillation）

**核心问题**：模态坍缩——学生过度依赖 VL 教师

**核心思想**：
- 不是让一个教师主导，而是强制两个教师平衡贡献
- 添加模态平衡损失，强制权重接近

**公式**：
```
loss = JS(student || VL) + JS(student || Text) + λ * |w_VL - w_Text|
```

**创新点**：
- 发现并定义"模态坍缩"问题（首次在多模态 OPD 中）
- 提出专门的模态平衡方法（不是通用的动态加权）
- 理论分析：为什么平衡能避免坍缩

**实现计划**：
- 在 `1.mcd` 代码基础上修改
- 添加平衡损失项
- 调参：λ ∈ {0.1, 0.5, 1.0, 2.0}

**预期结果**：
- 相比 MCDC（动态加权），性能提升 2-5%
- 模态利用率更均衡（w_VL ≈ w_Text）

**实现难度**：低（只需添加一个损失项）

---

### 3. `3.tamr` - 任务感知模态路由（Task-Aware Modal Routing）

**核心问题**：不同任务需要不同的模态组合

**核心思想**：
- 任务级路由（不是 token 级）
- 根据任务类型选择教师
- 轻量：只需一个任务分类器

**方法**：
```
if task_type == "visual_reasoning":
    use VL teacher
elif task_type == "language_reasoning":
    use Text teacher
else:
    use both (equal weight)
```

**创新点**：
- 发现：VL 教师在视觉任务上强，Text 教师在语言任务上强
- 方法简单：任务级路由，计算开销 <1%
- 可解释性强：知道为什么选择某个教师

**实现计划**：
- 在训练脚本中添加任务分类器
- 根据任务类型动态选择教师
- 分析：不同任务类型的教师贡献

**预期结果**：
- 相比 token 级路由（H-OPD），性能相当或更好
- 计算开销减少 50%+
- 可解释性：能可视化任务-教师映射

**实现难度**：低（只需添加任务分类逻辑）

---

### 4. `4.modd` - 模态解耦蒸馏（Modal Decoupled Distillation）

**核心问题**：多模态教师的能力耦合导致学生学到"捷径"

**核心思想**：
- 解耦训练：先学视觉，再学语言，最后整合
- 课程学习 + 能力解耦

**方法**：
```
Stage 1: 只训练视觉能力（用 VL 教师的视觉部分）
Stage 2: 只训练语言能力（用 Text 教师）
Stage 3: 整合（两个教师同时指导）
```

**创新点**：
- 发现：VL 教师同时教视觉和语言，学生可能只学语言（捷径）
- 方法新颖：分阶段训练，逐步解耦
- 理论深度：课程学习 + 能力解耦

**实现计划**：
- 修改训练脚本，支持多阶段训练
- 每个阶段使用不同的教师配置
- 分析：学生的视觉能力 vs 语言能力

**预期结果**：
- 相比联合训练，性能提升 3-8%
- 可视化：注意力图显示学生真正学到视觉能力

**实现难度**：中（需要多阶段训练逻辑）

**状态**：⏳ 待评估（根据前 3 个分支的结果决定是否实现）

### 5. `5.amf` - 自适应模态融合（Adaptive Modal Fusion）

**核心问题**：现有方法都是"选择"教师，没有"融合"教师

**核心思想**：
- 不是选一个教师，而是融合两个教师的 logits
- 融合权重基于每个 token 的模态置信度
- 理论：贝叶斯融合（最优融合策略）

**公式**：
```
fused_logits = α * VL_logits + (1-α) * Text_logits
α = softmax(confidence_VL, confidence_Text)
```

**创新点**：
- 方法简洁：logits 融合，不是选择
- 理论优美：贝叶斯融合
- 效果显著：融合比选择更好

**实现计划**：
- 在 `1.mcd` 代码基础上修改
- 实现 logits 融合逻辑
- 分析：不同 token 的融合权重分布

**预期结果**：
- 相比选择教师，性能提升 2-5%
- 融合权重分布可解释

**实现难度**：低（只需修改 logits 融合逻辑）

**状态**：⏳ 待评估（根据前 3 个分支的结果决定是否实现）

## 四、实验设计

### 4.1 Baseline

- **Vision-OPD**：单一 VL 教师的 OPD
- **Static-Multi**：多教师固定权重（w_VL=0.5, w_Text=0.5）
- **H-OPD**：Token 级教师仲裁（选教师）

### 4.2 评估基准

- **视觉推理**：ChartQA, DocVQA, InfoVQA
- **图文问答**：OK-VQA, A-OKVQA, GQA
- **细粒度视觉**：Visual7W, VQAv2

### 4.3 评估指标

- **准确率**：标准任务指标
- **模态利用率**：统计不同模态教师的平均参与权重
- **训练稳定性**：loss 曲线、熵变化
- **计算效率**：训练时间、显存占用

### 4.4 消融实验

每个分支内部消融：
- `1.mcd`：α, β, τ, ε 的影响
- `2.mbd`：λ 的影响
- `3.tamr`：任务分类器的影响
