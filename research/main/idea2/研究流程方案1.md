2. **添加 probe logging 逻辑**：
   - 编辑 `~/idea2_code/verl/workers/actor/dp_actor.py`
   - 在训练循环中，每 10 步对 probe batch 跑两个教师的 forward
   - 记录每个 token 的 JS 散度、Top-1 一致率
   - 保存到 `~/vopd/probe_logs/step_XXXX.jsonl`

   **具体修改点**：
   - 在 `forward_micro_batch` 后，添加 probe 逻辑
   - 加载 probe batch（从 `~/vopd/probe_data/probe_batch.jsonl` 读取）
   - 对 probe batch 的每个样本，分别跑 VL 教师（teacher_module）和 Text 教师（text_teacher）的 forward
   - 计算 JS 散度：`js_div = compute_js_divergence(vl_logits, text_logits)`
   - 保存到文件

   **参考代码**（伪代码）：
   ```python
   # 在 dp_actor.py 的 update_policy 方法中
   if global_step % 10 == 0:  # 每 10 步
       probe_batch = load_probe_batch("~/vopd/probe_data/probe_batch.jsonl")
       probe_results = []
       for sample in probe_batch:
           vl_logits = self.teacher_module(sample)  # VL 教师
           text_logits = self.text_teacher(sample)  # Text 教师
           js_div = compute_js_divergence(vl_logits, text_logits)  # [seq_len]
           probe_results.append({
               'step': global_step,
               'sample_id': sample['id'],
               'js_divergence': js_div.mean().item(),
               'top1_agree': (vl_logits.argmax(-1) == text_logits.argmax(-1)).float().mean().item()
           })
       save_probe_results(probe_results, f"~/vopd/probe_logs/step_{global_step}.jsonl")
   ```

3. **准备 probe batch**：
   ```bash
   # 从 Vision-OPD-6K 中随机抽 100 条

   samples = random.sample(data, 100)
   with open('~/vopd/probe_data/probe_batch.jsonl', 'w') as f:
       for s in samples:
   ```

### Step 2.2：训练期间准备分析脚本（并行，2-3 小时）

**动作**（本地，训练在服务器上跑）：

1. **写 probe 数据分析脚本**：
   ```python
   # analyze_probe.py
   import json
   import glob
   import pandas as pd
   import matplotlib.pyplot as plt
   
   # 加载所有 probe 日志
   probe_files = sorted(glob.glob("~/vopd/probe_logs/step_*.jsonl"))
   data = []
   for f in probe_files:
       with open(f) as fp:
           for line in fp:
               data.append(json.loads(line))
   
   df = pd.DataFrame(data)
   
   # 画 JS 散度 vs 训练步数曲线
   js_mean = df.groupby('step')['js_divergence'].mean()
   plt.plot(js_mean.index, js_mean.values)
   plt.xlabel('Training Step')
   plt.ylabel('Mean JS Divergence')
   plt.title('Cross-Modal Teacher Alignment Over Training')
   plt.savefig('js_divergence_curve.png')
   
   # 画 Top-1 一致率 vs 训练步数曲线
   agree_mean = df.groupby('step')['top1_agree'].mean()
   plt.figure()
   plt.plot(agree_mean.index, agree_mean.values)
   plt.xlabel('Training Step')
   plt.ylabel('Top-1 Agreement Rate')
   plt.title('Teacher Agreement Over Training')
   plt.savefig('top1_agreement_curve.png')
   ```

2. **写相变点检测脚本**（可选，如果有相变）：
   ```python
   # detect_changepoint.py
   from ruptures import Pelt  # 需要 pip install ruptures
   
   # 用 PELT 算法检测相变点
   signal = js_mean.values
   algo = Pelt(model="l2").fit(signal)
   result = algo.predict(pen=10)  # penalty 需要调
   
   print(f"Detected change points at steps: {result}")
   ```

3. **上传脚本到服务器**：
   ```bash
   scp analyze_probe.py detect_changepoint.py H200:~/vopd/
   ```

## 三、Phase 3：数据分析（Day 3，51-60 小时）

### Step 3.1：初步分析（2-3 小时）

**动作**（服务器上，训练刚结束）：
```bash
cd ~/vopd
python analyze_probe.py
```

**查看输出**：
- `js_divergence_curve.png`：JS 散度 vs 训练步数
- `top1_agreement_curve.png`：Top-1 一致率 vs 训练步数

**决策点 1：是否有明显 pattern？**

**分支**：
- **有相变点**（JS 散度在某阶段突然跳变） → 这是核心 finding，继续 Step 3.2A
- **有任务依赖**（如果 probe batch 有任务标签）→ 按任务类型分组画曲线，继续 Step 3.2B
- **JS 散度平滑变化，无明显 pattern** → 可能是 null result，继续 Step 3.2C
- **数据异常**（如 JS 散度一直为 0 或 NaN）→ probe logging 有问题，需要修复后重跑

---

### Step 3.2A：相变点分析（如果找到相变点）（3-4 小时）

**动作**：
1. **定位相变点**：
   ```bash
   python detect_changepoint.py
   ```
   输出类似：`Detected change points at steps: [80, 180]`

2. **分析相变前后的差异**：
   - 对比 step 70-90 和 step 170-190 的 probe 数据
   - 看哪些样本的 JS 散度变化最大
   - 看这些样本有什么共同特征（任务类型？难度？）

3. **可视化**：
   - 画相变点前后的 attention map 对比（如果有 attention 数据）
   - 画 JS 散度分布的 histogram（相变前 vs 相变后）

4. **验证**：
   - 用不同超参数重跑一次训练，看相变点是否复现
   - 如果复现 → strong finding
   - 如果不复现 → 可能是随机波动，需要更多实验

**决策点 2：相变点是否稳定复现？**

**分支**：
- **稳定复现** → 这是核心 finding，写 paper（Step 4.1）
- **不稳定** → 可能是随机波动，需要更多实验或换方向（Step 3.2C）

---

### Step 3.2B：任务依赖分析（如果有任务标签）（3-4 小时）

**动作**：
1. **按任务类型分组**：
   ```python
   # 在 analyze_probe.py 中加
   for task_type in df['task_type'].unique():
       subset = df[df['task_type'] == task_type]
       js_mean = subset.groupby('step')['js_divergence'].mean()
       plt.plot(js_mean.index, js_mean.values, label=task_type)
   plt.legend()
   plt.savefig('js_by_task_type.png')
   ```

2. **分析不同任务类型的 pattern**：
   - 视觉 Grounding：JS 散度是否一直高（Text 教师没看图）？
   - 图表理解：JS 散度是否快速下降（两教师都强）？
   - OCR：JS 散度是否一直高？
   - 常识问答：JS 散度是否中等？

3. **统计检验**：
   - 用 ANOVA 检验不同任务类型的 JS 散度是否有显著差异
   - 如果有显著差异 → strong finding

**决策点 3：任务依赖是否显著？**

**分支**：
- **显著**（p < 0.05）→ 这是核心 finding，写 paper（Step 4.2）
- **不显著** → 任务依赖不明显，可能需要更多样本或更细粒度的任务分类

---

### Step 3.2C：Null Result 处理（如果没有明显 pattern）（2-3 小时）

**动作**：
1. **检查数据质量**：
   - probe logging 是否正确？
   - probe batch 是否有代表性？
   - 训练是否正常收敛？

2. **尝试其他 metric**：
   - 计算 Top-K Jaccard（K=10, K=100）
   - 计算 Attention 相似度（如果提取了 attention map）
   - 看是否有其他 metric 显示 pattern

3. **决策**：
   - 如果其他 metric 有 pattern → 用那个 metric 写 paper
   - 如果所有 metric 都没 pattern → 写 null result paper（"Characterizing Cross-Modal Alignment in Multimodal OPD: A Null Study"）

**分支**：
- **其他 metric 有 pattern** → 用那个 metric 写 paper
- **所有 metric 都没 pattern** → 写 null result paper，投 workshop
