## 质量检查流程

### 1. 生成阶段

**每批次生成后检查**：
- [ ] API 调用成功率
- [ ] JSON 格式正确性
- [ ] 引导问题数量（2-4 个）
- [ ] 无明显重复

**记录内容**：
```json
{
  "batch_id": "001",
  "timestamp": "2026-09-04T10:00:00",
  "total_samples": 100,
  "success_count": 98,
  "failure_count": 2,
  "avg_questions_per_sample": 2.8,
  "format_errors": 0
}
```

### 2. 自动化检查

**检查项**：
- [ ] 引导问题非空
- [ ] 引导问题长度合理（5-50 字）
- [ ] 无重复问题
- [ ] 与原始问题相关（余弦相似度 > 0.3）
- [ ] 不包含答案泄露

**工具**：`code/data_processing/quality_check.py`

### 3. 抽样人工审核

**抽样策略**：
- 每批次随机抽取 10% 样本
- 覆盖不同难度级别
- 记录审核意见

**审核标准**：
- [ ] 引导问题循序渐进
- [ ] 不直接给出答案
- [ ] 语言清晰准确
- [ ] 与图像/问题相关

**审核记录**：`data/quality_reports/sample_review.md`

### 4. 最终验证

**检查项**：
- [ ] 数据完整性（无缺失）
- [ ] 格式一致性
- [ ] 引导问题质量（平均分 > 4/5）
- [ ] 与原始数据对齐

## 质量指标

### 量化指标

| 指标 | 目标值 | 说明 |
|------|--------|------|
| 生成成功率 | > 95% | API 调用成功比例 |
| 格式正确率 | > 98% | JSON 格式正确 |
| 问题数量 | 2-4 个 | 每个样本的引导问题数 |
| 审核通过率 | > 85% | 抽样审核通过比例 |
| 平均质量分 | > 4.0/5.0 | 人工评分 |

### 定性指标

- 引导问题是否循序渐进
- 是否有助于推理
- 语言是否清晰
- 是否与任务相关

## 审查接口

### 供你审查的文件

1. **质量报告**：
   - `data/quality_reports/quality_check_001.md`
   - `data/quality_reports/sample_review.md`
   - `data/quality_reports/statistics.json`

2. **示例数据**：
   - `data/guiding_questions/reviewed/approved.jsonl`（前 50 条）
   - `data/guiding_questions/rejected.jsonl`（不通过示例）

3. **生成 prompt**：
   - `code/data_processing/generation_prompt.md`

### 审查方式

**快速审查**（5 分钟）：
- 查看 `statistics.json` 了解整体质量
- 查看 `sample_review.md` 了解典型示例
- 查看 `rejected.jsonl` 了解常见问题

**深度审查**（30 分钟）：
- 随机打开 `approved.jsonl` 检查具体样本
- 对比原始问题和引导问题
- 评估引导质量

## 问题处理

### 如果质量不达标

**方案 A：调整 prompt**
- 分析问题类型
- 改进 prompt 模板
- 重新生成

**方案 B：增加过滤**
- 提高自动化检查标准
- 增加人工审核比例
- 剔除低质量样本

**方案 C：使用更强模型**
- 如 DeepSeek 效果不佳，考虑其他 API
- 或使用本地大模型

### 如果数据量不足

**方案**：
- 降低质量标准（谨慎）
- 增加数据源
- 减少实验规模
