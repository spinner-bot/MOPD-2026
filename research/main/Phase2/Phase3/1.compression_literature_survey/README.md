# 工作1：4B/9B 量级模型的输出 token 压缩调研

**阶段**：Phase3
**状态**：开工（2026-10-21）

## 术语澄清（重要）

- 导师口中的"小模型"指 **4B/9B 这一档**（Vision-OPD 原文的两个基座），是相对 70B+ 部署模型而言，不是学术定义的 small model。
- 本项目做的是 **输出侧压缩（output-token / CoT 压缩）**，不改模型参数；**不是**文献里的 *model compression*（蒸馏/剪枝/量化），检索时必须区分，否则会捞回大量无关论文。
- 已知风险：现有的输出压缩工作多集中在 7B 以上的推理模型，4B/9B 多模态模型上的证据稀少，迁移可行性需逐篇标注。

## 目标

为 Phase3 主线（把输出压缩嵌入 OPD 训练）提供方法依据，回答三个问题：

1. 小模型（4B/9B 量级）如何压缩输出 token？现有方法各自压缩到什么幅度、付出什么准确率代价？
2. 这些方法能否迁移到多模态推理/自蒸馏场景？迁移的前提与失效条件是什么？
3. 哪些环节可以嵌入 OPD 自蒸馏训练过程（teacher-student 信号、loss、数据构造）？

## 背景

- 导师在 A211 会议（2026-10-18）布置：先做文献调研，不要动 OPD；创新点定位为"现有压缩方法 + 集成进 OPD 训练"。
- 目标压缩幅度约 50%，判据是准确率不降（而非提升）。
- Phase2 已证明：仅靠 prompt 压缩会掉点（工作2、工作5）。
