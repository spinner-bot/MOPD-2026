# 工作2 第1步：双教师/多教师 OPD 先验对比矩阵

**日期**：2026-10-22（UTC+8）
**作者**：Claude Code (local)
**结论先行**：导师的"一个学生、两个教师"在**架构层面已被 H-OPD（EMNLP 2026）占位**；多教师冲突、OPSD 压缩也各有工作。"视觉特权 + 简洁特权 + 输出压缩"这个**具体组合**未直接检索到，但属于已有组件的组合，novelty 必须落在**新的仲裁机制或新的受控证据**上。

## 2. 已被占据的四个位置

| 位置 | 代表工作 | 判断 |
|---|---|---|
| 一个学生 + 两个教师 + token 级仲裁 | **H-OPD（EMNLP 2026）** | **已占**，且是正式录用 |
| 多教师信号冲突的处理 | Counteraction-Aware MOPD、DOPD、From Gradients to Capabilities | **已有研究**，不能当全新发现 |
| OPSD 内压缩输出 | CRISP/OPSDC、COPD/COPSD、BIRD、MPD、Masked SD | **已占**，且强结果多 |
| 视觉特权 OPSD | OPD-V、Visual-OPSD、Vision-OPD、Where-OPD、SCOPD、LT-OPD | **已占**（多数压输入视觉 token，不是输出） |

## 3. 仍然可能的缝隙

**直接检索未发现**："视觉特权教师 + 简洁特权教师 + token 级压缩仲裁"这一具体组合。但它是四个已有组件的交叉，审稿人很可能理解为"H-OPD + CRISP"。

因此可主张的 novelty 不能是"用了两个教师"，只能是以下之一：

### 主张 A（推荐）：视觉证据门控的压缩仲裁

- 两个教师：视觉教师（zoom/mask 特权）+ 简洁教师（"be concise" 特权）。
- **仲裁信号不是教师置信度，而是"该 token 是否依赖视觉证据"**：视觉信息增益高的 token（物体属性、空间关系、OCR 结果）**不压缩**；视觉信息增益低的 token（重复描述、自验证、套话）**交给简洁教师压缩**。
- 与 H-OPD 的差异：H-OPD 按预测熵仲裁"谁更可信"；A 按视觉证据仲裁"哪里该短、哪里不能短"。
- 与 CRISP/COPD 的差异：它们没有视觉条件；A 明确保护视觉 grounding。
- 可检验假设：单教师同时加两种特权会在"视觉 token 该保留 vs. 简洁教师想删"上冲突；双教师 + 视觉门控能同时降 token、保 grounding。

### 主张 B：冲突的受控证据

- 把"同一教师叠加两种特权"作为对照，量化冲突（token 长度、视觉 grounding 指标、准确率）。
- 贡献是"诊断 + 机制"，不是新架构。
- 风险：如果没有明显冲突，故事立不住；需要先做小实验验证。

### 主张 C：预算可控的双教师

- 在 A/B 之上加推理时预算旋钮（L1/BudgetThinker 式）。
- 工程量大，且"预算"不是导师当前最关心的点；可作为后续扩展。

## 4. 结论与建议

1. **导师"两个教师"的直觉方向可行，但"架构新"不成立**；必须在第一次汇报中如实说明 H-OPD（EMNLP 2026）与多教师冲突文献，避免文章写到一半被审稿人指出。
2. **建议主攻主张 A**：视觉证据门控的压缩仲裁。它同时利用了本项目已有的两个资产——OPD-V 的视觉特权教师、VIG 的视觉信息增益信号——并与导师的"双教师"故事一致。
3. **主张 B 作为文章第一幕的实验**：先做"单教师叠加两种特权"的对照，若确实冲突，故事完整；若不冲突，及时调整。
4. **不建议**把"两个教师"或"OPSD 压缩"单独作为卖点。

## 5. 风险清单

| 风险 | 说明 | 缓解 |
|---|---|---|
| H-OPD 撞车 | 架构同构，且已正式发表 | 明确差异在"视觉证据仲裁 + 压缩目标"；引用并对比 |
| 冲突假设不成立 | 单教师叠加两种特权可能不冲突 | 先做小规模对照实验，再定故事 |
| 视觉信息增益成本 | 每 token 两次前向，训练成本高 | 用 attention/缓存近似；只在关键 span 计算 |
| 多教师文献更新快 | 2026 下半年密集出现 | 最终报告前再做一次增量检索 |
| 组件拼接感 | 审稿人可能认为是 H-OPD + CRISP | 用受控实验证明 1+1>2，而非简单组合 |
| GPU 配额 | 训练实验受阻 | 先读论文/代码；GPU 恢复后再做 |
