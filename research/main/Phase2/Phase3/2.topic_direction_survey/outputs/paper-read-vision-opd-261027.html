Vision-OPD：用区域→全局的自蒸馏，让模型学会看细节Learning to See Fine Details for Multimodal LLMs via On-Policy Self-Distillation

The same MLLM plays two roles: a teacher that sees an evidence-centered crop, and a student that sees the full image. Per-token JSD on the student's own rollouts transfers the teacher's privileged regional view into the full-image policy — no external teacher, no labels, no verifier, no inference-time zooming.

同一个多模态模型分饰两角：教师看"证据区域的裁剪放大图"，学生看"整张原图 + 红框提示"；在学生自己生成的轨迹上做逐 token JSD， 把"教师看得清"的行为写回整图推理。不需要外部教师、标准答案、验证器，也不在推理时裁剪放大。本报告覆盖数据构造、训练目标、逐项超参、主表与全部消融。

01一句话与定位One-sentence summary and positioning

它到底做了什么？What does it actually do?

同一个 MLLM 实例化出两个"条件策略"：教师看证据区域的裁剪放大图 x′，学生看整图 x（图上画了红框）；学生先生成 on-policy 轨迹，再让学生和教师在同一条前缀上给出 next-token 分布，逐 token 最小化 JSD；梯度只流向学生；教师权重用 EMA 慢速跟随。

三个关键点，把它和普通蒸馏区分开：

  • 教师不是另一个模型，而是"同一个权重 + 特权视觉输入"。所以它没有 teacher–student 的能力差距，只有视角差距。
  • 特权信息是视觉的（裁剪放大），不是答案、不是奖励。
  • 训练前缀由学生自己产生（on-policy），避免了 SFT 在教师轨迹上训练带来的分布偏移。

它的地位：这是本项目 Phase3 主线的地基。导师说"在视觉 OPD 基础上，输出太多，想压掉"，指的正是这篇。后续的 OPD-V（2608.05131）是在它之上换了一套"正/负教师 + 模态平衡"的构造，但训练骨架（条件教师 + on-policy rollout + top-K logits 蒸馏 + EMA）完全沿用。

02动机：区域→全局的感知差距The regional-to-global perception gap

为什么"看裁剪图"能当监督信号？Why does a crop constitute a valid teaching signal?

现象的测量方式很朴素：把同一个问题问两遍——一遍给整图，一遍只给证据区域（crop）。在 ZoomBench 上，区域输入的准确率系统性地高出整图输入 18–22 个百分点，而且这个差距在 GLM-4.6V、GPT-5.4、Gemini-3.1-Pro 这些大模型上同样存在。

结论不是"模型看不清楚"，而是"模型在整图中找不到该看的地方"。参数规模不能自动弥合这个差距——所以它是可控的训练信号，而不是能力上限。

论文给的定性例子（Figure 2）：问"耳罩是什么颜色"，Qwen3.5-9B 看整图答 black，看裁剪图答 green（正确）。证据本身是可识别的，只是被全局上下文淹没了。

这件事为什么重要：它把"Thinking-with-Images"（推理时反复裁剪、放大、再调模型）的效果，转化成了一个可知识蒸馏的视角差。推理时的工具调用被搬到了训练时，推理只剩一次前向。

03数据构造：三元组 (x, x′, q)Dataset synthesis

6.2K 条数据是怎么来的，每一步做什么？How the 6.2K triplets are produced.

  1. 找小区块：对原始图像 I 做目标检测 + 分割，得到一批候选框；只保留面积比小于阈值 τ 的小区域 R——这些才是"藏在大图里的细节"。
  2. 生成问题：用 Qwen3.5-397B 作为出题器，针对每个保留区域 R 生成一个"只看 R 就能回答"的细粒度问题 q。
  3. 把问题锚回整图：把 R 的边界框以红色画在整图 I 上，得到 x；并在 q 后面追加空间约束，例如"Only focus on the objects inside the red bounding box in the image to answer this question."——否则问题在整图上无从指代。
  4. 造教师视角：把 I 裁到 R 并把裁剪图放大 2×，得到 x′。
  5. 顺手造标签（只给对比方法用）：同样用 Qwen3.5-397B，以 R 为图像输入多次采样答案，只有多数答案一致度 > 0.75 的题才保留，作为 SFT / GRPO / DAPO / OPSD 的 ground-truth。Vision-OPD 自己不用这个标签。

最终 6.2K 条三元组。注意两个容易被忽略的细节：

教师（裁剪图）和学生（整图+红框）看到的不是"同一张图的两种分辨率"，而是两套不同的提示：教师的问题没有红框约束句（因为裁剪图里只有那一个区域）。因此教师-学生之间的差异 = 视角差异 + 少量提示差异，论文没有单独消融这一项。

红框是为了消歧，不是为了给教师看。它的作用是让"整图条件下"的问题有唯一指代物，从而保证区域-全局对比测量的是"注意力"而不是"问题歧义"。

04训练方法：目标函数、top-K 与 EMAMethod: objective, top-K, EMA

损失怎么算，梯度走哪里？How the loss is computed and where gradients flow.

4.1 两个条件策略Two conditional policies from one model

  • 学生：p_S(·|x, q) —— 整图 + 红框 + 带空间约束的问题。
  • 教师：p_T(·|x′, q) —— 裁剪放大 2× 的证据图 + 原问题。
  • 两者初始权重相同，但教师不反传（stop-gradient），并用 EMA 慢速跟随学生：θ_T ← 0.05·θ_S + 0.95·θ_T。

4.2 逐 token 散度Per-token divergence over the student rollout

学生先按自己的策略生成完整回答 y ~ p_S(·|x,q)；然后把这条 学生自己写的轨迹同时喂给教师和学生，在每个位置 n 比较两者的 next-token 分布：

D(p_T‖p_S)(y) = (1/|y|) Σn=1|y| DJSD( p_T(·|x′, q, y<n) ‖ p_S(·|x, q, y<n) ) 式 (3)：只在学生实际生成的位置上算；教师只提供目标分布，不接收梯度。
L(θ) = E(x,x′,q)~D Ey~p_S(·|x,q) [ D(p_T‖p_S)(y) ] 式 (4)：外层对数据采样，内层对学生自己的 rollout 采样。

JSD 的插值权重 β：JSD(p_T‖p_S) = β·KL(p_T‖m) + (1−β)·KL(p_S‖m)，其中 m = β·p_T + (1−β)·p_S。论文用 β = 0.5（对称）。

4.3 top-K 近似：为什么不是全词表Top-K logits with a tail term

全词表（15 万+）做 logits 蒸馏显存扛不住。做法是：只取学生 logits 的 top-K=100，以及教师在同一批 token id 上的 logits，配一个 tail-probability 项补上剩余概率质量，从而得到仍然"归一化合法"的逐 token 散度。

论文的量化依据：在本任务中，top-100 之外的 token 覆盖的概率质量 < 1e-13——所以截断几乎无损。这个数字值得记住，因为它是"为什么 K=100 够用"的唯一实证。

4.4 为什么梯度只过学生Why stop-gradient on the teacher

  • 如果把教师也算进梯度，最小化 JSD 的最优解是"两边一起塌到某个常数分布"——这就是自蒸馏崩塌。
  • 第 08 节的消融证明了这点：不冻结、不用 EMA，直接拿当前策略当教师，训练完全崩溃（六基准平均 0.59）。

4.5 算法全流程（对应论文 Algorithm 1）

# 每个训练步
for batch B in dataset:                      # 采样三元组
    for (x, x_crop, q) in B:
        y = student.generate(x, q)           # on-policy rollout，最多 1024 token
        for n in 1..len(y):
            p_T = teacher.logits(x_crop, q, y[:n])   # 特权视角，no grad
            p_S = student.logits(x, q, y[:n])        # 只在 top-100 ∪ 教师对应位算
            d_n = JSD_beta(p_T, p_S)                 # beta = 0.5
        loss = mean(d_n)
    update(student)                          # 梯度只流向 student
    teacher.ema_update(student, rho=0.05)    # 教师慢速跟随

10.1 它已经给了我们什么

  • 框架：verl 改装版，训练脚本、数据格式、评估脚本全部开源（github.com/VisionOPD/Vision-OPD），本地已完整存档。
  • 一条已验证的"特权信息 = 视觉变换"路径：我们想做"视觉特权 + 简洁特权"双教师，可以直接在这套代码上加第二个教师，而不是从零搭。
  • 关键的稳定性知识：教师必须冻结或 EMA，否则崩溃；散度选择取决于教师性质（JSD vs reverse KL）。
  • 评测口径：6 个细粒度 + 4 个 holdout，我们可以直接沿用，做"压缩后是否遗忘"的对照。

10.2 它没有解决的问题（我们的空隙）

它不压缩输出。Vision-OPD 换了教师的视角，但学生的生成长度、推理风格完全没变——论文里 1024 token 的 rollout 上限只是训练预算，不是压缩目标。导师说的"输出太多"，在这篇里没有任何对应手段。

  • 单特权：只有"视觉视角"一种特权信息。我们想加"简洁"，就变成两个特权源共同作用于同一个学生的逐 token 分布。
  • 冲突未被检验：视觉教师想让模型"多说细看"，简洁教师想让模型"少说快答"。两者的逐 token 目标在什么位置冲突、冲突有多大，这篇不涉及。
  • 生成长度与监督量的耦合（见 8.3）：压缩会让可用的蒸馏 token 变少，这是自蒸馏 + 压缩的固有张力。

10.3 5 分钟口头稿

① 问题：多模态模型在细粒度任务上，看裁剪图比看整图准 18–22 分。差距不是"看不清"，是"找不到"。

② 方法：同一个模型分两角——教师看裁剪放大图，学生看整图加红框。学生先生成，教师在同一前缀上给出 next-token 分布，逐 token 做 JSD。梯度只给学生，教师 EMA 慢跟。

③ 关键配置：JSD β=0.5，top-100 logits，生成长度 1024，EMA ρ=0.05，1 epoch，6.2K 合成数据，Qwen3.5-4B/9B。

④ 结果：4B 70.68→77.07，9B 73.37→79.68，超过 397B 开源和 GPT-5.4；相较 SFT/GRPO/DAPO 不掉 holdout 分（SFT 掉 MMStar 近 10 分）。

⑤ 对我们的意义：这是双教师方案的代码地基。它证明了"视觉特权 → 逐 token 蒸馏"可行且稳定；但没有处理输出长度，也没检验两个特权是否会打架——这正是我们要补的。
