# 2130-T：Phase2 工作5全量五模式评测实施方案

**创建时间：** 2026-10-14 01:01（Asia/Shanghai）\
**作者：** Codex（本地工作站）\
**触发原因：** 研究范围由此前 CV-Bench 2000 样本比较转为 Vision-OPD 完整主评测集上的全量五条件评测；需先明确可复现的评测、分层统计和交付流程。

## 一、目标与设计

工作5将对 Vision-OPD 论文主评测集做五轮完整评测：S0（不发送 system message）以及 SC、S1、S2、S3 四个 system-prompt 条件。每一题在五种条件下重复评测，模型、checkpoint、图像、原始 user query、生成参数和评分路径保持一致；原始回答与评分过程完整保存。最终形成可按 benchmark、类别、题型、语言等层次分析的全量 5S 逐题数据，并完成高水平统计分析及中英双语图文报告。

这不是将所有记录混为一个总准确率的简单扩容。V* Bench、ZoomBench、HR-Bench 4K/8K、MME-RealWorld EN/CN 将分别呈现；各 benchmark 原生的子任务、答案格式和评价指标均保留。全量数据提升估计精度，但不能自动消除评分器偏差、数据相关性或跨 benchmark 不可比性，分析中将明确处理这些限制。

## 二、范围与执行前核验

根据目前核对的 Vision-OPD 评测入口，主评测范围暂定为六个 track：V* Bench、ZoomBench、HR-Bench 4K、HR-Bench 8K、MME-RealWorld EN、MME-RealWorld CN。MME Lite 与主 EN/CN 完整集不重复计入；CV-Bench、MMStar、MMVP、POPE、VisualProbe 等代码支持的其他集合，暂列为额外/泛化评测，不纳入主范围。范围会在数据清点阶段与论文表格、官方脚本示例及导师任务定义复核后冻结。

现有数据页面显示 V* 为191题、ZoomBench为845题、HR-Bench 4K/8K各800题；MME LMMs-Eval 转换集页面约为英文23.1K、中文5.89K行。MME 原始基准介绍的 QA 数与 LMMs-Eval 转换集显示数不同。因此这些数字仅为启动规划参考，**不是本报告确认的全量题数**。实际规模必须由固定 revision 的下载数据及 Vision-OPD 转换输出逐行核验，分别记录 QA 数、图片数、类别/题型数、无效和排除项，并冻结哈希。

正式全量运行前需完成：

1. 固定 Vision-OPD 代码 commit、依赖环境和各数据集 revision；重新生成并校验各 benchmark 输入文件。
2. 精读 `prepare_data.py`、`infer.py`、`judge_qwenlm.py`、`cal_acc.py` 对六个 track 的输入及评分路径，尤其确认 ZoomBench 的 full/crop 双视图在实际模型调用中如何使用。
3. 核实 MME 的选项标签范围、EN/CN 类别字段和完整 parquet 实际行数；核实类别的唯一键与评分输出能可靠关联。
4. 对照论文的主结果表与脚本运行示例，冻结主评测范围；把额外 benchmark 与 Lite 子集明确排除或另立扩展范围，不混淆口径。
5. 记录模型 checkpoint、tokenizer、服务器推理后端、生成参数、图像编码、最大 token、thinking 设置、并发、重试策略及评分器配置。

## 三、五种提示词设计

五条件语义沿用工作2已定义的 S0/SC/S1/S2/S3 梯度，不重新随意设计提示词。S0 不带 system message；SC 中性说明角色和任务；S1 要求简洁；S2 要求直接给出适当答案；S3 要求只给完成任务所需的最小答案。

但原工作2的 S2/S3 明确提到选项字母、A–D，不能无差别应用到 MME 的 A–E、ZoomBench 开放式问题或其他答案空间。为尊重题集特性，SC/S1保持通用语义，S2/S3 按题型做预先定义的答案格式适配：多选题使用该题实际选项范围；二元任务使用原生标签；开放题直接简洁作答而不强迫输出选项字母。ZoomBench 根据数据提供的题型元数据做确定性路由。所有模板将版本化、逐字保存并计算哈希；报告按条件和适配模板版本披露。此适配必须先通过不同题型 pilot 核验，不能在正式运行过程中临时改词。

## 四、复现原评测并保障评分可信

推理沿用 Vision-OPD 的 benchmark 数据准备、图像处理、user query 和各模型调用方式；S0 必须与官方基线的消息结构一致。S1–S3 仅额外加入 system message，其他设置不得变化。保留每条完整原始输出、返回元数据、样本唯一键、条件、prompt 版本和推理配置。

评分按 benchmark 使用 Vision-OPD 原生实现，包括选择题/二元答案解析、LLM 语义判断及类别专用指标。由于本项目前序工作已发现规则判别可能错误，评分环节必须保留原生评分结果和 `judge_source`，保存 judge 原始响应/日志；对规则快通道、LLM 路径、开放题及边界输出分别做分层人工审计。技术错误、超时、解析失败不能自动等同于模型错误，也不能静默丢弃。正式报告分别标明原生 benchmark 分数、审计结论及必要的敏感性分析，不把自行修正值混称官方结果。

## 五、运行规模与完整性

若冻结六集合总 QA 数为 `N`，五条件需要 `5N` 次模型生成。先完成全量数据清点和存储/吞吐估算，再进行覆盖各 benchmark 与题型的 pilot；pilot 之后冻结代码、prompt、模型和配置。全量任务按 benchmark、条件和 shard 切分，可断点续跑；每 shard 保留输入 manifest、配置哈希、Slurm 记录、完整日志、输出、失败 ID 与完成标记。失败 shard 单独补跑，历史尝试不覆盖。

全量质量门禁要求每个 benchmark-condition 均覆盖该 benchmark 的全部固定样本，唯一键无重复，五条件样本集合完全相同；图像、query、类别、参考答案字段可追溯，所有错误/拒答/空答均有显式状态。将模型请求数、成功数、重试数、评分数与预期逐项对账；未过门禁不得产出正式准确率或下结论。

## 六、统计分析与报告

按 benchmark 和官方类别分别报告分母、有效覆盖、原生指标、区间及样本构成；不会只报告合并准确率。保留 benchmark 等权宏平均与按 QA 加权微平均作为不同摘要，并解释其统计含义。五条件比较采用同题配对设计，呈现效应大小与置信区间、多重比较校正后的检验；按类别和题型分析异质性。若一张图关联多条 QA，则以图像/任务为聚类单位处理不独立性。

主要分析包括各集合/类别表现、五模式间正确性转移、有效答案与格式遵从、不同原生评分指标、字符/token 长度分布与长尾、长度和表现的条件关联、类别/题型交互、评分器路径及审计分歧。图表应与解释共同呈现，避免用冗长大表代替分析；成品报告全程中英双语，样本案例按需选取并隐藏无助于解释的原始 ID。
