# 2168-T：回填时限与 checkpoint 续跑策略

## 调度配置修订

服务器实测 `SchedulerType=sched/backfill`。全量作业原先请求normal QoS允许的整24小时；在有更高优先级作业预留时，这一长时限降低短资源空档回填可行性。Slurm官方调度说明建议提交合理的作业时限以改善backfill排程（[Slurm Backfill Scheduling](https://slurm.schedmd.com/sched_config.html)）。

已将全量单条件作业时限改为2小时，并允许五个提示词条件各占一张A100、最多五项并发。超过2小时只会结束当前片段；每条成功回答在写出后立即flush，重启会识别并保留成功UID，仅请求缺失/错误样本。续跑管理器的补交同样指定2小时时限与最多5路并发，最大轮数从12提高到80；有界上限可覆盖约160小时的累计分片运行窗口，避免 pilot 的长尾时间风险使管理器过早停止。

该配置不改变 Vision-OPD 模型、问题、prompt、32768最大生成token、采样参数、回答或评分方式；每轮均在normal QoS与分区时限内，不通过debug QoS切片。后台数据仍仅写入large userexternal存储区。
