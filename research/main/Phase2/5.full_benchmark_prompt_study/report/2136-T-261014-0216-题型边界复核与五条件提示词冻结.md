## 1. ZoomBench题型复核

对845条记录按 `question_type` 与参考答案格式做全量交叉计数：

| 原始 `question_type` | 字母型参考答案 | 数字型参考答案 | 合计 |
|---|---:|---:|---:|
| `mcq` | 621 | 0 | 621 |
| 空值 | 0 | 224 | 224 |

空值组抽查的原始问题明确要求用阿拉伯数字回答（例如计数问题），参考答案与此一致。统计时保留原字段为空，同时建立派生任务类型“数字短答/计数题”；不修改原 parquet 或 user query。`audits/task-edge-cases.json` 留存每种类型的原始题目/答案格式摘例及全量交叉计数。

## 2. MME六选项异常的逐项复核

MME EN的22条及CN的8条六项记录均已逐条读出。30条全部满足：

- 参考答案均为 `E`；
- 六条选项的标签序列均是 `A, B, C, D, D, E`，第五条重复标记D，而非一个新标签F；
- 官方准备脚本会原样将源选项文本拼入问题，并在 user query 中指示按 A–E 回答。

这是源数据中的格式异常/歧义，尤其D标签重复会给模型造成真实歧义。为遵守“按Vision-OPD原评测输入”，不重标、不删题、不改写 query；全部纳入主结果，并预先定义这30条为单独风险子组，另报告含/不含该子组的敏感性结果。评分输出需要保存原始回答，并人工复核该组错误/格式解析边界。提示词不再按选项个数推导可用标签，也不重复硬编码 `A–D` 或 `A–E`。
