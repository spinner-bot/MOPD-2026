## 3. 对网页估算与初版统计的更正

MME 英文版 Hub 页面曾显示估算 23,089 行；固定 revision 的70个完整 parquet 分片合计为23,609行，相差520行。MME 中文版此前 viewer rows API 返回5,891；完整固定 revision 的13个 parquet 分片合计为5,917行，相差26行。本工作使用下载并扫描的 revision 结果作为源文件计数依据；网页 estimate/API 读数保留为历史查询结果，不再用于计划总量。

HR-Bench 的一个 Hub revision 同时发布 `hr_bench_4k.parquet` 与 `hr_bench_8k.parquet`。初版脚本按两个 track 的目录各抓取了仓库全部 parquet，因此中间的 `row-counts.json` 曾错误显示每个 track 1,600行。该数是把两个 track 都重复相加的程序错误，不是 benchmark 真实规模。修订脚本按 track 仅纳入对应 parquet 文件，正确的源行数分别为800。下载时形成的额外文件副本保留作本轮中间产物，不纳入 track 行数；后续 fetch 修订将只请求匹配文件，避免继续重复获取。

## 4. 数据状态及后续门禁

目前核验的是 parquet 文件级 revision、文件清单、字节数和源行数。下列工作仍未完成：

1. 将每个源数据集按 Vision-OPD 官方 `prepare_data.py` 语义转换，逐项比对输入 query、选项、reference answer、图片/裁剪图与原生评分字段。
2. 对每个转换后的样本生成稳定 UID，验证重复、缺失、无效图片、无参考答案及异常类别，并解释源行数与有效评测数的差异。
3. 验证 MME EN/CN 的 category/l2-category、选项空间及评分分组，ZoomBench 的 MCQ/OQ 类型与视图字段，HR/V* 各自的任务标签。
4. 对五条件共用的样本集合做完全相同性校验，并冻结有效 N 与其五倍请求数。

在这些门禁完成前，32,162 与160,810只用于数据规划；不能称为最终全量运行规模，也不能计算正式模型准确率。
