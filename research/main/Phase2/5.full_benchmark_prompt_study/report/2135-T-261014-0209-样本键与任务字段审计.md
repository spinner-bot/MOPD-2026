# 2135-T：样本键与任务字段审计

**记录时间：** 2026-10-14 02:09（Asia/Shanghai）  
**状态：** 六个固定 revision 的源行均通过主键唯一性检查；类别、题型和答案空间已初步盘点。下一步需验证实际 query/media 转换并做内容边界 pilot。

## 1. 主键和源行覆盖

服务器逐文件读取不含图像载荷的主键、参考答案和分类列。六个 track 均满足 `源行数 = 非空唯一主键数`，未发现空主键或重复主键：V* 191/191、ZoomBench 845/845、HR-Bench 4K 800/800、HR-Bench 8K 800/800、MME-RealWorld EN 23,609/23,609、CN 5,917/5,917。详细结果与字段频数保存于 `audits/sample-key-answer-audit.json`；schema 与类别频数见 `audits/schema-and-category-audit.json`。

这意味着当前源数据的 `(track, source key)` 可作为稳定配对主键基础；正式预处理仍会加 benchmark 前缀，并验证写出后的 ID 集合、图片文件和五条件覆盖，不据此跳过转换后的门禁。

## 2. 数据集类别、题型与答案空间

- **V*：** 2类 `direct_attributes`（115）和 `relative_position`（76）；参考标签为 A/B/C/D，分别71/70/27/23。
- **ZoomBench：** 题型字段为字面值 `mcq` 621条和 `blank` 224条；reference response 的聚合频数中有621个字母型标签和224个数值型字符串，与题型样本数相符。`blank` 不是缺失值；原始 query 明确要求用阿拉伯数字作答。分层时保留源类别 `blank`，另可解释为数字短答，不回填或覆盖源字段。Zoom 的图像记录同时有 `image` 与 `crop_image`，但官方 `infer.py` 实际只选取 `images[0]` 的全图；本研究遵循原推理输入，不额外发送 crop。
- **HR-Bench 4K/8K：** 每个 track 中 `single`/`cross` 各400条，`cycle_category` 0–3各200条；答案 A/B/C/D各200条。
- **MME-RealWorld EN/CN：** 保留9个顶层 `category` 和约40个 `l2-category` 字段值；EN/CN 各自类别分布不同，不合并抹平。答案空间都包含 A–E。EN有23,587条五选项及22条六选项，CN有5,909条五选项及8条六选项。六选项记录要求对官方固定 A–E user query 做单独边界核验；不能误把整个数据集都描述为A–D，也不能假定六选项对应正确答案必为F。

类别拼写大小写按源数据原样保留，例如EN中 `Person/counting` 与 `person/counting` 是两个不同的源标签，不在预处理中自动归并。分析代码需同时报告来源标签和任何经过解释的标准化汇总，避免隐式改写类别。

## 3. 对五条件 prompt 的约束

不同 track 答案空间不统一：V*/HR主要A–D，MME主要A–E且存在少量六选项，Zoom同时含字母标签和短数值回答。五条件须维持同一任务语义梯度，但 S2/S3 不能向所有记录强写 A–D。SC/S1可使用通用任务指令；S2按原题任务空间要求直接作答；S3要求仅输出完成该题所需的最小回答，具体允许形式从官方 user query / 题型确定，不泄露答案、不改写 user query。不同题型适配模板将冻结为版本化文件，并在运行清单保留条件、模板 ID 和哈希。

Zoom字段空值应在转换后的原始 query 与 response 上复核后，才冻结为“开放题”分层。MME六选项记录要确认官方prompt与真实选项列表之间的对应关系；在完成这两个核验前不启动覆盖这些边界的正式全量任务。

## 4. 转换中的保留与不变项

为可分层统计，转换样本须额外保留 `category`、`l2-category`、`cycle_category`、`question_type`、`bbox`、语言、源文件和稳定 `sample_uid`（字段仅在相应数据集实际提供时填写）。这些元数据不能拼入用户问题、传给模型作为题外信息或改变原始参考答案。模型看到的 user query 和媒体必须与 Vision-OPD 官方 `prepare_data.py` + `infer.py` 一致：V*的官方后缀、HR选项呈现、MME原查询构造均逐字复现；Zoom继续遵循官方的全图输入行为。S0的消息列表必须与原评测一致，无 system message。
