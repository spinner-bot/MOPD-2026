# 五组原始输出的大模型重判协议（初稿）

## 1. 分析对象与数据来源

- 正式 run：`60011513`；冻结样本数：2000；条件：S0、SC、S1、S2、S3；总回答数：10000。
- 原始回答：`../2.short_output_prompt_study/runs/60011513/outputs/{condition}.jsonl`。
- 冻结题目、选项和标准答案：2 号工作的样本清单及 inference input。标准答案必须从冻结数据读取，不能由判别模型改写。
- 一条判别记录唯一键：`(sample_id, condition)`。每个回答、题目和 gold option 必须原样保留并可追溯。

## 2. 判别任务

判别器只负责识别被测模型在整段回答中最终表达的选项，不负责重新解题，也不直接评价回答是否正确。输入包括问题、A–D 选项和该条件的完整回答；不输入原图或 gold option。判别器输出最终选项及作答状态，再由确定性程序将最终选项与 gold option 比较计算正确性。排除 gold option 可避免其对抽取造成暗示，也可避免 judge 以自己的解题判断取代被测模型实际作答。

返回状态：

- `ANSWERED`：可以从最终答案或明确的语义表达唯一识别选项 A/B/C/D；
- `NO_ANSWER`：回答未表达可判定选项；
- `AMBIGUOUS`：回答没有唯一最终选项或自相矛盾。

结构化记录还须保留 `selected_option`、支持判定的原文证据片段、判别器原始文本、模型标识、prompt 版本、采样参数和请求状态。`NO_ANSWER`、`AMBIGUOUS` 在常规准确率中计为未答对，同时单列数量和比例；不得静默丢弃。

## 3. 判别规则与歧义处理

1. 提取回答实际主张的最终选项，而非回答中偶然提到的选项字母。
2. 优先采用清楚标记的最终答案；回答未给字母但明确选择了某个选项文本时，按题目选项映射到相应字母。
3. 解释过程中的否定选项、举例选项和被排除选项不作为最终答案。
4. 多个答案无法消解、相互矛盾或没有明确收束时，返回 `AMBIGUOUS`；没有作答时返回 `NO_ANSWER`。
5. judge 不根据题目自行选择其认为正确的选项，不把 gold option 当作诱导信号，也不修改/润色被测回答。
6. judge 必须返回可机器解析的 JSON。解析失败的请求保留原始响应，按同一固定协议重试；超过重试上限的记录标为技术失败，不得默认计为错误或跳过。

## 4. 模型和推理冻结

当前候选已确定为服务器本地 Qwen3.8-27B BF16 checkpoint（`/leonardo_scratch/large/userexternal/rqian000/models/Qwen3.8-27B`，配置架构 `Qwen3_5ForConditionalGeneration`）；服务器 `sc-vllm` 环境包含 vLLM 0.30.0+cu129、PyTorch 2.13.0+cu129、Transformers 5.17.0。运行使用 `cuda/12.6` module，兼容性仍须由试判日志确认。正式配置须记录 checkpoint/config 哈希、提示词哈希、温度 0、top_p 1、seed 0、最大输出 384 tokens、最大上下文 8192、JSON schema 解码及单卡分片参数。模型权重在 A100 上曾成功加载（约 51.1 GiB），但试判尚未成功，因此当前配置还未通过冻结门禁。

先生成固定 pilot，覆盖五种条件、答案字母、显式字母答案、仅语义答案、先否定后肯定、提及多个选项、冗长推理、无有效答案和歧义输出。pilot 全部逐条人工核对；冻结 prompt 后再启动 10000 条。抽样规则、人工标签和逐条分歧须留档。

## 5. 质量门禁

1. 输入校验：五个条件各 2000 行，唯一键无重复，五组 sample_id 集合完全一致；与冻结样本一一匹配。
2. 输出校验：恰有 10000 条最终判别记录；所有原始回答均有对应记录，全部记录的 `gold_option` 与冻结标签相同。
3. 人工评估：对冻结 pilot 全量人工复核；正式结果按条件、LLM 状态、规则/LLM 答案一致或分歧分层抽样，并额外检查所有 `AMBIGUOUS`、`NO_ANSWER`、技术失败和无效结构化响应。报告抽样种子、各层样本数、逐项错误、准确率和区间。若复核发现系统性错判，修订协议/prompt 后重新冻结并重跑受影响范围。
4. 判别器证据：抽查原回答中的证据片段是否确实支撑所选选项；比较同一答案结构在五种条件中的一致性；对无法解决的案例明确列为不确定。
5. 仅全部门禁通过后，冻结 corrected correctness 数据并重算统计。未经核验的临时数字不得进入结论或成品报告。

## 6. 重分析范围与衔接

### 2 号工作的完整保留项

- 五组实际输入结构与 system prompt 对照；
- 每组有效答案、准确率、严格格式遵从、输出长度及全部已有描述性指标；
- 与基线的配对统计及多组比较；
- 输出字符数、token 数、分布偏斜、长尾、长度与答对/错的关联；
- 任务/来源分层观察、研究方向评估、结论边界；
- 代表性题目、原图、题干、五种模式的完整原始输入/输出及校正后判别结果。

原始回答字符数、token 使用量、prompt 文本、输入条件和图像哈希不由判别结果改变。任何涉及正确/错误分组、准确率、关联、配对检验或案例标签的分析必须使用新标签重新计算。

### 3 号工作的完整保留项

- 若 S2 在纠正后仍可忽略：按 LLM 标签重做 S0/S1/S3 八种互斥正确性状态和逻辑合并组、gain/loss、共同/特异翻转、任务构成与组内率、token 长度关系、图表和代表性案例。
- S2 是否纳入由纠正后 S2 准确率、相对 S0/S1/S3 的配对准确率差及 Holm 校正 exact McNemar 检验、S2 独有 gain/loss 数量和任务分布共同判断；不以单一未校正 p 值作决定。若 S2 显示会改变主要解释或具有独有且实质的翻转模式，则扩展到 S0/S1/S2/S3 的 16 状态及三组配对翻转，并保留八状态投影用于与原版工作 3 对照；否则严格重做原版 S0/S1/S3 分析。决定与依据写入报告。

### 新增：规则判别器与 LLM 判别器对照

- 原规则 `parsed_answer`、`answer_valid`、`correct` 原样保留为旧标签；不覆盖 2 号工作的权威旧派生文件。
- 每条 LLM 记录保存状态、选项、原文证据、判别器原始 JSON、版本/配置哈希；由冻结 gold 确定性计算 `llm_correct`。
- 统计答案字母完全一致率（以双方均有答案为分母）、旧/新可解析状态交叉表、基于 gold 的正确/错误四格表、每条件标签改变方向、两种准确率、Cohen's κ 与配对 exact McNemar 检验。模型标签不是独立金标准；必须结合人工审查结果解释，不把一致率误称为准确率。

工作 2 原统计分析中的准确率、答对/错长度分组、token 分位/长尾正确率、相关、配对比较、任务分层和十个五条件案例结论，全部以 LLM 标签重算。输出长度、token 使用、prompt、题目输入、图像哈希等原始事实保持原值。最终交付是一份完整整合报告，不分别交付旧版 2/3 报告的修正版。

最终报告为单文件、中英双语、嵌入所有图像，统一在 4 号工作目录交付；工作 2 的每节内容不得缺失。同时保留旧规则标签、完整 LLM 逐题 JSONL/CSV、统计源文件、图表、模型原始判别响应、配置、日志与校验清单。
