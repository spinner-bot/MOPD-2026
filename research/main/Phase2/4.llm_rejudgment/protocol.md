# 五组原始输出的大模型重判协议（初稿）

## 1. 分析对象与数据来源

- 正式 run：`60011513`；冻结样本数：2000；条件：S0、SC、S1、S2、S3；总回答数：10000。
- 原始回答：`../2.short_output_prompt_study/runs/60011513/outputs/{condition}.jsonl`。
- 冻结题目、选项和标准答案：2 号工作的样本清单及 inference input。标准答案必须从冻结数据读取，不能由判别模型改写。
- 一条判别记录唯一键：`(sample_id, condition)`。每个回答、题目和 gold option 必须原样保留并可追溯。

## 2. 判别任务

判别器只负责识别被测模型在整段回答中最终表达的选项，不负责重新解题，也不直接评价回答是否正确。输入包括问题、A–D 选项和该条件的完整回答；不输入原图或 gold option。判别器输出最终选项及作答状态，再由确定性程序将最终选项与 gold option 比较计算正确性。排除 gold option 可避免其对抽取造成暗示，也可避免 judge 以自己的解题判断取代被测模型实际作答。

返回状态：

- `ANSWERED`：可以从最终答案或明确的语义表达唯一识别选项 A/B/C/D；
- `NO_ANSWER`：回答未表达可判定选项；
- `AMBIGUOUS`：回答没有唯一最终选项或自相矛盾。

结构化记录还须保留 `selected_option`、支持判定的原文证据片段、判别器原始文本、模型标识、prompt 版本、采样参数和请求状态。`NO_ANSWER`、`AMBIGUOUS` 在常规准确率中计为未答对，同时单列数量和比例；不得静默丢弃。

## 3. 判别规则与歧义处理

1. 提取回答实际主张的最终选项，而非回答中偶然提到的选项字母。
2. 优先采用清楚标记的最终答案；回答未给字母但明确选择了某个选项文本时，按题目选项映射到相应字母。
3. 解释过程中的否定选项、举例选项和被排除选项不作为最终答案。
4. 多个答案无法消解、相互矛盾或没有明确收束时，返回 `AMBIGUOUS`；没有作答时返回 `NO_ANSWER`。
5. judge 不根据题目自行选择其认为正确的选项，不把 gold option 当作诱导信号，也不修改/润色被测回答。
6. judge 必须返回可机器解析的 JSON。解析失败的请求保留原始响应，按同一固定协议重试；超过重试上限的记录标为技术失败，不得默认计为错误或跳过。

## 4. 模型和推理冻结

服务器已发现多个候选本地模型目录，模型权重存在不等于已部署服务或已验证可用于本任务。正式重判前须记录并冻结：精确 checkpoint 路径及 revision/hash、模型架构、推理环境和库版本、API/运行方式、system/user 判别提示版本、temperature、top_p、最大生成长度、JSON 解码方式、并发和批大小。优先采用能力较强且可在当前节点稳定运行的本地指令模型；候选模型需先通过试判和人工对照，不得在正式运行中途换模。

先生成固定 pilot 清单，覆盖五种条件、答案字母、显式字母答案、仅语义答案、先否定后肯定、提及多个选项、冗长推理、无有效答案和歧义输出。由人工逐条标注 pilot；冻结 prompt 后再启动全部 10000 条。抽样规则、人工标签和逐条分歧须留档。

## 5. 质量门禁

1. 输入校验：五个条件各 2000 行，唯一键无重复，五组 sample_id 集合完全一致；与冻结样本一一匹配。
2. 输出校验：恰有 10000 条最终判别记录；所有原始回答均有对应记录，全部记录的 `gold_option` 与冻结标签相同。
3. 人工评估：对冻结 pilot 全量人工复核；另对正式判别结果按条件、状态及旧规则新旧分歧分层随机抽样复核，并额外检查所有 `AMBIGUOUS`、`NO_ANSWER`、技术失败及新旧判别不一致项。报告样本数、逐项错误、准确率和区间。若复核发现系统性错判，修订协议/prompt 后重新冻结并重跑受影响范围。
4. 判别器证据：抽查原回答中的证据片段是否确实支撑所选选项；比较同一答案结构在五种条件中的一致性；对无法解决的案例明确列为不确定。
5. 仅全部门禁通过后，冻结 corrected correctness 数据并重算统计。未经核验的临时数字不得进入结论或成品报告。

## 6. 重分析范围与衔接

### 2 号工作的完整保留项

- 五组实际输入结构与 system prompt 对照；
- 每组有效答案、准确率、严格格式遵从、输出长度及全部已有描述性指标；
- 与基线的配对统计及多组比较；
- 输出字符数、token 数、分布偏斜、长尾、长度与答对/错的关联；
- 任务/来源分层观察、研究方向评估、结论边界；
- 代表性题目、原图、题干、五种模式的完整原始输入/输出及校正后判别结果。

原始回答字符数、token 使用量、prompt 文本、输入条件和图像哈希不由判别结果改变。任何涉及正确/错误分组、准确率、关联、配对检验或案例标签的分析必须使用新标签重新计算。

### 3 号工作的完整保留项

- S0/S1/S3 八种互斥正确性状态和逻辑合并组；
- gain/loss、共同/特异翻转及所有样本分母；
- 翻转组内部任务构成与任务内部条件率；
- 按新正确性状态重算的 token 长度关联和图表；
- 代表性翻转案例及对应原图、三组完整回答。

只有状态/翻转类别依赖正确性，须从新标签重算。SC、S2 继续不进入 3 号工作定义的 S0/S1/S3 八状态主分析，但五组总体比较完整保留。

最终报告为单文件、中英双语、嵌入所有图像，统一在 4 号工作目录交付；同时保留完整逐题 JSONL/CSV、统计源文件、图表、模型原始判别响应、配置、日志与校验清单。

## 7. 冻结与变更记录

本协议由 2123-T 创建，因旧规则判别器存在已观测的选项误抽取而启动。模型及推理参数在实际部署与 pilot 验证后补录；每次协议或判别提示修改均记录时间、作者、原因及影响范围。正式标签产出后不得覆盖，只能新建版本并记录差异。
