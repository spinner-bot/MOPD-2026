# 2202-T：提交作者身份异常与 Git 历史改写修复

**创建时间**：2026-10-16 03:50（UTC+8）  
**创建作者**：Claude Code (local)  
**触发原因**：在生成仓库结构快照与提交历史记录时，发现 58 条提交的作者为「Rui Qian <rqian000@login02.leonardo.local>」。该人员为计算资源提供方，从未参与本项目、亦未获得仓库权限。经溯源确认为 git 身份回退所致，随即对历史进行改写修复。

## 1. 异常现象

提交历史统计中出现 58 条署名：

```
Rui Qian <rqian000@login02.leonardo.local>
```

特征高度一致，与正常署名截然不同：

| 维度 | 观察 |
|---|---|
| 时间 | 集中于 **2026-10-13 ~ 2026-10-15** |
| 内容 | **几乎全部为 merge 提交**（`Merge branch 'main' of github.com:spinner-bot/MOPD-2026`、`merge: sync …`） |
| 位置 | **全部在 main**，其他分支未见 |
| author/committer | 两者相同，均为该回退身份 |

## 2. 根因：git 身份回退

服务器（Leonardo）上该仓库工作环境的 git 身份**完全未配置**，git 启用内置回退：

| 字段 | git 回退规则 | 实际取值 |
|---|---|---|
| `user.email` | `${USER}@$(hostname)` | `rqian000@login02.leonardo.local` |
| `user.name` | 系统账号的 GECOS 真实姓名字段 | `Rui Qian` |

现场证据（Leonardo 登录节点）：

```console
$ getent passwd rqian000
rqian000:*:134514:25200:Rui Qian:/leonardo/home/userexternal/rqian000:/bin/bash
                          ^^^^^^^^ GECOS 字段

$ hostname
login02.leonardo.local        ← 与邮箱域名完全一致

$ git config --global --list   # 空
$ git config --local  --list   # 空
```

**关键判定**：账号 `rqian000` 系计算资源提供方所有，其 GECOS 字段自然登记为该人员姓名。因此

> **完成这些提交的是运行于该共享账号下的本项目服务器端自动化；「Rui Qian」这一姓名是被操作系统账号元数据带入的，并非其本人参与。**

这也解释了为何只有 merge 中招：服务器上另有 481 条提交使用了正确的 agent 身份（显式设置），说明身份配置在多数环节是到位的；而 merge 属于最"随手"、最易遗漏配置的一步操作。

## 3. 影响

无内容或正确性影响，但**污染了提交归属记录**，并会波及远程仓库的贡献统计。更值得注意的是，本情形恰好印证了报告 1093 自立的原则：

> 「Git commit 中的 author/name 只能证明 Git 中记录的提交身份，不能单独证明背后的 OpenAI 账号、具体 Codex session 或实际操作者身份。」

该原则此前是推论，本次成为实证案例。

使用 `git filter-repo`（`D:\Scripts\git-filter-repo`）按 mailmap 改写：

```

```

**影响范围**：自 2026-10-13 19:20 起 main 上 **259 条提交**哈希变化（占 1888 条的 14%）；其余分支经比对**未受影响**（`codex/r4-monitor`、`codex/w3-hardening` 等远端哈希与服务器本地完全一致）。

**安全性保障**：

1. 改写前建立仓库外全量镜像备份（311 MB，停在改写前状态）；
2. 改写后逐条核验：`Rui Qian` 归零、`leonardo.local` 邮箱归零、`Codex (CINECA Leonardo)` 由 424 增至 **482** 条、提交总数 **1888 不变**；
3. **内容完整性**：改写前后工作树哈希逐字节一致，`git diff` 为空——仅元数据变更。

最终：`fc93e005` → **`1d3e462c`**（forced update 成功）。

> 该保护机制的价值在此次得到验证：它把一个可能造成远端数据丢失的操作，变成了一次无害的拒绝。
