## 4. 触发转向的两个原因

**4.1 导师对 CRISP 的判断**

CRISP 用同一个模型加 "be concise" 指令作教师、对学生 rollout 做 reverse KL，反复迭代把简洁行为内化。导师认为：

- 数据集小、通用性不足；
- token 减少幅度有限（10%–50% 不等）；
- 创新点太薄——"加个 prompt 也是这个效果，那 OPSD 的意义是什么"。

这与我们在 2239 中的判断一致：纯压缩 + 文本信号不足以支撑一篇视觉会议论文。

**4.2 GPU/配额问题**

导师明确"显卡搞不出来，CVPR 应该是没戏了"。服务器当前 `squeue` 无运行/排队任务；账号 `aifac_f02_774` 未显示显式 GPU TRES 上限，近 7 天有 GPU 任务完成。"超限额"具体指向仍需确认（项目额度、账号或小时数）。

结论：**不再按 CVPR 四周冲刺**，改看 ICML 2027（1 月）/ ECCV（2 月），并要求"做慢一点"。

## 5. 新方向：双教师 OPSD

导师提出的方法与文章故事：

1. **出发点**：Vision-OPD 输出太长，希望压到单个 token / 单个 output。
2. **先试 prompt**：能压缩，但准确率下降——这是故事的第一幕。
3. **单教师叠加两种特权**：如果同一个教师既加视觉特权（OPD-V 的 zoom/mask），又加简洁指令，训练会冲突、出问题——这是第二幕。
4. **解法**：**一个学生、两个教师**。一个视觉教师提供视角/视觉特权，一个文本教师提供简洁信号；学生两者都不看；蒸馏时让两个教师协同/仲裁（具体机制待定，可能涉及 token 级路由、加权 KL、信任域等）。
5. **目标结果**：token 大幅下降，准确率不降甚至提升——第三幕。

**可发表性判断**：导师认为这是"组合性创新"，比纯压缩稳，但明确说"不一定能做出来"，要求先把代码和论文吃透。

## 6. 先验核查（初步，必须先解决）

导师要求确认"有没有人这么做过，我感觉应该没有"。初步检索发现**一般形态上已经存在**：

| 工作 | arXiv | 与双教师设想的关系 |
|---|---|---|
| **H-OPD** | 2607.02592 | 最接近：异构多教师多模态 OPD，VL 教师 + 文本教师，在同一 student prefix 上做 token 级置信度仲裁 |
| DualOPSD | 2608.26019 | 自适应特权教师，交替更新学生与教师；不是双特权并行 |
| DOPD | 2606.30626 | "特权幻觉"，在特权教师与特权学生之间做 token 级路由 |
| COPD / COPSD | 2607.19046 | 对比 OPD，轻/重思考提示的 log-prob 差作 token advantage，直接压缩输出 |
| MOPD / MT-SDPO / VG-OPD / MAD-OPD / PROMPTSD / Neighborhood OPSD | 2609.02548、2609.15404、2605.01347、2607.18293、2609.39687 等 | 多教师 OPD 已是 2026 年密集赛道 |

**判断**：

- "一个学生两个教师"**本身不新**，不能作为主创新点；
- 仍可能成立的具体组合是"**视觉特权 + 简洁特权 + 输出压缩**"，以及导师故事中的关键假设"**两种特权放在同一教师上会冲突**"；
- 但 H-OPD 的文本教师看图像描述、目标是推理提升，不做压缩；COPD 做压缩但不用双教师。差异需要逐项证明，不能只靠叙事。

这项核查由工作2第 1 步完成。
