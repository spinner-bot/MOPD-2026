**触发原因**：代码审计发现 `finalize_teacher_gap_manifests.py` 的旧 summary 只记录 seed、输出清单哈希和数量，没有绑定完整代码提交、运行代码哈希、三项输入哈希或 tokenizer revision。即使下游 GPU runner 完整锁定，也无法仅凭冻结档案重建“哪些人工输入经哪版冻结器产生这些 base manifests”。

## 1. 修复

提交 `6c11452` 增加以下 fail-closed 合同：

- CLI 必须显式传入 40 位小写 `--code-commit` 和 `--tokenizer-revision`；
- 冻结器核对当前 HEAD 等于提交值，并拒绝六个运行相关源码相对 HEAD 有 tracked 修改；
- 成功和“合格簇不足”两类 summary 均保存 constructed、human review、duplicate-cluster map 的 SHA-256；
- 成功 summary 另保存 tokenizer artifact hashes、逐题 generic 算法和中性词库哈希；
- 每条 base manifest 写入 `finalization_provenance`，绑定 code commit、运行代码 hashes、三项输入 hashes 和 seed；
- `generic_length_control` 增加 tokenizer revision；locked-manifest validator 拒绝缺失、短 hash 或非法结构。

这些字段不参与样本排序、人工语义裁决或条件效果计算，只使输入→清单→rotation→raw 的来源链闭合。

## 3. 操作入口

冻结时必须从仓库根目录取得完整提交并显式传入：

```bash
PINNED_COMMIT="$(git rev-parse HEAD)"
python finalize_teacher_gap_manifests.py \
  --constructed <constructed.jsonl> \
  --human-review <completed-human-review.jsonl> \
  --duplicate-clusters <duplicate-clusters.json> \
  --tokenizer <frozen-model-or-tokenizer-path> \
  --tokenizer-revision 851bf6e806efd8d0a36b00ddf55e13ccb7b8cd0a \
  --code-commit "${PINNED_COMMIT}" \
  --output-dir <new-run-id>
```

实际 Python 路径仍应使用项目固定环境。`--output-dir` 必须不存在；失败档案不得覆盖后重跑。
