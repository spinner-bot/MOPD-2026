# 2107-T-261011-单选项短输出可行性验证方案

## 1. 任务定位

本任务是 Phase2 的新验证，不是对前一轮 12 个样本案例审计的补充。前一轮结果保留为案例级观察，不再扩展样本规模。

本任务验证：在不改变已训练模型权重的前提下，通过不同 system prompt 约束模型输出格式，能否使视觉选择题模型只输出选项字母，同时保持可接受的答题准确率。

## 2. 研究背景

前一轮案例观察显示，部分视觉选择题的模型回答虽然包含自然语言说明，但说明内容可能只是对最终答案的语言化改写，并未提供额外的决策信息。对于这类任务，完整自然语言回答与直接输出选项之间是否存在必要的性能差异，需要通过同一批样本上的受控比较进行验证。

需要特别区分以下两件事：

- 题目本身需要的视觉识别或感知能力；
- 输出阶段是否必须生成完整自然语言说明。

本任务只验证第二个问题，不据此直接断言模型是否具有真正的推理能力。

## 3. 实验设计

### 3.1 数据

- 使用同一视觉问答数据集中的约 1000 个样本；
- 各实验条件必须使用完全相同的样本集合；
- 样本选择、顺序和参考答案需要固定并记录；
- 任务以选择题为主，目标输出为 A/B/C/D 选项。

### 3.2 实验条件

至少设置以下三组条件，并行运行：

1. 原始 system prompt：保持复现时使用的原始系统提示词；
2. 简短回答 prompt：要求模型减少解释、尽量简短回答；
3. 单选项 prompt：要求模型只输出一个选项字母 A、B、C 或 D。

具体 prompt 文本必须在实验前固定并归档。原始 system prompt 需要先从现有复现代码或运行配置中确认，不能凭记忆重写。

### 3.3 控制变量

除 system prompt 外，以下条件保持一致：

- 模型权重；
- 数据集与样本顺序；
- 图像输入；
- 推理脚本；
- 解码参数；
- 服务端模型配置；
- 评价脚本。

本阶段不进行重新训练，不修改模型权重，也不把 prompt 约束直接加入自蒸馏训练。

## 4. 评价指标

### 4.1 主要指标

- 答题准确率：模型最终选项与参考答案一致的比例；
- 格式遵循率：输出是否严格符合对应 prompt 的格式要求；
- 单选项有效率：输出是否可以无歧义地解析为 A/B/C/D。

### 4.2 输出效率指标

- 平均输出长度；
- 输出 Token 数量；
- 非必要解释文本的比例；
- 违反格式要求的样本数量。

### 4.3 误差分析

每组至少保留并人工检查：

- 正确且严格遵循格式的案例；
- 正确但输出过长或格式不合格的案例；
- 格式正确但答案错误的案例；
- 因强制短输出而无法判断或答题失败的案例。

误差分析中需要保留题目、图像、参考答案、完整模型原始输出和最终解析结果。

## 5. 结果判定

本任务的核心判断不是单纯追求输出越短越好，而是比较压缩输出格式是否造成准确率损失。

结果至少分为以下三种情况：

- 准确率基本保持，且格式遵循率显著提高：单选项输出具备进一步研究价值；
- 准确率下降：需要分析下降是否来自 system prompt、原始 prompt 差异、格式约束或特定题型；
- 模型无法稳定遵循单选项格式：当前 prompt 约束不足，不能直接进入后续训练设计。

上述判定仅作为后续实验决策依据，具体接受阈值需结合三组结果和误差分析确定，不在本报告中预先虚构数值结论。

## 6. 记录与交付

最终结果应整理为面向人阅读的报告包，至少包含：

- 实验条件与完整 prompt 文本；
- 固定样本清单及数据来源；
- 三组准确率、格式遵循率和输出长度统计；
- 逐样本结果表；
- 各组典型案例图文展示；
- 完整原始模型输出；
- 错误案例与人工分析；
- 运行配置、模型版本和结果文件校验信息。

报告中的样本展示应同时呈现图像、题目、参考答案、原始输出和解析结果，避免只展示汇总数字。

## 7. 与后续 Vision-OPD 研究的关系

本任务首先验证“短输出是否能够保持性能”，不直接改变 Vision-OPD 的训练流程。

只有当 prompt 级验证表明短输出在准确率和格式稳定性方面具备可行性，后续才讨论是否将输出压缩目标加入自蒸馏过程，以及如何设计 teacher-student 的监督信号、损失函数或输出约束。若 prompt 级验证不成立，则不能直接假设训练阶段加入同类约束会有效。
