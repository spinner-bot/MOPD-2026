## 5. 你崩溃后发生了什么（完整时间线，2026-09-09 深夜 → 09-10）

1. **v1 pilot 结果出炉并失败**（你崩溃前提交的 56995520 链）：1,200 条全部完成但 **0 条通过校验**（全部 invalid_json）。你崩溃前做了宽松重解析（`extract_json_response.py`/`reparse_t02_outputs.py`，commit `61b7958`，这是你的遗产，仍在用），只救回 93 条（7.75%）。
2. **claude code (local) 接管诊断**，逐条分析 1,200 条原始输出，确认双重根因：
   - **thinking 模式未关 + max_new_tokens=512**：82% 输出截断在推理链中（从未到 JSON），10.6% 截断在 JSON 中，仅 7.4% 完整。
   - **bbox 坐标系错位**：模型输出原生 [0,1000] 归一化坐标（95/95 个 bbox 上限恰为 1000，源图 1500–2672 px），旧校验只查 `x2<=w` 恒真 → accepted 样本 bbox 静默错位。
   - **排除模型能力不足**：thinking 链内容显示 9B 理解任务、定位合理。你在崩溃前"内容也不达标"的初判被修正为"结构/配置问题"。
3. **v2 修复**（commits `111459e`…`fa58858`）：runner 关 thinking（`enable_thinking=False`）、上限 1022、prompt 改为显式 norm1000 坐标约定、新模块 `bbox_geometry.py` 做确定性 norm1000→pixel 换算（保留双坐标系+provenance）、EOS 截断标志、`extract_json_object` 兜底、validator 新增 `truncated_output` 原因、新增 canary 机制（同一 allocation 内先跑 96 条，CPU fail-closed 门控通过才跑全量）。**T03/T04/T05 runner+validator 同类缺陷一并修复**（共享 `generation_audit.py`）。
4. **v2 首跑（57151182）canary 熔断**：结构指标全过（parse 98.96%、截断 0），但 accept_rate 26% < 当时 40% 阈值 → 按设计提前退出。诊断发现 **26% 是数据属性**：pilot 1,200 条全部是 Vision-OPD P 层，其 final question 以 **teacher crop 视角**撰写（铁证 `vision-opd-000002`：问 "bottom center of the image"，真值 bbox=[2130,431,2232,480] 在全图右上）。非 thinking 模型诚实拒绝"全图无法 ground"。canary 门控随即修正为**只拦配置故障**，accept_rate 降为观测项（`a3bfeaf`）。
5. **v2.1 全量 pilot（57154729→34→36）通过** ✅：1,200/1,200，**accepted 353（29.4%）**，invalid_json 仅 2；accepted bbox 与真值 source_bbox 对照 **median IoU 0.894、97% 重叠、0 越界**（同时独立验证了坐标换算修复）；吞吐 ~1,375 条/h/4GPU（~10 s/条/GPU）。

## 7. 经验教训清单（用真金白银的 GPU 时换来的，务必内化）

1. **Qwen3.5-9B 默认 thinking**。任何新 runner/新 prompt 一律显式 `enable_thinking=False`（除非实验目的就是 thinking），并为 thinking 场景预留 ≥4096 token。
2. **模型坐标系约定要顺应原生行为**：Qwen-VL 系输出 [0,1000] 归一化 bbox，prompt 要求像素坐标没用；正确做法是 prompt 显式要 norm1000 + 代码确定性换算 + provenance 留痕。
3. **校验器通过 ≠ 语义正确**：v1 的 bbox 越界检查对归一化坐标恒真。新增校验时问自己"这个检查在什么错误下会失效"；有真值（如 source_bbox）就用真值对照（IoU）。
4. **canary 先行**：排队数小时才拿到 GPU，任何配置改动先在同一 allocation 内小样本验证再全量（`submit_t02_visual_structure_v2.sbatch` 是模板）。canary 门控只拦**配置健康**（parse/截断/错误数），科学指标（accept 率）是观测项不是熔断项——v2 首跑为此白熔断过一次。
5. **截断要有审计标志**：靠 EOS 检测，不要靠事后猜。
6. **失败档案是资产**：v1 档案保留不动，让 v2.1 的每个数字都可对照。
7. **survivorship bias 无处不在**：v1 "86% accept（parsed 中）"是被截断偏差污染的；分析前先问"哪些样本没进入我的统计"。
