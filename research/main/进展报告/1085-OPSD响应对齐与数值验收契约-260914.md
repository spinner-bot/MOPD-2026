**性质**：重点文档；在任何 T/V/VT OPSD 训练代码实现和训练结果产生前，冻结“同一 student rollout 上比较 student/privileged EMA teacher”的位置、mask、分布和诊断验收边界。

## 1. 唯一监督对象

对每个基础训练样本和 rollout，student 从完整图像与最终问题 `I,Q` 生成一次响应 token 序列 (y=(y_1,\ldots,y_L))。所有训练条件的 student 都只见 `I,Q`；EMA teacher 分别见 `I,Q`、`I,G,Q`、`I,C,Q` 或 `I,C,G,Q`，但必须在**同一条 student 已生成的 (y)** 上 teacher-forcing。

在响应步 (t)，student 与 teacher 的 next-token 分布分别条件于各自 context 与相同的 token ID 前缀 (y_{<t})。teacher 不独立采样回答，不把人工正确答案或 G 的中间答案当作 response target。不同训练条件可在参数更新后产生不同 rollout；“同一条”是同一步内 student/teacher 对齐要求，不声称跨已分叉模型共享训练响应。

## 2. 位置和 mask 的运行时不变量

模型/processor 必须逐条返回或由同一编码过程导出实际展开后的 `student_response_start`、`teacher_response_start`、response token ID、attention mask、position/rope 元数据和有效响应长度。不能用原始字符串长度、`len(tokenizer.encode(text))` 或图像占位符数推断多模态 logits 起点。

对每个有效 (t\in[1,L])：

1. student logits 取自其实际 response 第 (t-1) 个 token 之后预测 (y_t) 的位置；teacher logits 取自 **teacher 自己的**相应位置；两边绝对索引通常不同；
2. 两边 target token ID 均为同一个 (y_t)，完整前缀 (y_{<t}) token ID 逐项相等，编码在 prompt/response 边界不得发生 BPE 重分词；
3. loss mask 只覆盖预声明的响应预测位置，不覆盖系统提示、图像/视频 token、G、Q、pad、无效 EOS 后缀或另一条 rollout；
4. 多 rollout 的 mask 不能把一条样本尾部与下一条开头拼为连续上下文；
5. teacher logits、EMA 权重和 teacher-side 图像/G context 无梯度；student 的有效 response logits 必须有梯度；
6. prompt/response 合计超出位置、视觉 token 或内存预算时，按 1084 作为配置/训练失败审计，不能静默左截断掉 G、图像证据、问题或响应前缀。

若 EOS 是 rollout 的真实预测终止 token，是否对该步计算 JSD 必须在训练配置冻结时统一指定；本项目主实现指定**包含第一次真实 EOS 预测步**，并排除其后 padding。触及 `response_max_length` 而没有 EOS 的响应保留已生成有效步，但必须逐条件/seed 报告截断率；若不同方法的截断率形成系统差异，不能仅凭平均 loss 解释迁移。空响应不产生伪造零损失，应标为失败并计入 1084 分母。

## 3. JSD 与 Top-K 的数值口径

对同一词表的完整归一化 student/teacher 分布计算正式目标。若为节省显存使用 Top-K=100 近似，必须在任何训练前确定其支撑集、两边概率质量与剩余词表的处理方式，保存明确的 `distillation_distribution_spec_hash`。不得各自取 Top-K 后按位置拼接，也不得把两个不相同的 token ID 集当成同一分类空间。

第一版验收要求在小词表合成分布上把实现值与独立 dense JSD 参考值比较；在真实词表上固定一组离线 logits，报告 Top-K 近似与 dense 参考的误差、遗漏概率质量和梯度有限性。若复用 Vision-OPD 官方 Top-K 公式，须把其代码版本和偏离 full-vocab JSD 的实测差异写入档案，不把“Top-K=100”本身当成数学定义。

统一使用固定的 β、温度、log-softmax 精度和归一化轴。JSD 必须非负、有限；teacher=student 时接近零，交换两边不改变值。Top-K 近似若不是严格对称 JSD，文中与代码均须标明其真实目标，不能沿用未经核对的 JSD 名称。

## 4. 训练前 CPU/单批验收

任何 GPU 训练提交前必须归档以下最小 fixture 与其 expected output：

1. **不同 prompt 长度**：同一响应在 S/T-Q/T-QA、Generic、V-add/VT 下使 teacher response 起点不同，逐步核对相同 (y_t) 和正确的 logits 索引；
2. **图像 token 展开**：processor 将不同大小图片/附加 crop 展开后，再核对实际 response 起点、attention/position IDs 与有效 image bytes；
3. **EOS、截断与 padding**：短响应含真实 EOS、触顶无 EOS、批内不同长度、空响应四种；loss mask 与计数符合 §2；
4. **teacher 梯度隔离**：一次 backward 后，student 有有限非零梯度，teacher/EMA 无梯度；
5. **分布对齐**：小词表 dense 参考、真实词表固定 logits、不同 Top-K 集合和大尾部质量；JSD/近似值、质量与梯度符合 §3；
6. **无额外信息 student**：student prompt 的 token IDs、图像输入与最终评测一致，不含 G、crop 或 answer；teacher 的 G/visual 内容与冻结训练 manifest hash 一致；
7. **同种子对照**：OPD-00、OPD-Generic、OPD-Real-T 的 student rollout 配置、loss 归一化单位和 optimizer step 数一致；真实 G 与 Generic 的逐题 teacher token 差异遵守 1071。

单批数值 smoke 还须报告有效响应 token 数、每条件 student/teacher prompt token 与视觉 patch 数、EOS/截断、JSD 分布、梯度范数、OOM、throughput 和每步 teacher forward 成本。不能仅以 loss 下降或模型输出看似合理判定对齐正确。

## 5. 冻结和权限边界

训练 manifest 必须保存 prompt/response 编码规则、processor/model revision、response-mask 规则、EOS 规则、Top-K 分布规范、代码 commit、fixture SHA 和 1084 的 failure-policy hash。正式 Stage 1 或 9B 运行前，还须满足 1071/1077 的组别、数据隔离、尺度桥与资源门。

当前没有 OPSD 训练代码、训练 smoke 或学生迁移结果；本契约只是未来实现验收，不是“数值链已验证”的证据。现有 `configs/training/training_config.yaml` 仅为旧版设计模板，未涵盖 1071 的 OPD-Generic、1078 的 V-sham、1084 的分母以及本文的响应对齐，因此不得直接当成授权运行配置。实现时需生成新的 resolved config 和对应 hash，不得在旧模板上填路径后提交。
