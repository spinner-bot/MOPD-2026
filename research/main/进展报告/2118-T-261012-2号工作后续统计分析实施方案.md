# 2118-T-261012-2号工作后续统计分析实施方案

## 1. 报告目的

本报告规定 Phase2 2 号工作在正式五条件实验之后的后续统计分析流程。分析以正式作业 `60011513` 的冻结配对样本、五组完整原始输出和逐样本派生表为基础，重点补足 tokenizer 级长度统计、答对/答错分层分析和长尾输出分析。

本阶段先固定分析方案，再执行统计和制图，避免根据结果临时改变指标或样本范围。

## 2. 已固定的实验事实

- 数据集：CV-Bench，固定 revision 为 `bc284db50d036958861cb60cdd7b77612052ce0d`；
- 合格抽样框：2343 条；
- 正式固定样本：2000 条，seed=`261011`；
- 条件：S0、SC、S1、S2、S3，每组 2000 条；
- 配对单位：`sample_id`；
- 模型：`OPD-V-Qwen3.5-4B`；
- 推理配置：`enable_thinking=false`、temperature=0、`max_tokens=2048`；
- 正式作业：`60011513`，已完成，退出码为 `0:0`；
- 五组 API 错误数和空输出数均为 0；
- 当前已有指标：准确率、有效答案率、严格格式遵从率、词法推理标记率、可见输出字符数和词数。

## 3. 后续研究问题

### 3.1 长度测量问题

字符数和词数只能描述可见文本长度，不能直接等同于模型 tokenizer 的 token 数。需要使用正式模型对应的 tokenizer，对五组原始输出重新计算输入与输出 token 数，并比较字符数、词数和 token 数之间的一致性。

### 3.2 长度与准确率问题

需要分别回答：

1. 输出 token 数与答题正确性是否存在关联；
2. 答对和答错样本的 token 长度分布是否不同；
3. 该关系是否在五种条件中一致；
4. 长输出是否集中在特定任务类型或困难样本；
5. S1、S3 相对 S2 的准确率优势是否在控制长度和任务分层后仍然存在。

## 4. 分析流程

### 4.1 输入审计

读取以下权威文件：

- `raw/inference_input.json`；
- `raw/sample_manifest.json`；
- `derived/run-60011513/per_sample.csv`；
- `runs/60011513/outputs/*.jsonl`；
- `experiment_config.json`；
- `raw/source_provenance.json`。

执行以下门禁：

- 五组 `sample_id` 集合完全一致；
- 每组恰好 2000 条；
- 每条输出均能与唯一 `sample_id` 对齐；
- 原始输出与 `per_sample.csv` 中的 response 完全一致；
- 解析答案、gold answer 和 correct 字段不重新推断、不覆盖；
- 样本和条件顺序不参与统计结果的重新排序。

### 4.2 tokenizer 级长度统计

优先使用正式运行所对应的模型 tokenizer，并记录 tokenizer 来源、模型 revision 和 tokenizer 文件或配置哈希。对每个条件、每个样本至少保存：

- `output_token_count`：原始可见输出经过 tokenizer 后的 token 数；
- `response_chars`：现有字符数；
- `response_words`：现有词数；
- `answer_correct`；
- `strict_format`；
- `task`、`split`、`source` 和 `sample_id`。

如果正式模型 tokenizer 在本地不可用，则先在服务器完成 tokenizer 计算，再通过 GitHub 中转派生表、脚本和统计结果；不使用未经确认的替代 tokenizer 作为正式结果。

### 4.3 描述性统计

对五个条件分别计算字符数、词数和 token 数的：

- 均值、中位数、标准差；
- IQR、P90、P95、P99、最大值；
- 偏度；
- 答对和答错子集的相同统计量；
- 严格格式合规与不合规子集的相同统计量。

均值和中位数必须同时报告，以避免右偏长尾掩盖典型样本行为。

### 4.4 长度—准确率关系

对每个条件分别计算长度与二元正确性之间的 Pearson 点二列相关和 Spearman 秩相关，并报告系数、p 值和样本量。由于五组使用相同配对样本，条件间准确率比较继续使用配对检验，不把独立样本检验作为主检验。

长度分组采用预先固定的组内分位数，不根据准确率寻找最佳阈值。每组按输出 token 数分成十个等频分位组，报告每组的中位 token 数、准确率和样本量。该分析用于描述非线性趋势，不把分位组结果解释为因果效应。

### 4.5 答对/答错分析

每个条件制作答对与答错的 token 长度分布图和汇总表，并使用 Mann–Whitney U 检验作为分布位置差异的补充描述。该检验不替代配对准确率检验，也不证明长度导致正确或错误。

### 4.6 长尾分析

长尾样本定义在统计前固定为各条件输出 token 数的 P95 以上样本，并额外报告 P99 样本。对这些样本检查：

- 任务类型和数据来源；
- 答对/答错比例；
- 严格格式是否合规；
- 是否出现重复、循环、无关解释或格式异常；
- 五种条件是否在同一 `sample_id` 上同时出现长输出。

长尾案例只用于机制线索和质量审计，不直接作为单独的主要准确率结论。

### 4.7 S1、S2、S3 的稳健性分析

首先复核现有正式结果：

- S1 vs S2；
- S3 vs S2；
- S1 vs S3。

随后按任务类型、输出长度分位组和答对/答错状态进行描述性分层。分层结果用于判断优势是否具有一致方向，不在未预注册的细分组上反复寻找显著性。

## 5. 统计图表

计划生成以下图表：

1. 五组字符数、词数和 token 数的均值—中位数比较图；
2. 五组 token 长度分布图，保留右尾；
3. 答对/答错 token 长度箱线图或等价分布图；
4. token 长度分位组准确率曲线；
5. 五组长度—准确率相关系数森林图或点图；
6. P95/P99 长尾样本的任务类型和正确性分布图。

所有图表必须带有样本量、条件名称、指标单位和统计口径；图表标题与结论文字使用面向读者的简洁表述。

## 6. 执行环境与资源安排

本阶段的输入审计、tokenizer 统计和大部分统计制图属于 CPU 任务，本地或服务器 CPU 均可完成，不需要 GPU。只有在 tokenizer 或模型资源必须依赖服务器环境时，才在服务器执行对应步骤。

执行时保留独立的派生结果目录，不覆盖正式实验的 raw、derived 或 report 文件。若服务器执行，通过 GitHub 同步脚本和派生产物，不使用 SSH 传输文件。

## 8. 结论边界

本阶段只能检验输出长度与准确率之间的统计关联，不能仅凭相关性证明“缩短输出导致准确率提升”。如果 tokenizer 级结果与字符数结果不一致，应以 tokenizer 级结果作为长度分析的正式口径，并保留字符数分析作为可见文本行为描述。

在重复实验或多随机种子验证完成前，S1、S3 的优势应称为本次正式配对实验中的优势，不直接外推为普遍模型能力或稳定蒸馏收益。
