# 2221-T：分层样本多模态辅助审计流程

**记录时间：** 2026-10-16 08:03（Asia/Shanghai）

## 1. 触发背景

报告2218准备的60例、300条件视图审阅包使用最长边1920px的内嵌图像。对前几个V*例进行图像核看时，题目提及的目标较小，缩略图不足以可靠判别“确实看不见”还是“图像内容与题目不符”。目前没有证据足以认定样本错配，因此不据此更改数据或结论。为提供可复现的补充核验，新增多模态辅助审计流程，使用原始全尺寸模型输入图像，而非审阅HTML中的压缩预览图。

服务器上已有的 `Qwen3.8-27B` 配置包含视觉配置；现有全量文本抽取作业使用同一模型权重，但不发送图像。vLLM环境版本记录为0.30.0。本流程使用离线 `LLM.chat` 的 PIL 图像消息格式，图像与文本构成单个user输入；接口格式依据[vLLM官方多模态输入文档](https://docs.vllm.ai/en/stable/features/multimodal_inputs/)核对。

## 2. 审计设计及边界

冻结同一风险分层样本：六个track各10个UID，五条件逐题配对，共300个判读请求。对每条请求，审计模型收到：Vision-OPD正式推理使用的完整原图、原始问题/选项、benchmark参考答案、该条件下原始模型回答。判读器**不接收**条件标签、UID、风险层标签、其他条件回答、官方裁判输出或Qwen文本抽取结论。条件和UID只作为写入结果文件的元数据。

输出采用结构化JSON：`CORRECT / INCORRECT / UNCERTAIN`、参考答案可支持性、候选最终答案、图像证据及比较理由。只有参考答案被判为图像支持时才允许输出确定的正确/错误结论；目标细节不清晰或参考答案可疑时须保留为不确定。原始生成文本与结构化判定共同保留。

这是一项**模型辅助审计**，不是人工复核，不是新的官方评分器，也不覆盖原生Vision-OPD评分、终行诊断或全量统计v4。审计模型Qwen3.8-27B此前已用于文本答案抽取；这次增加全图输入和明确的图像证据判读，可补充文本路径，但不能声称为不同模型的独立复现。其目的在于发现图像可见性、参考答案、模型回答与自动裁判之间的显著分歧，所有视角分开保存和报告。它仍不能替代研究者对关键争议案例进行人工裁决。

## 3. 实现与复现保障

新增冻结提示词 `prompts/visual_audit_v1.txt`、运行器 `scripts/run_visual_audit.py`、两张A100的Slurm入口 `scripts/run_visual_audit.sbatch` 和契约测试 `tests/test_visual_audit.py`。运行器在推理前执行：

1. 检查抽样清单覆盖六个track、每track恰有10个唯一样本；
2. 对照prepared benchmark与媒体清单，验证每个样本使用的full-image路径、字节数及SHA-256；
3. 检查每个条件的原始模型输出均包含60例；
4. 冻结300行请求清单；prompt payload只包含题目、参考答案和当前候选回答，不包含身份/条件字段；
5. 记录抽样清单、冻结请求、prompt、模型配置和全部safetensors分片的SHA-256，以及运行代码commit、软件版本、采样设置和原始输出。

作业输出将写至large scratch的 `judgment/visual-audit-v1/`，不会将benchmark独立图片提交Git，也不会改写全量推理、评分或统计输入。相同请求可断点续跑；输入、prompt、模型权重或代码commit变化时要求使用新运行目录。

本地完整Work5测试现为 **41项通过**（原37项加本轮新增4项）。新增测试覆盖300条配对请求构造、图片hash一致性、判读payload隔离，以及结构化审计结果的逻辑约束。尚未提交GPU作业；必须先在服务器以生产数据运行`--prepare-only`，确认真实300条输入冻结通过，再提交双卡作业。结果未完成前不报告任何多模态审计发现。
