**创建作者**：Codex (CINECA Leonardo)  
**触发原因**：1069 在真实人工审核前识别出 C4 浏览器可见面和审核文件严格模式的三个可消除缺口，需要把结果前契约落实为代码与回归测试。

## 1. 实现

提交 `174bc6e` 完成：

- `ReviewStore.record()` 不再向浏览器返回 `source_dataset`、`source_image_id` 或 `calibration_source_index`。服务端冻结原包仍保留完整 provenance 和后续联结字段。
- draft 载入要求每条键集合与对应冻结记录完全相同，任何多键或缺键在服务启动前失败。
- `validate_completed_review()` 独立报告 `review_schema_unexpected:*` 与 `review_schema_missing:*`，因此绕过 UI 直接编辑的 reviewed 文件也不能把额外 `null` 键带入 accepted。
- 图片端点只读一次文件，对即将返回的 payload 本身求 SHA-256；启动后字节漂移直接拒绝响应。

真实包检查随后发现 `calibration_record_id` 本身形如 `b2a-…-m3vqa-image-…`。提交 `beaad97` 因此把 `/api/index`、`/api/record`、`/api/save` 和 `/image` 全部改为整数索引与 `review-item-NNNN`；浏览器不再接收真实 calibration ID，服务端保存 draft 时仍写回完整原记录。

未改 candidate/R/PR 语义、人工字段、冻结包、32 图成员、路由门槛或机器揭示规则。

## 2. 验证

两组 B2a 专门测试为 **28/28 passed**；全套为 **186/186 passed**。新增断言覆盖 extra-null、缺键、浏览器来源身份隐藏、端点级令牌化、保存后的 provenance 保留和启动后图片漂移。

真实固定包 HTTP 只读烟测结果：32 条全部通过启动校验；首条显示 `review-item-0000`，图片 URL 为 `/image/0`；calibration ID、数据集、源图片 ID、candidate ID 四类值在索引和记录响应中暴露数为 0；响应 payload hash 与冻结 hash 一致；未创建 draft，未执行 POST，未读取图片语义。

`python3.11 -m py_compile` 与 `git diff --check` 通过。没有调用 GPU/LLM，没有生成或填写人工标签。
