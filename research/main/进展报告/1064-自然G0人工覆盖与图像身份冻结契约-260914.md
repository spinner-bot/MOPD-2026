# 1064-自然 G0 人工覆盖与图像身份冻结契约

**性质**：重点文档；自然 G0 冻结前的数据选择与图像身份增量预注册

**创建时间**：2026-09-14 11:52（UTC+8）

**作者**：Codex (CINECA Leonardo)

**触发原因**：在自然资产和 S/T 结果均为 0 时审计冻结器，发现当前实现会接受只覆盖部分 queue-eligible construction candidates 的人工完成稿；同时 duplicate-cluster map 虽保存图片 SHA-256，冻结器只读取路径到簇的映射，未重验冻结时文件字节。两者分别允许无记录的人工子集选择和基于过期图片的簇隔离。

## 1. 冻结规则

### 1.1 审核集合必须精确覆盖固定队列

`--constructed` 不得传入任意候选超集，而必须是本批次**固定、已留档的 construction queue source**。其中所有通过 `validate_constructed_row`、即会由 `build_teacher_gap_human_review_queue.py` 进入审核队列的 `candidate_id`，必须在 `--human-review` 中恰好出现一次；人工完成稿不得：

- 省略困难、borderline 或 reject 条目；
- 增加不属于该固定 construction 输入的条目；
- 为未进入审核队列的结构无效 construction 补写人工结果；
- 通过只交付至少 136 个 accept 来隐藏其余审核结果。

`accept`、`borderline` 和 `reject` 都应保留真实人工字段。只有 accept 可进入 eligible；其余条目进入 `finalization-rejects.jsonl`。若扩量 construction 超过人工预算，应先按结果不可见的固定规则生成并哈希一个不超过预算的新 construction queue source，再开始审核，不能在完成稿中事后删行。

### 1.2 图像文件必须与簇清单字节一致

duplicate-cluster map 对每个 `image_original` 已记录 SHA-256。冻结器必须在分区和写 manifest 前逐条重算审核候选的图片 SHA-256，并要求：

1. 路径存在且为普通文件；
2. 当前字节哈希等于 cluster map 中的哈希；
3. frozen manifest 的 `image_checksum` 直接使用该次重验值。

不一致条目标记为 `image_checksum_mismatch_with_cluster_map` 并拒绝，缺失条目标记为 `image_file_missing`。不得用当前文件的新哈希静默覆盖旧 cluster map，也不得继续沿用旧簇 ID。

## 2. 科学意义

审核集合完整性保证“为什么某题没进入冻结集”始终可审计，阻断人工或文件交付阶段的效果无关但不透明的子集选择。图像字节绑定保证近重复簇、人工观察对象和学生实际输入是同一对象，避免样本独立性只在旧版本图片上成立。

这两项是数据身份门禁，不改变：

- 8/32/96 基础样本规模；
- image-only、R/PR、唯一答案、最小 DAG 与 guide 规则；
- 五个自然 G0 条件、四标签轮换或 Go/Revise/Stop 阈值；
- B2a 0/32 的当前阻塞状态。

## 3. 实现与验收要求

实现必须在读取 tokenizer 和创建输出目录前检查审核 ID 集合；图片哈希可在语义合格判定时读取一次并传给最终 manifest，避免同次冻结重复读取。最低回归覆盖：

- 缺少一个 queue-eligible review 时 fail-closed；
- review 含未知或结构无效 construction ID 时 fail-closed；
- borderline/reject 记录仍计入审核覆盖并进入 rejects；
- cluster map 哈希与当前图片不一致时拒绝；
- 匹配时 frozen `image_checksum` 等于重验值。
