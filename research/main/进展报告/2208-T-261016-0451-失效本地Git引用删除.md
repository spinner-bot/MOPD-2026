**创建作者**：Claude Code (local)

## 1. 涉及引用

| 引用 | 类型 | 指向 |
|---|---|---|
| `backup/pre-author-fix` | 分支 | `358e1154` |
| `backup-author-fix-20261016` | 标签 | `358e1154` |
| `refs/remotes/live/main` | 远端跟踪引用 | `358e1154` |
| `publish/work5-2201` | 分支 | `d903f04a` |

## 2. 核验结果

### 2.1 前三个并非"孤儿"，而是有效历史中的旧提交

`358e1154` 是报告 2202 所述历史改写中，原 `c7950348` 改写后的对应提交。核验：

```console
$ git merge-base --is-ancestor 358e1154 HEAD   # 通过
$ git rev-list --count 358e1154..HEAD
14
```

即它**在当前历史中**，只是落后 HEAD 14 个提交。

原因：`git filter-repo` 的改写是**确定性的**——两次独立改写（第一次针对 `c7950348`，第二次针对含报告 2201 的 `fc93e005`）对相同历史产生了**相同的哈希**，因此第一次改写的产物恰好也是第二次改写中的一环。详见报告 2210。

### 2.2 第四个为孤儿提交

`publish/work5-2201` 指向 `d903f04a`，该提交**不在**当前历史中（`merge-base --is-ancestor` 失败）。它是第一次改写时由 `publish/work5-2201` 分支改写而来的产物，第二次改写后该分支指向了其它哈希，`d903f04a` 遂成为孤儿。

### 2.3 来源

- `backup/*` 两条：报告 2202 执行改写**前**我为留退路所建。**实际未起到备份作用**——`filter-repo` 把它们一并改写了，详见报告 2210。
- `refs/remotes/live/main`：名为 `live` 的远端已被移除，其跟踪引用残留。当前仓库仅配置 `origin`。
- `publish/work5-2201`：服务器端推送报告 2201 时使用的临时分支，其本地副本残留。

### 2.4 引用检查

全仓库检索无任何脚本、配置或文档引用上述任一名称：

```console
$ grep -rl "live/main" --include="*.sh" --include="*.py" --include="*.sbatch" --include="*.md" .
（无输出）
```

## 3. 处置

四条引用全部删除：

```console
$ git branch -D backup/pre-author-fix live/main publish/work5-2201
$ git tag -d backup-author-fix-20261016
$ git update-ref -d refs/remotes/live/main
```

删除不涉及任何提交对象丢失：`358e1154` 仍可由 `main` 到达；`d903f04a` 成为不可达对象，将在后续 `gc` 中回收（该提交为改写中间产物，无保留价值）。

## 4. 结果

当前引用列表已无残留（`main`、`origin/*`、各历史分支、`stash` 及 `codex/turn-diffs/*` 日志引用除外）。

**注意**：`codex/turn-diffs/captures/*` 与 `codex/turn-diffs/checkpoints/*` 是 Codex 工具自身写入的引用，非本次清理对象，未处理。
