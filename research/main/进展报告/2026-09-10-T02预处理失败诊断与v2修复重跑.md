## 2. 第一次失败原因

对 1,200 条原始输出逐条分析，确认**两个相互独立的结构性缺陷**，并排除"9B 能力不足"假设：

### 2.1 缺陷一：thinking 模式未关闭 + token 上限过小（主因，~92%）

runner 调用 `apply_chat_template(...)` 未传 `enable_thinking=False`，Qwen3.5-9B 默认进入 thinking 模式先输出数百 token 推理链；`max_new_tokens=512` 装不下"推理链 + 完整 JSON"。截断形态：

| 形态 | 条数 | 占比 |
|---|---:|---:|
| 在 thinking 推理链中截断，**从未输出 JSON** | 984 | 82.0% |
| JSON 已开始但中途截断 | 127 | 10.6% |
| 完整 JSON | 89 | 7.4% |

典型样本：以 `The user is asking about...` 开头、终结于 `Let's look at the "evidence_regions`；或 ` ```json {"decision":...,"bbox_xyxy":[372,` 中途断裂。这正对应"输出包含推理链与意外格式化符号"的观察。

### 2.2 缺陷二：bbox 坐标系静默错位（更隐蔽、更危险）

v1 prompt 要求 "Use pixel coordinates"，但模型实际输出 Qwen-VL 系原生 **[0,1000] 归一化坐标**：93 条 accepted 的 95 个 bbox 坐标上限恰为 1000，而源图像全部 1500–2672 px。v1 校验仅查 `0<=x1<x2<=w`（w≥1500 恒真）→ bbox **静默通过校验但坐标空间错误**，直接 crop 会系统性裁错区域（x2/w 中位数仅 0.256，所有"证据区域"被压缩至图像左上约 1/4）。

### 2.3 排除模型能力不足

thinking 链显示模型理解任务且表现合理：能判断问题前提与图像不符并给出 reject 理由、能定位目标并评估 clarity/dependency。Codex 崩溃前"内容也不达标"的初判，应是被截断推理链（天然不完整）污染的观察。

**结论：规范化/配置不足，工程修复即可；无需更强模型，无需 API 外呼。**

## 4. 第二次发现：accept_rate 26% 是数据属性，不是配置故障

对 canary 拒绝理由与 v1 同批候选交叉分析，确认根因：

1. **pilot 1,200 条 100% 来自 Vision-OPD-6K（P 层）**，且 canary 的拒绝理由清一色为"图像无法 ground 问题"。
2. **Vision-OPD 的 final question 以 teacher crop 视角撰写**。决定性证据 `vision-opd-000002`：问题问 *"What is the light source visible at the **bottom center of the image**?"*，而 `source_bbox_xyxy=[2130,431,2232,480]` 位于全图（~2667 px 宽）**右上区域**——"bottom center" 指的是 crop 视图。T02 只给模型看全图，模型诚实回答"全图底部中央没有光源"→ reject。原 Vision-OPD 方法靠给学生图像叠加 bbox 标注消解此指代；Track B 的干净 (I,Q) 条件下该指代错位暴露无遗。
3. **v1 的 86% accept 率有严重幸存者偏差**：疑难样本推理链更长→更易被 512 截断→不进入 parsed 子集；能解析的 93 条天然偏向简单接受样本。
4. 同候选对照（`vision-opd-000003` 口袋问题）：v1-thinking 反复审视后找到口袋，v2 非 thinking 直接拒绝——非 thinking 模式在细小目标上可能存在 deliberation 不足，需要量化。

### 据此做出的门控修正（a3bfeaf）

canary 门控职责重定义：**只拦截配置性故障**（parse/truncation/runner 错误/记录数），accept_rate 降为纯观测指标。科学层面的 accept 率判断属于 pilot 后分析，不属于 fail-closed 配置闸。
