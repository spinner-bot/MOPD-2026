# 2231-T：审阅页翻译引擎切换至本地 LLM 的情况说明

**创建时间**：2026-10-16 22:50（UTC+8）  
**创建作者**：Claude Code (local)  
**触发原因**：报告 2230 部署的翻译任务由 Codex 执行至第 25 例时，被上游模型提供方的内容策略拦截，无法继续。项目所有者决定改用本地 LLM 完成剩余翻译。本文记录该变更、其对既有约束的影响，以及必须随交付物一并声明的事项。

---

## 1. 现象

Codex 在翻译审阅页内容时报错：

```
Invalid prompt: your prompt was flagged as potentially violating our usage policy.
```

**判断为误拦。** 被翻译的内容是**公开学术基准数据集中已冻结的样本**——包括评测图像对应的题目、模型生成的回答、以及裁判模型的输出文本。翻译目的是供研究者阅读理解，不涉及创作、改写或扩写。

该错误在翻译长模型回答时出现；短字段（题目、选项）未报错。

## 2. 影响：报告 2230 的 R1 被废止

报告 2230 第 3 节 R1 原文要求：

> **由 Codex 亲自翻译，不得转交本地 LLM。**

本次决策**废止该条**，改用本地部署的 Qwen 模型翻译。理由：

1. **R1 的原定理由已被所有者重新论证。** R1 设立时基于"审阅须取得模型之外的判断基准，翻译若由另一模型产出会污染该基准"。此后所有者论证：**翻译误差是随机噪声，不随被比较的条件变化**——而工作4 的事故之所以是灾难，恰恰因为当时的解析误差**与条件相关**、把结论做反了。随机噪声增加个别误判与检验噪声，**不制造假的系统性故障**，因而不影响审阅的主要作用（发现环节性故障）。

2. **上游策略拦截是硬约束**，无法通过改进翻译流程消除。

3. **本地模型免费且可控**，不再受外部策略限制。

**R2（原文逐字保留）、R3（导出 JSON 结构不变）、R4（自包含）、R5（另存双语版不覆盖原件）继续有效。**

## 3. 执行方案

### 3.1 沿用既有流水线，只替换翻译引擎

Codex 已建立完整的翻译与注入设施，本次**全部沿用**：

| 组件 | 用途 |
|---|---|
| `report/translation-work/case-NNN.json` | 每例译文数据（问题、分层、标记、参考答案、五条件的评分/证据/回答/裁判输出） |
| `report/translation-work/TRANSLATION_PROTOCOL.md` | 翻译规程（七条：逐项完整、原文并列、保留内容状态、统一术语、分块可追溯、重复串无损、一致性审校） |
| `scripts/add_manual_review_bilingual_layer.py` | 将译文按正则匹配注入 HTML，追加于英文原文之后 |
| `scripts/translate_ordinal_bullet_list.py` | 序号列表的专门处理 |

**本地翻译必须遵循同一份 `TRANSLATION_PROTOCOL.md`**——引擎更换不改变翻译标准。

## 4. 必须声明的事项

### 4.1 译文来源为混合

**审阅页的译文有两个来源**：

- 案例 1–24：Codex 翻译
- 案例 25–60：本地 Qwen3.8-27B 翻译

若不做声明，将来阅读者会默认全部译文出自同一来源。**审阅页与相关报告须明确标注该分界。**

> 若所有者要求译文来源统一，可对案例 1–24 一并重译（约 60 万字符），但这会作废 Codex 已完成的工作。**本次不默认执行。**

### 4.2 译文仍为非权威阅读辅助

原结论不变：**译文不进入任何评分、统计或结论**；三项判断仍锚定英文原文。译者由 Codex 换为本地 Qwen，不改变译文在证据链中的位置——**它始终只是阅读辅助**。

### 4.3 审阅者应对译文保持的怀疑

由于译文由模型产出且无第三方核验，审阅者遇到**译文读起来矛盾、突兀或与图像明显不符**时，应回看英文原文，而非据译文直接判定。建议在审阅页显著位置保留此提示。
