## 已复现的问题与检查边界

1. **语法检查**：main 下 14 个 Python 文件全部通过 Python 3.11 AST 解析。语法通过不代表可导入或结果正确。
2. **模块导入**：除绘图模块外检查 13 个模块，10 个成功；`reasoning_depth.py` 抛出 `TypeError: Cannot create a consistent method resolution order (MRO) for bases int, IntEnum`；`metrics.py` 和 `statistics.py` 缺 scipy。
3. **深度计算**：`ReasoningDepth(int, IntEnum)` 继承冲突已运行复现。静态阅读另发现 `compute_depth_from_graph` 在边数基础上再次加 1，以及分支共享 visited 的问题；需在修复导入后用直接证据、线性链和共享节点 DAG 验证。不得以 guide 数量替代真实不可省略的推理深度。
4. **Depth 4 抽样**：10 个 depth=4 的样本得到 `{'D4': 10}`，而覆盖检查期待 `D4+`。此外，覆盖检查要求全部 3×4×4=48 组合，超出了方案仅要求覆盖各维度的表述；并非所有组合都有合理任务含义。
5. **数据划分**：10 图、8/1/1 划分及 Stage 0=1 的小样例中，Stage 0 样本同时属于 test。当前实现有意从 test 抽取，并非 train/test 同图泄漏，但 screening 会影响方法选择，需将该子集从最终确认性测试中剔除，或预留独立 screening 集。`target_prp_ratio` 未使用，分配实际按图数比例而非样本配额执行；scene/近重复去重未实现。
6. **Go/No-Go**：从 AST 单独执行 `check_stage0_go_criteria` 原函数定义，`check_stage0_go_criteria({})` 返回 `{'overall_go': True}`。这是 `all([])` 的空条件误判；本检查未声称完整 metrics 模块已可导入。静态阅读还发现 accuracy 固定用 T-Q、log-prob 固定用 T-QA，且缺 generic、depth≥3 和 paired CI 检验，不符合方案 §22–23 的完整方法选择要求。
7. **质检边界**：answerable 检查主要验证文本格式，path relevance 主要检查词汇，leakage 为规则启发式。还需独立模型验证和人工抽查；质检模板使用 0/1/2 分数，而 Schema 验证使用 0.5/0.3 阈值，需明确转换规则。

未运行 GPU 推理、训练、全量统计验证或独立 verifier；未核验外部模型权重和数据的完整性。本报告是就绪性核查，不是所有代码的正确性认证。

## 后续推进顺序与验收条件

1. **P0：补齐 CPU 可验证的正确性**
   - 建立项目独立 Python 环境，先安装 CPU 核查所需依赖并记录实际版本。
   - 修复深度导入、图深度、D4+ 分桶；校正抽样覆盖与 screening/test 隔离。
   - 重做完整且拒绝缺失结果的 Go/No-Go：T-Q、T-QA 分别与同一批 S 配对，再与 random/generic 对照；覆盖 depth≥3 和图像级 paired CI。
   - 对上述问题增加有实际判别力的回归检查，完成 Schema → 抽样 → 指标 → 判定的合成数据验证。合成结果只用于测试。
2. **P1：盘点并准备真实输入**
   - 盘点旧版资源和服务器已有模型/数据，验证图片、权重与版本，明确复用范围。
   - 固定同一个 checkpoint、processor/tokenizer 与模型软件版本；requirements 的宽泛下界不能作为模型兼容性证明。
   - 先制作少量经核验的 P/R/PR 样本，包含原图、crop、四选项、引导链、来源和深度；对齐生成/验证评分，冻结 random 与 shuffle 控制条件。
3. **P2：实现 Stage 0 运行闭环**
   - 九条件共享样本与冻结模型，接通真实图像输入、choice scoring 和 free generation 两种评估。
   - 保存 sample_id、source_image_id、条件、原始输出、选项概率、正确答案 log-prob、运行配置和错误；支持断点续跑。
   - 验证 T-random token 长度匹配、shuffle 内容一致性、crop 正确性和答案位置评分，防止输入差异引入混杂。
4. **P3：Slurm 小规模 GPU 验收**
   - 固定本项目单节点资源配置，先做少量样本九条件 smoke test；检查显存、吞吐、输出和重跑一致性。
   - 验收通过后再扩至方案要求的 400–600 条，执行分层分析、paired CI、控制组比较及 T-Q/T-QA 选择。
5. **P4：进入 Stage 1 的门槛**
   - 仅在真实 Stage 0 达到方案 §23 的 Go 条件后推进 1K–2K T-only pilot；否则先修订数据和引导。
