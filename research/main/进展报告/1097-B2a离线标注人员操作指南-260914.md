# B2a 离线真人盲审标注人员操作指南

**文档性质**：重点文档；供无法访问 Leonardo 服务器或项目仓库的真人审核者使用。

**创建时间**：2026-09-14（UTC+8）  
**创建作者**：Codex (CINECA Leonardo)  
**触发原因**：原 B2a 指南要求访问 Leonardo 上的 loopback 审核服务，外部标注人员无法使用；本指南改为不依赖服务器、SSH、Python、仓库或网络的离线工作流，不改变 B2a 的科学判定规则。

## 1. 你会收到什么

项目负责人应单独提供一个离线标注包，至少包含：

```text
b2a-offline-package/
├── images/
│   ├── review-item-0000.jpg
│   ├── review-item-0001.jpg
│   └── ...
├── b2a-review-form.xlsx   或   b2a-review-form.csv
└── README.txt
```

图片文件名只能使用 `review-item-0000` 到 `review-item-0031` 这样的匿名编号。标注包中不得出现原始数据集名称、原始图片 ID、原问题、原答案、机器 proposal、模型分数或其他来源线索。

你不需要访问：

- Leonardo、GitHub 或任何项目服务器；
- SSH、Python、网页服务或命令行程序；
- 原始数据集网站；
- 任何机器生成结果。

如果收到的包包含原问题、数据集名称或机器建议，请停止标注并联系项目负责人，不要自行删除后继续。

## 2. 离线工具

只需使用：

1. 普通本地图片查看器；
2. Excel、LibreOffice Calc、Numbers，或纯文本编辑器；
3. 项目负责人提供的离线表格。

不要使用 AI 图像增强、反向图片搜索、OCR 自动识别、图像问答工具或任何会给出语义建议的工具。可以使用图片查看器的缩放和原生像素查看，但不能让软件生成图片中不存在的细节。

## 3. 离线表格字段

每个 `review-item` 一行。项目负责人提供的表格应包含以下列；审核者只填写“人工填写”列，不改动编号列或任何隐藏列。

| 字段 | 填写内容 |
|---|---|
| `review_item_id` | 不修改，例如 `review-item-0000` |
| `image_file` | 不修改，例如 `images/review-item-0000.jpg` |
| `human_image_usable` | `true` 或 `false` |
| `human_affordance_decision` | `candidate`、`reject` 或 `ambiguous` |
| `human_target_question` | candidate 的一个具体目标问题；其他决定留空 |
| `human_canonical_answer` | 对整个问题的完整答案；其他决定留空 |
| `human_affordance_family` | `R` 或 `PR`；其他决定留空 |
| `human_evidence_descriptions` | 至少两项直接视觉证据；每项单独一行 |
| `human_reasoning_steps` | 至少两步不可省略的推理；每步单独一行 |
| `human_counterfactual_required_evidence` | 与直接视觉证据完全相同；每项单独一行 |
| `human_difficult_visual_evidence` | 困难且必要的视觉证据；R 必须为空，PR 至少一项 |
| `human_external_knowledge_needed` | `true` 或 `false`；candidate 必须为 `false` |
| `human_reviewer` | 你的姓名或项目负责人分配的审核者 ID |
| `human_reviewed_at` | 带时区时间，例如 `2026-09-14T16:30:00+08:00` |
| `human_notes` | reject/ambiguous 必填原因；candidate 可留空 |
| `review_status` | 完成该行后填 `human_blind_affordance_review_complete` |
| `human_verified` | 确认独立完成后填 `true` |

不要改变 `review_item_id`、图片文件名、行顺序或项目负责人提供的其他固定列。不要新增列。

## 4. 每张图片的判断顺序

### 4.1 先判断图片是否可用

打开完整图片，必要时同时查看适合窗口和 100% 原生像素。

- 损坏、无法打开或整体无法辨认：`human_image_usable=false`，决定为 `reject`，备注原因；
- 图片有潜力，但遮挡、分辨率或多解使判断不稳定：可以选择 `ambiguous`，备注具体原因；
- 可以稳定查看与核验目标所需信息：`human_image_usable=true`。

### 4.2 只根据图片提出一个目标

尝试提出一个需要组合多个可见事实的问题，例如比较路线、组合位置和状态、判断连接关系或根据多个局部条件确定对象。

合格问题必须：

- 只依赖图片和问题文字；
- 有唯一、完整、可明确写出的答案；
- 至少依赖两项互不替代的视觉证据；
- 至少包含两步不可省略的推理变换；
- 不需要搜索或知道人物、地点、品牌、物种、事件等外部事实。

如果提不出合格问题，选择 `reject`。如果有潜力但无法稳定确认，选择 `ambiguous`。不要为了凑够 candidate 数量而猜测。

### 4.3 填写 candidate

candidate 必须填写完整问题、完整答案、R/PR 家族、至少两项直接视觉证据和至少两步推理。

直接证据应写成图片事实，例如：

```text
左侧路线在中段被障碍物截断
右侧路线连续连接到出口标记
```

推理步骤应产生新的中间结论，例如：

```text
分别检查两条路线的连续性，得到左路中断、右路连通
将路线状态与“可到达出口”的条件结合，确定右路
```

不要把“模型认为答案是右路”“这是某国地标”或“这种动物通常会……”写成视觉证据。

### 4.4 做反事实检查

将直接视觉证据逐项复制到 `human_counterfactual_required_evidence`。对每项问：

> 如果遮住或删除这项证据，剩余信息还能否唯一推出答案？

如果仍然可以，该项不是必要证据，应删除；如果删除后只剩一个局部读取，目标偏向 P，不应标为 R/PR candidate。

### 4.5 区分 R 和 PR

- `R`：视觉证据本身清楚，主要困难是多个证据之间的关系整合；困难视觉证据列必须为空；
- `PR`：除了关系整合外，至少有一项答案必需的视觉证据确实难以感知，例如小字、细小标记、遮挡或低对比差异；该证据必须同时出现在直接证据列和困难视觉证据列。

画面复杂、物体很多或图片整体不美观，不自动构成 PR。

## 5. 三种决定的填写要求

### `candidate`

必须满足所有 candidate 字段要求，`human_external_knowledge_needed=false`，并将 `human_verified=true`。

### `reject`

用于没有合格目标、目标需要外部知识、答案不唯一、证据不足或图片不可用的情况。必须在备注中写清楚原因。

### `ambiguous`

用于图片可能支持目标，但因遮挡、分辨率、多解或其他具体问题无法稳定签名的情况。必须在备注中写清楚问题。

## 6. 工作和保存流程

1. 先确认表格正好有 32 行，编号从 `review-item-0000` 到 `review-item-0031`，图片一一对应；
2. 按顺序逐张审核，不跳过、不交换、不删除行；
3. 每完成一行就保存一次；
4. 保存前检查姓名、时间、决定和签名字段；
5. 完成后逐行复查，确认 candidate 的两个证据列表内容完全一致；
6. 另存为新文件，例如 `b2a-review-reviewer01-offline-v1.xlsx`；
7. 不覆盖原始空白表，不修改图片文件；
8. 将结果文件和项目负责人要求的校验值通过约定的安全渠道交回。

如果表格软件自动把 `true`/`false` 改成其他语言、日期格式或数字格式，应按项目负责人提供的模板恢复原文。不要把多个证据合并成一个逗号分隔单元格，除非模板明确要求每项换行。

## 7. 交回后由项目负责人完成的工作

离线审核文件不能直接替代项目的冻结 JSONL。项目负责人必须在服务器端：

1. 将匿名 `review_item_id` 按固定顺序映射回冻结 B2a 原包；
2. 检查 32 行完整覆盖且无重复、无额外行；
3. 恢复原始 provenance，但不得让审核者接触这些字段；
4. 运行官方 finalizer 检查字段类型、不可变字段、原包 SHA-256、语义门禁和 32/32 签名；
5. 保留原始离线文件、转换文件、哈希和 finalizer summary；
6. 只有 finalizer 报告 `valid_signed_reviews=32` 后，才把本轮 B2a 视为完成。

审核者不需要自行计算 candidate 数量，也不需要运行 B2a 路由分析器。B2a 结果仍必须按 1039 预先冻结的 0、1–7、8–32 路由解释。

## 8. 绝对禁止

- 查看原问题、原答案、机器 proposal 或模型结果；
- 使用 AI、OCR、反向搜索或外部知识替代图片判断；
- 为了提高 candidate 数量而猜测；
- 删除 reject/ambiguous 行；
- 修改匿名编号或图片文件；
- 把一个直接关系拆成两句话伪装成两步推理；
- 把图片复杂度本身写成 PR 证据；
- 在标注结束前与其他审核者交换逐图判断。

## 9. 最终检查清单

提交前逐项确认：

- [ ] 正好完成 32 张图片；
- [ ] 每张图片都有 `candidate`、`reject` 或 `ambiguous`；
- [ ] 每行都有审核者和带时区时间；
- [ ] 每行 `human_verified=true`；
- [ ] reject/ambiguous 都有备注；
- [ ] candidate 的答案完整且唯一；
- [ ] candidate 至少有两项直接证据；
- [ ] candidate 至少有两步不可省略推理；
- [ ] 两个证据列表完全一致；
- [ ] R 没有困难视觉证据，PR 至少有一项；
- [ ] candidate 不需要外部知识；
- [ ] 没有查看或使用机器/原题信息。
