# 2204-服务器克隆与工作树布局规范

**性质**：重点文档；冻结服务器端 Git 仓库的布局规则、身份配置要求与验收检查项。

**创建时间**：2026-10-16 04:30（UTC+8）  
**创建作者**：Claude Code (local)  
**触发原因**：报告 2202 处理「58 条提交署名 Rui Qian」时，根因最终定位为——项目报告 1063 与工作5 README 描述的是 **Git 工作树（worktree）**，而 `fast` 上实际建成的却是**独立克隆**。工作树继承主克隆的 `.git/config`，独立克隆不继承，因此该克隆身份为空、git 回退到 `账号名@主机名`，产生了那 58 条署名。本文件将这一落差固化为规则，避免重复出现。

---

## 1. 设计意图：为什么需要工作树

报告 1063《Slurm 固定提交 worktree 隔离》已确立契约，原文触发原因：

> 既有 Slurm 入口虽精确绑定 40 位 commit，但作业排队后仍从共享 `main` 启动；队列等待期间的正常文档提交会推进 HEAD，使作业在 allocation 内因 commit drift fail-closed。

要点：**一个工作目录同时只能检出一个分支**。项目作业常需排队数小时，期间任何一次向 main 的提交都会改变共享工作目录的 HEAD，使已绑定 commit 的作业读到错误代码。报告 1063 的解法：

> 独立 detached worktree，HEAD 永远等于提交时的完整 commit；冻结输入来自该提交；持久化输出写主仓库的 `research/main/outputs/runs/`。

**结论：多份工作目录是必需的，但共享一份对象库（`.git`）即可。这就是 worktree 而非 clone 的理由。**

核验方法（区分类型）：

```bash
test -d <path>/.git && echo "独立克隆（.git 是目录）" || echo "工作树（.git 是文件）"
```

## 3. 问题：独立克隆不继承身份配置

| | 工作树 | 独立克隆 |
|---|---|---|
| `.git` | 文件，指向主克隆 | 完整目录，自带对象库与 config |
| 身份配置 | **继承主克隆的 `.git/config`** | **必须各自设置** |
| 本次表现 | 11 个 codex-* 全部正常 | **work5 未设 → 回退为 `Rui Qian <rqian000@login02.leonardo.local>`** |

而 `user.name` / `user.email` 缺失时，git 启用内置回退：`user.email` 取 `${USER}@$(hostname)`，`user.name` 取系统账号 GECOS 字段。该账号（`rqian000`）为多方公用，GECOS 登记的是资源提供方姓名——**这就是「Rui Qian」被写进提交的完整机制**。

脚本化提交会临时设置身份环境变量（故此后如报告 2201 的署名正确），但 `git pull` / `git merge` 不携带环境变量，于是回退。**58 条全部是 merge 提交，与此吻合。**

## 4. 规则

### R1　服务器上只保留一个独立克隆
该克隆为 `/leonardo/home/userexternal/rqian000/spinner-bot/MOPD-2026`。其余一切并行工作**一律用 `git worktree add`**，不得新建独立克隆。

### R2　跨文件系统工作用工作树实现，而非再克隆
若作业需要 `fast` 等文件系统上的代码路径，**从主克隆创建指向该路径的工作树**：

```bash
cd /leonardo/home/userexternal/rqian000/spinner-bot/MOPD-2026
git worktree add /leonardo_scratch/fast/AIFAC_F02_774/rqian000/MOPD-2026-work5 <commit-or-branch>
```

工作树的**元数据仍在主克隆内，工作目录可在任意文件系统**——这正是 1063 契约想要的形态。

> **本轮未改建制**：`fast/…/MOPD-2026-work5` 目前仍是独立克隆。改为工作树需要迁移，属单独任务；在此之前，按 R3 为其保留局部身份配置。**新增路径不得沿用此偏差。**

### R3　任何独立克隆必须在创建后立即配置局部身份

```bash
git config --local user.name  "Codex (CINECA Leonardo)"
git config --local user.email "langxibielangle@qq.com"
```

`user.email` 必须是 GitHub 账号注册邮箱，否则提交不会归属到项目账号名下。

### R4　禁止设置账号级（`--global`）身份
该账号为多方公用（`large` 分区下并存 `chentian`、`cvpr27`、`flybrain` 等他方项目）。账号级身份会把**他人的提交一并记入本项目名下**，制造比原问题更广的归属错误。

> 本规则的来历：报告 2202 的首次修复曾误用 `--global`，随即被否决并撤回（见 2202 第 7.2 节）。

### R5　新克隆不得置于数据分区
`/leonardo_scratch/large/` 按项目约定承载数据（数据目录以 `-data` 结尾）。`large` 上现有的两个 blobless 克隆无设计依据，不得作为先例。所有者在 2203 中已决定保留，但**不再新增**。

## 5. 验收检查项

新增或迁移任何 Git 位置后，逐条核验：

| # | 检查 | 命令 | 通过标准 |
|---|---|---|---|
| 1 | 类型正确 | `test -d .git \|\| echo worktree` | 除主克隆外必须为 worktree |
| 2 | **身份非回退值** | `git var GIT_AUTHOR_IDENT` | 输出 `Codex (CINECA Leonardo) <langxibielangle@qq.com>` |
| 3 | 未污染公用账号 | `git config --global --get user.name` | 空 |
| 4 | 远端一致 | `git rev-parse HEAD origin/main` | 一致，或明确领先/落后 |
| 5 | 无异常未提交 | `git status --porcelain` | 无未预期的暂存删除 |

**第 2 项是本次事故的直接检测手段**：只要输出里出现 `@<主机名>.leonardo.local` 或非预期姓名，即表示身份缺失、必须立即按 R3 配置。

## 6. 建议增设的自动化防线

在服务器端配置一条提交前检查，命中回退身份即中止：

```bash
# .git/hooks/pre-commit（每个独立克隆各放一份）
case "$(git config user.email)" in
  *"@$(hostname)"|"") echo "git 身份未配置，拒绝提交"; exit 1 ;;
esac
```

工作树共享主克隆的 hook 目录，无需重复放置。
