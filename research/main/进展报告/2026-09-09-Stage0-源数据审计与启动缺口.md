# 2026-09-09：Stage 0 源数据审计与启动缺口

## 结论

全量下载完成不等同于 Stage 0 可启动。对固定 revision 的 Vision-OPD-6K
`train.jsonl` 进行了逐记录审计：共 6,241 条记录均不满足九条件 Stage 0 的
正式输入契约，因此当前不得提交正式 Stage 0 GPU 作业。

## 已有资源

- Qwen3.5-4B、Qwen3.5-9B 权重与 processor 已下载并固定 revision；
- Vision-OPD-6K 包含原图、教师 crop 图、bbox、选择题和标准答案；
- 九条件 prompt、输入渲染器、无泄漏划分逻辑和 Go/No-Go 判据已在 main 中。

## 审计结果

审计产物位于
`outputs/runs/20260909T-stage0-source-audit/outputs/vision-opd-source-audit.json`。

Vision-OPD 记录不含下列 Stage 0 必需字段：`sample_id`、`source_image_id`、
解析后的题目与四个选项、逻辑图像与 crop 路径、冻结长度匹配随机问题、P/R/PR
类别、guidance strategy、reasoning depth，以及完整 guide question/answer 链。
所有 6,241 条记录的完整 guide QA 对数量均为零。

这并不表示 Vision-OPD 无用：它可作为视觉特权（S、V-crop、V-add）对照和
新 P/R/PR 构建的图像来源。但不得把它伪装成文本特权实验的数据。

## 启动前剩余工作

1. 解压并登记 Vision-OPD 的原图和 crop，建立稳定的逻辑路径与来源映射；
2. 从已下载来源构建或人工/模型辅助标注一个独立的 400–600 条 P/R/PR
   screening 集，每条均须有经验证的 guide QA 链、策略、深度和冻结随机对照；
3. 运行输入验证器，冻结样本与随机化种子；
4. 建立项目独立 Python 环境、九条件推理入口和 Slurm 脚本；
5. 先以少量样本做多卡 smoke test，再提交正式 screening。

## 预计用时

若采用可追溯的半自动标注并预留人工质量验收，数据构建是主路径，预计 1–3
个工作日。推理入口、环境和 Slurm smoke test 可与其并行，约 0.5–1 个工作日。
完成冻结数据后，500 条 × 9 条件的 Qwen3.5-4B screening 在单节点多卡资源获批
后预计数小时至约一天；Slurm 排队时间不包含在内。
