## 2. 数据主线定义与契约（浓缩）

完整契约见 `docs/Stage0及后续共用数据预处理执行清单.md`（权威，不复述），此处仅存骨干：

### 2.1 流水线与角色

```text
原始资源 → T00 登记 → T01 候选池 → T02 视觉结构 → T03 latent graph+guide QA
        → T04 四选项+文本控制 → T05 独立质检 → T06 人工审核 → T07 冻结切分 → T08 消费接口
```

- 角色分工：**D** 确定性脚本（哈希/解析/切分/渲染，禁语义判断）；**B** Qwen3.5-4B（仅机械转写）；**H** Qwen3.5-9B（结构分析/graph/guide/质检，输出只能是候选）；**M** 人工（borderline 终审与分层抽查）。
- 必做模型调用 H-T02/T03/T04/T05：固定 revision、prompt hash、`do_sample=false`、原始输出与解析输出分离存放；T03 与 T05 同 checkpoint 也必须异 prompt、异目录、异 run。
- 版本单向流：`candidate → verified → human_reviewed → frozen`；冻结后修订必须开新版本。
- payload 目录：`00_sources / 01_assets / 02_candidates / 03_verified / 04_human_review / 05_frozen / rejects`（rejects 绝不静默删除）。
- 每个运行必须有 run archive（`run_archive.py` 初始化，command.txt/report.md 回填，档案不可变，重跑开新 run_id）。

### 2.2 两层流程严格分开（中期评估 §3.1 确立的表述纪律）

T00–T08 是**数据生产线**；Stage 0–9 是**科学验证线**，Stage 0 在 T08 之后才开始。因此：runner 就绪 ≠ 数据完成；gate 通过 ≠ 科学结论；T00–T08 完成 ≠ Stage 0 Go。

### 5.2 固化下来的技术合约（后续一切 H 调用适用）
