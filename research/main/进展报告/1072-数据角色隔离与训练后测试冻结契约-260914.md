## 1. 角色决定独立性要求

数据隔离不只防止图像记忆，还防止研究决策反复使用同一结果。现行流程区分：

| 角色 | 允许用途 | 禁止用途 |
|---|---|---|
| `B2a-source-calibration` | 判断图源是否值得继续、校准人工标准 | teacher gap、训练或训练后主测试 |
| `pipeline-canary` | 结构、文件和构题流程验收 | 效果估计、训练、正式测试 |
| `construction-dev` | 调 prompt、guide、选项和审核说明 | 锁定结果、训练后主测试 |
| `G0-locked-method-selection` | 一次性选择 T-Q/T-QA/Revise/Stop | G1、训练样本、validation、训练后 diagnostic 主测试 |
| `G1-locked-mechanism` | 确认 P/R/PR specialization、V/T interaction 和训练解锁 | 训练样本、validation、训练后 transfer 主测试 |
| `Stage1-train` | OPSD/SFT 参数更新 | validation 或任一测试 |
| `Stage1-validation` | checkpoint、超参数与停止规则 | 主结果 |
| `Stage1-internal-test` | 一次性训练后结构特异迁移和机制检验 | 任何模型/超参数选择 |
| `external-benchmark` | 官方协议下的外部泛化 | 反向修改后仍称同一确认结果 |

上述角色必须以 `image_cluster_id`/near-duplicate cluster 整组互斥；同图不同题、不同 crop、不同 option rotation 或不同 guide 不产生新的独立单位。

## 2. G0/G1 不能兼任训练后主测试

G0 的结果会直接决定采用 T-Q、T-QA，还是停止当前配方。G1 又会决定方法是否进入训练、哪些 task-family interaction 成为主假设。即使题目本身没有被修改，这两个集合已参与研究选择。

因此：

- G0/G1 的 pretraining teacher 结果可作为独立的前置机制证据永久报告；
- 训练完成后可以在 G1 上做明确标注的开发对齐/机制追踪，但不得把它称为 held-out transfer 主结果，也不得据此选择 checkpoint；
- `Transfer_specific=M_T-M_Generic` 的主要训练结论必须来自新的 `Stage1-internal-test` 图簇；
- 若看过 internal test 后修改训练配方，修改版必须使用新的独立确认 test 或明确降级为探索结果。

G0/G1 图簇也不进入 Stage1-train。这样避免“先用 aggregate teacher gap 选择方法，再把同一批样本作为训练素材”的隐性定向，并让前置 teacher 证据可独立重放。

## 3. 冻结顺序

Stage 1 的可执行顺序固定为：

```text
G0 locked 选择 privilege 表示
  → 独立 G1 locked 确认机制与训练门
  → 从未参与 B2a/G0/G1 结果的图簇构建 pilot-train/pilot-val
  → 单 seed pilot 只在 pilot-val 调试
  → 固定正式数据构造与训练 recipe
  → 一次性冻结互斥的 formal train / validation / internal test
  → internal test 内容与 hash 锁定，训练进程不可读取其标签
  → 运行至少 3 个共同 seed 的正式最小模型组
  → 只用 validation 选择预定 checkpoint
  → 最终一次性打开 internal test 主结果
```

如果资源要求先构建部分 test，仍须在第一项正式训练结果可见前固定成员、问题、答案、近重复簇版本、指标和主比较。Pilot 使用的模型和数据不能查看未来 internal test 表现。

## 4. 清单与运行门

未来正式数据 finalizer/runner 至少写入并验证：

- `dataset_role` 为上述枚举之一；
- `source_image_id`、`image_cluster_id`、图片 SHA-256；
- role manifest SHA、duplicate-cluster manifest SHA 与构造代码 commit；
- 全部 role 两两的 source/cluster intersection 为 0；
- internal test 的 membership/question/options/answer hash；
- validation-only checkpoint selection rule；
- 每个正式模型的相同 seed 集、训练 manifest 和 test manifest。

在 Stage1 入口中，任何 G0/G1/canary/dev cluster 与 train/validation/test 相交都必须在加载 GPU 前 fail-closed。该门现在只冻结语义；需等 Stage 1 获得授权后再实现，避免提前建设 8K 数据和训练代码。

## 5. 报告边界

论文可把 G0/G1 和 Stage1 test 组成连续证据链：前者说明 privilege 在未训练模型上存在并具有任务瓶颈结构，后者说明该结构优势能否迁移到无 privilege 学生。两者来自独立图簇，支持的是跨样本复现，而不是同一题上的循环验证。

若 Stage1 internal test 不复现 G1 上的机制方向，应如实解释为转移泛化失败或数据分布差异，不能把 G1 重新命名为主要训练后测试。外部 benchmark 是进一步泛化证据，不替代内部新锁定 test。
