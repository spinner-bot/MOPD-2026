# 1063-Slurm 固定提交 worktree 隔离

**性质**：临时文档；高频 Git 协作下的排队作业复现性修复记录

**创建时间**：2026-09-14 11:48（UTC+8）

**作者**：Codex (CINECA Leonardo)

**触发原因**：spinner-bot 要求 Codex 与 Claude code (local) 通过 GitHub 高频同步。既有 Slurm 入口虽精确绑定 40 位 commit，但作业排队后仍从共享 `main` 启动；队列等待期间的正常文档提交会推进 HEAD，使作业在 allocation 内因 commit drift fail-closed。直接在临时 worktree 内写 run archive 又会让结果随 worktree 清理而丢失。

---

## 1. 问题边界

完整 commit gate 能识别漂移，却不能让排队作业继续读到原提交。高频协作场景中必须同时固定三类位置：

1. **代码 checkout**：独立 detached worktree，HEAD 永远等于提交时的完整 commit；
2. **冻结输入**：来自该提交中的清单，或由清单记录并校验哈希的外部只读资产；
3. **持久化输出**：继续写入主仓库的 `research/main/outputs/runs/`，不能只留在临时 worktree。

worktree 解决的是“排队期间共享分支前进”这一运行身份问题，不放宽模型、输入、tokenizer、源文件哈希、人工验收或科学门控。

## 2. 已实现契约

提交 `4a7ab83..4b418fa` 完成以下修改：

- 新增可执行工具 `research/main/code/utils/create_pinned_run_worktree.sh`；只接受完整 40 位小写 commit 和尚不存在的目标路径，验证 commit 对象与最终 HEAD；
- 六个现行入口支持 `MOPD_CHECKOUT_ROOT`，并从该 checkout 解析运行代码：自然 G0、G-PC0、G-PC0 label rotation、image affordance screening、teacher-gap screening、teacher-gap construction；
- 六个入口支持独立 `MOPD_RUNS_ROOT`。固定 worktree 只承载代码，run archive 默认可由工具指向调用时主仓库的持久目录；
- helper 的标准输出只包含经过 `%q` shell 转义的三个 `export`，状态消息与 `git worktree add` 输出走标准错误，因此可安全用于命令替换。

推荐的登录节点准备方式为：

```bash
PINNED_COMMIT="$(git rev-parse HEAD)"
WORKTREE="/leonardo_work/AIFAC_F02_774/rqian000/mopd-run-worktrees/<run_id>"
eval "$(research/main/code/utils/create_pinned_run_worktree.sh \
  "${PINNED_COMMIT}" "${WORKTREE}")"
```

helper 会设置：

```text
MOPD_CHECKOUT_ROOT=<固定 detached worktree>
MOPD_EXPECTED_CODE_COMMIT=<完整 40 位 commit>
MOPD_RUNS_ROOT=<调用时主仓库>/research/main/outputs/runs
```

随后应在 `${MOPD_RUNS_ROOT}/<run_id>/` 初始化并核验 run archive，再提交对应 worktree 中的 `.sbatch`。作业启动后仍执行原有完整 HEAD 和关键 tracked runtime files 检查。

## 3. 生命周期与故障处理

- 一个 `run_id` 对应一个固定 worktree；不得在同一路径切换 commit。
- 排队及运行期间可继续在共享 `main` 高频提交，不能修改该 detached worktree。
- 作业完成后先补齐 `summary.json`、`report.md`、哈希和 Slurm 日志并提交持久 run archive；确认 Git 证据完整后，才可移除 worktree 并执行 `git worktree prune`。
- helper 创建失败、目标路径已存在、commit 非 40 位、archive 未初始化或运行入口发现身份漂移时均 fail-closed；不能就地绕过检查。
- 若 push 失败，按 spinner-bot 指令记录本地 commit 后继续独立工作，不循环重试；这不影响已经由固定 worktree 启动的作业。
