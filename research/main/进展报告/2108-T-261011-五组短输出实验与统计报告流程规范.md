# 2108-T-261011-五组短输出实验与统计报告流程规范

## 1. 文档定位

本报告将单选项短输出可行性验证规范化为一套可追溯、可复现、面向论文式分析的完整实验流程。

本流程取代 2107-T 中“约 1000 个样本”的初步规模描述，正式实验规模调整为 2000 个固定随机样本。前一轮 12 个样本仅作为案例级观察，不并入本实验的统计样本。

## 2. 研究问题

在不改变已训练模型权重和视觉输入的前提下，逐级增加 system prompt 的输出约束，是否能够显著减少无必要的自然语言输出，同时保持视觉选择题准确率和输出稳定性？

本实验只研究输出约束对模型行为的影响，不直接证明或否定模型是否具有内部推理能力，也不在本阶段修改 Vision-OPD 的训练过程。

## 3. 实验总体结构

实验采用同一样本集合上的五条件配对设计：

- S0：原始 baseline，无 system prompt；
- SC：中性 system prompt 对照组，仅说明角色和任务，不限制输出；
- S1：简洁回答，要求避免不必要的解释；
- S2：回答正确选项的字母；
- S3：严格只输出一个字符 A、B、C 或 D，不输出解释、标点或其他内容。

五组条件必须使用相同的 2000 个样本、相同的图像、相同的用户问题、相同的模型权重和相同的推理参数。每个样本在五个条件下均运行一次，总计 10000 条推理记录。

## 4. 实验前数据准备

### 4.1 数据源确认

在正式抽样前，确认数据集名称、版本、样本总量、图像可读性、题目字段、选项字段和参考答案字段。

当前已核查的 HRBench-4K 准备清单仅包含 800 条样本及对应图像，不能直接满足 2000 条实验规模。因此正式实验不得从这份 800 条清单重复抽样凑数，必须先取得至少 2000 条有效样本的完整数据清单，或重新确定数据范围。

### 4.2 样本抽样

完成数据源确认后：

1. 固定数据集版本和输入清单；
2. 使用明确记录的随机种子进行无放回随机抽样；
3. 抽取 2000 条样本；
4. 冻结样本 ID、图像路径、题目、选项、参考答案和类别信息；
5. 对样本清单计算校验值；
6. 五组实验全部读取同一份冻结清单。

抽样完成后不得因某组结果不理想而更换样本、删除样本或重新抽样。

### 4.3 图像准备

每条样本必须具备可读取的原始图像。图像准备阶段只进行路径解析、完整性检查和必要的格式转换，不改变视觉内容。

需要记录：图像文件名、图像尺寸、文件大小、读取状态和校验值。报告中的代表性案例使用可读、可放大的图像版本；原始图像和展示版本分别保留。

## 5. Prompt 固定

实验前固定并归档 S0、SC、S1、S2、S3 的完整 prompt 文本和版本标识。

S0 必须保持官方评测接口：不添加 system prompt，保留原始 user query。其余四组只增加相应的 system prompt，不同时改写 user query。

每组需要记录：

- system prompt 完整文本；
- 是否存在 system 消息；
- user query 完整文本；
- 图像输入顺序；
- chat template 设置；
- thinking 设置。

Prompt 一旦冻结，正式实验期间不得修改。任何 prompt 修改都必须产生新版本并重新进行完整实验。

## 6. 推理执行

所有条件使用同一模型权重和同一推理服务配置。除 system prompt 外，以下参数固定：

- 模型版本和权重校验值；
- 图像处理方式；
- user query；
- temperature、top-p、最大输出长度等解码参数；
- thinking 开关；
- 并发方式和重试规则；
- 输出保存格式。

每条输出必须保留原始文本，不在推理阶段截断、改写、清洗或只保存解析后的选项。

## 7. 数据分层与产物

实验产物分为四层，禁止用原始数据直接替代统计报告。

### 7.1 raw：原始证据层

保存不可变的实验输入和原始输出：

- 冻结样本清单；
- 原始图像及图像索引；
- 五组完整模型输出；
- 推理请求和响应元数据；
- 运行配置、模型版本和任务日志；
- 各文件校验值。

### 7.2 derived：派生分析层

由独立分析程序从 raw 层生成：

- 解析后的预测选项；
- 是否为有效 A/B/C/D 输出；
- 是否严格符合该组格式要求；
- 答案是否正确；
- 输出字符数和 Token 数量；
- 错误类型和异常类型；
- 每个样本在五组条件下的配对结果。

派生数据必须保留生成脚本、输入文件校验值和分析程序版本。

### 7.3 figures：图表层

从 derived 层生成论文式图表，至少包括：

- 五组准确率及置信区间图；
- 五组格式遵循率和有效选项率图；
- 输出长度分布图；
- 样本级条件间一致性或转移矩阵；
- 配对正确性变化图；
- 按题型或类别分层的准确率图（数据字段支持时）。

每张图都应标注样本数、统计单位、误差条含义和实验条件。

### 7.4 report：报告层

最终报告只呈现经过分析的结果：

- 实验问题和设计；
- 数据与样本构成；
- prompt 条件；
- 统计结果和图表；
- 代表性正确/错误案例；
- 原始输出片段作为证据；
- 局限性；
- 结论和后续决策。

完整原始输出保存在 raw 层；报告只嵌入能够解释结论的代表性样本，不把原始 JSONL 直接当作报告主体。

## 8. 统计分析

### 8.1 描述性统计

对每组计算：

- 准确率；
- 有效选项率；
- 严格格式遵循率；
- 平均、中位数和分位数输出长度；
- 空输出、异常输出和 API 错误数量；
- 各题型或类别的分层结果。

### 8.2 配对比较

由于五组使用同一批样本，主要比较采用样本级配对分析：

- 两组正确/错误结果使用 McNemar 检验或等价的配对二项检验；
- 准确率差异报告点估计和 bootstrap 置信区间；
- 输出长度等连续指标报告配对差异及其分布；
- 五组多重比较进行适当的多重比较校正。

统计结论必须同时报告效应大小、置信区间和样本量，不能只报告单一准确率。

### 8.3 结果解释

需要分别回答：

1. 加入中性 system prompt 是否本身改变性能；
2. 简洁性约束是否减少输出长度；
3. 要求输出选项字母是否影响准确率；
4. 严格单字符约束是否进一步提高格式稳定性；
5. 准确率变化是否集中在特定题型或视觉任务类别。

## 9. 可视化案例报告

报告中的代表性案例应至少包含：

- 原始图像；
- 题目和选项；
- 参考答案；
- 五组原始模型输出；
- 解析结果和正确性；
- 输出长度与格式状态。

案例选择规则应在分析前固定，例如覆盖：五组一致正确、S0 正确而 S3 错误、S0 错误而 S3 正确、格式失败但答案正确、各组输出长度差异明显等情形。

## 10. 结论门槛

若 S2 或 S3 在准确率没有实质性下降的情况下显著减少输出长度并提高格式遵循率，则说明短输出具有进一步研究价值。

若准确率下降，则必须结合配对错误样本和题型分层结果分析下降来源，不能仅依据总体均值下结论。

若 S3 无法稳定输出单个选项，则不能直接把单字符目标加入后续自蒸馏训练。

本报告不预先设定实验结论；结论必须由 raw、derived 和 figures 三层产物共同支持。

当前已完成实验流程规范化和原始评测接口核查。正式实验尚未开始。
