# G 作者归因与生成—验证模型解耦契约

**性质**：重点文档；在自然 G0/G1、正式 G 生产和 9B scale bridge 前，冻结 guide 作者、生成器、验证器与实验模型的耦合记录和可支持主张。

**创建时间**：2026-09-14 13:01（UTC+8）

**创建作者**：Codex (CINECA Leonardo)

**触发原因**：现行 T03 与 T05 均使用同一 Qwen3.5-9B checkpoint，仅 prompt/目录/run 隔离；未来 9B 实验模型又可能与 G 生成 checkpoint 相同。相同权重的一致性不构成独立验证，9B teacher gap 也可能包含模型对自己生成措辞的兼容性。人工语义审核能检查正确性，但未直接测量 guide 作者风格是否改变效果。

## 1. 四个角色必须分开记录

每条 G 及其结果至少记录：

| 角色 | 定义 | 最小 provenance |
|---|---|---|
| `guide_author` | 写出 latent graph/guide QA 的人、程序或模型 | author type、模型/人员匿名 ID、revision、prompt/code hash、时间 |
| `semantic_reviewer` | 独立检查答案、证据、依赖、泄漏与唯一性 | reviewer ID、是否看过原 guide、逐项判定、仲裁 |
| `auto_critic` / `independent_verifier` | 自动质量筛查 | model family、weights/revision、prompt、raw/parsed hash |
| `experimental_model` | 接收 S/V/T/VT 或被训练的模型 | 完整 asset inventory、processor/tokenizer、运行 commit |

角色名按事实填写。prompt、seed 或输出目录不同不能把同一权重变成独立模型。

## 2. “独立 verifier”的最低定义

只有同时满足以下条件才使用 `independent_verifier`：

1. 与 generator 不同权重；
2. revision 与资产 inventory 分别冻结；
3. verifier 不读取 generator 的 hidden thinking、自评分或 accept/reject 决定，只读取成品字段和原始视觉/问题证据；
4. verifier 选择和阈值在目标生产批结果可见前固定；
5. 在独立 `G_gold` 校准集上报告每类关键错误的 sensitivity/specificity 或 precision/recall，不只报告与 generator 的一致率。

最好使用不同模型家族；若只是同家族不同 checkpoint，必须写成“weight-independent, family-shared”。当前 T05 与 T03 同 checkpoint，因此现行准确名称是 `same-checkpoint auto_critic`，不能继续把它单独描述为独立质检证据。

若当前资源无法提供独立 verifier，允许使用“same-checkpoint critic → 程序门 → 1076 人类随机校准”的生产路线，但论文和数据卡必须披露。critic 的 auto-accept 只是抽样框，不是语义真值；1076 的人类质量区间和 prod/gold 效果保真门仍为训练前最终依据。

## 3. G1 同题作者敏感性子集

在 G1 条件输出可见前，从全部 G1 图簇按 P/R/PR、depth 和来源冻结：

\[
n_{author}=\max(32,\lceil0.10N_{G1}\rceil).
\]

每题建立两份语义目标一致的 `G_gold`：

- `G_model`：冻结 H generator 生成，按 1076 逐节点人工复做并签名；
- `G_human`：另一位人类作者只看完整图、final question 和冻结 evidence/answer contract，不能看 `G_model`、generator raw/self-score 或任何实验模型输出，独立写出 guide；之后由独立 reviewer 检查。

两份 guide 均不得泄漏 final answer，各自保留 T-Q/T-QA，并各配自己的逐题 tokenizer-matched Generic。不能强行把两份真实 G 改写成相同 token 数，因为那会改变作者文本；应报告节点数、token 数，并使用各自 generic 分离长度效应。

在同一 experimental checkpoint 上比较：

\[
Gap_{model}=LP(T_{model})-LP(Generic_{model}),
\]

\[
Gap_{human}=LP(T_{human})-LP(Generic_{human}),
\]

以及配对 `Gap_model-Gap_human`、accuracy flips 与 cluster bootstrap CI。该子集只做作者敏感性，不用于按单题效果挑选生产 G。

解释边界：

| 结果 | 解释 |
|---|---|
| 两种作者均有正 gap、差异小 | 信号对作者实现较稳健 |
| 只有 model-authored G 有效 | 存在 author/model-style affinity；主结论限于当前生产配方 |
| 只有 human-authored G 有效 | 自动 generator 没保留可消费结构；先修 G_prod |
| 两者均无效 | 当前任务/G 表示无可用自然信号；按 G0/G1 路由处理 |

## 4. 与 4B/9B scale bridge 的交叉

主 G0/G1 先用 4B，guide generator 为 9B，因此不是同一权重，但仍共享模型家族。1077 的 9B bridge 若使用与 H generator 相同的 checkpoint，必须在作者子集上同时报告 4B/9B 的 `Gap_model` 和 `Gap_human`：

- 若 9B 对 `G_model` 的增益明显高于 4B，而 `G_human` 无同向变化，不能把规模差异单独解释为更强推理能力；
- 若 4B/9B 对两类作者均同向，尺度迁移证据更强；
- 9B 正结果不能覆盖 4B 自然 Stop，也不能按 9B 的作者偏好换写 locked G。

若论文声称方法适用于一般 MLLM，而不是 Qwen3.5 当前配方，至少需要一个与 generator 不同家族的冻结 experimental checkpoint 做 inference-only 外部机制复核；否则主张明确限定为 Qwen3.5 family。第二家族的选择、资产和样本清单必须在其结果可见前冻结，且不能按其表现改写 G。

## 5. 审核独立性

`G_gold` 中“逐节点人工复做”要求 reviewer 自己根据图片、问题和父节点确认中间状态，不得只勾选 generator 的总分。作者敏感性子集的 human author 与 model-guide reviewer 不能是同一角色；至少一个 reviewer 对 guide author type 盲法。

对 `G_prod`：

- same-checkpoint critic、independent verifier 和 human audit 的结果分别存储，不能合并成一个 `verified=true`；
- 自动模型之间的一致不能替代 1076 至少 400/5% 人类 audit；
- independent verifier 若失败，只能在独立开发集调整；目标批修订后须开新版本并重新抽样；
- 实验 logits、teacher gap 和单题训练收益永不对 author/reviewer/verifier 开放。
