# B2a 草稿事务与导出一致性契约

**性质**：重点文档；在真实 B2a 人工输入前冻结界面内存状态、落盘 draft 与最终导出之间的一致性。

**创建时间**：2026-09-14 12:35（UTC+8）
**创建作者**：Codex (CINECA Leonardo)  
**触发原因**：C4 保存链内部审计发现 `_save_at_index` 先替换 `self.rows`，再调用原子文件写入。原子替换只能保证目标文件不出现半写状态；若临时文件写入、`fsync` 或 `os.replace` 失败，内存仍可能保留未落盘修改。随后 finalizer 使用内存行生成 accepted，却从旧 draft 读取 `reviewed_packet_sha256`，两者可能失去内容绑定。

---

## 1. 冻结不变量

1. 单条保存先在独立候选快照上应用人工 updates。
2. 候选快照完整写入同目录临时文件并完成 `flush`、`fsync`、`os.replace` 后，才允许替换进程内 `self.rows`。
3. 任一写入步骤失败时，内存行和既有 draft 必须同时保持保存前状态；错误返回人工，不得静默重试或标记成功。
4. 最终 32/32 导出前，必须用与 draft writer 相同的 canonical JSONL 序列化规则重算内存快照 SHA-256，并与实际 draft 文件 SHA-256 完全相同。
5. draft 缺失、内存与 draft 不一致或 draft 在导出过程中被外部修改时，finalizer 必须 fail-closed，且不创建 accepted/rejected/summary。
6. summary 的 `reviewed_packet_sha256` 只表示实际用于 accepted 内容的同一字节视图。

## 2. 验收

- 注入模拟写入异常后，API 保存失败，内存字段不变，旧 draft 字节不变。
- 直接篡改进程内 rows 后调用最终导出会拒绝，三个 final 文件均不存在。
- 正常 32 条完成稿仍可导出，summary hash 等于 draft hash，accepted 内容逐条等于 draft 行。
- 不修改冻结输入、人工语义门、B2a 路由或 0/32 当前状态。
