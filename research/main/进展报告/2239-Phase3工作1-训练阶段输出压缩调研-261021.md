## 1. 任务边界（本次调研的硬约束）

| 项 | 约束 |
|---|---|
| 训练阶段 | 必须通过训练改变模型（RL / SFT / 蒸馏 / 数据构造）；**排除**仅 system prompt、仅推理时截断/解码 |

| 框架 | 视觉域 On-Policy Self-Distillation（OPSD，自蒸馏） |
| 分级视角 | 不是"方法强不强"，而是"**迁移到视觉多模态 OPSD 的适配度**" |
| 初期策略 | 先定大方向，不抠单个方法的公式细节；广度优先，避免南辕北辙 |

**评测约束（来自 work5，必须继承）**：Vision-OPD 官方原生判别器不可用。work5 已证明：

- 官方原生口径只承认裸 `Yes`，准确率 53.5%，与人工 κ=0.492；
- 裁定终行/答案抽取口径均为 73.3%，与人工 κ=0.907 / 1.000；
- 裸 `Yes` 的裁判误判率是含推理输出的 **21 倍**（5.55% vs 0.26%）。

因此本项目的验证必须使用**答案抽取 + 带推理的独立裁判**，并按 work5 的做法报告口径分歧，不能直接引用 OPD-V 的原生判分。

## 3. 路线分类：三条信号 + 一个底座

本次调研把现有方法按**压缩信号作用的位置**归为三条机制路线，另加一个**训练底座**：

```
压缩信号（三条路线）
├── A. 奖励塑形：在 RL 奖励里惩罚长度/冗余
│      └─ 轨迹级 → 步级 → token 级（视觉信息增益）
├── B. 内容筛选：识别低语义密度内容，删掉后再训练
│      └─ 数据级（压 CoT 再 SFT）→ token/步骤级（重要性打分）
└── C. 预算/停止：训练模型按指定预算输出，或自己决定何时停
       └─ 控制 token → 预算条件化 → 自适应停止

训练底座（承载压缩信号）
└── D. 蒸馏信号：把压缩写进 teacher-student 的 on-policy 目标
       └─ 简洁教师 → 对比教师 advantage → 前缀截断 → 自蒸馏变体
```

**关键判断**：A/B/C 是"压缩信号"，D 是"把这些信号送进模型"的接口。对本项目而言，D 不是与 A/B/C 并列的第四条压缩方法，而是**必须适配的底座**——最终方案大概率是"某条信号 × D 的接口"。

导师在 A211 举的两个例子，正好落在 A（长度惩罚）与 B（低语义密度识别）。调研确认这两条路线都成立，且各自已经演化出多个子类；但真正与 OPSD 原生兼容的是 D，因此最终方案不能只做 A 或 B 的孤立复现。

## 4. 路线详解

### 4.1 路线 A：奖励塑形 / 长度惩罚

**机制**：在 RL（GRPO/DAPO/PPO）目标中加入长度项，或把长度作为预算约束。演进方向是"从轨迹级粗惩罚，走向步级、难度自适应、视觉信息密度"。

- 静态长度惩罚必须与正确性/训练时机耦合，否则奖励"短而错"。O1-Pruner、LASER、Short-RL、ConciseR 都用了门控；反例是固定惩罚在训练后期长度崩溃。
- 自适应/难度调制（ALP、LASER-D、Leash、CARE）给出最好的 Pareto，但需要在线 rollout 统计；对 4B/9B VLM 的多 rollout 成本明显高于 1.5B 文本模型。
- **VIG 是本路线对项目最有价值的发现**：它把"每个推理 token 是否真的依赖图像"变成逐 token 奖励（有图/无图两次前向的熵差），无需外部奖励模型。这与 OPSD 的 token 级蒸馏接口天然同构，是我们最应该借鉴的信号。
- 视觉证据仍薄：Route A 的多模态工作集中在 2B–8B，**没有 9B，也没有 OPSD**。

### 4.2 路线 B：低语义密度内容识别与剔除

**机制**：先识别"水词、重复、自验证、与图像无关的描述"，再通过数据构造或 token/步骤级筛选把模型训短。分两条实现路径：

- **B1 数据级**：把长 CoT 压缩成短 CoT，再 SFT/DPO；
- **B2 token/步骤级**：在当前轨迹上按重要性、熵、信息增益筛选。

**代表工作**：

**路线判断**：

- 数据级方法便宜、可直接把压缩轨迹喂给 OPSD 做 warm start，但会把 teacher 的省略偏置固化，且静态数据与 student 的 on-policy 分布有偏移。
- token/步骤级更贴 OPSD，但依赖重要性估计，容易 reward hacking。
- **多模态第一障碍不是长度，而是视觉 grounding**：纯文本 LLMLingua-2 会删掉"文本低熵但视觉高信息"的 token（物体属性、空间关系、指代）。VLM 的重要性分数必须加入 image attention / visual-text alignment / grounding consistency，压缩后必须测 CHAIR/POPE/AMBER，不能只看数学准确率。
- 安全压缩区间大致 30–50%；>60% 在 7B 以下明显更脆弱。4B/9B 应从 20–30% 起步、按难度分层。
- **伪简洁（pseudo-conciseness）**：token 数下降不等于冗余下降，步骤可能反而变多（ChainPrune）。评估必须同时看 token、step、grounding。

**机制**：训练模型"按预算输出"或"自己决定何时停"。这是与 OPSD rollout 最兼容的一类，因为可以在学生前缀/控制 token 上直接施加预算。

**代表工作**：

**路线判断**：

- 预算条件化是**唯一能直接嵌入 OPSD rollout** 的路线：控制 token、prompt 预算、前缀截断都只改变学生 rollout 的 prefix，教师可在同一 prefix + 特权信息下给 token 分布。
- 现有工作只给"序列级"结果奖励，没有监督"停止动作"本身；OPSD 的稠密 token 信号恰好可以补这个缺口。
- 最大风险是**停止边界的教师可靠性**：教师看到答案后可能过度自信，停止点恰恰是"教师最不可靠"的位置。需要 branch-viability/teachability 过滤。
- VLM 证据薄，且"越短越好"不成立：ARES 在 AIME25/OlympiadBench 上反而变长；视觉感知失败比推理失败更常见。

**机制**：把压缩写进 teacher-student 的 on-policy 目标。这是本项目真正要落地的接口。

**路线判断（最重要）**：

1. **"压缩进 OPSD"已有先例，但都是间接的**：CRISP/BIRD 写进教师条件；COPD/COPSD 写进 token advantage；TRSD 写进前缀构造。**没有任何工作把显式长度项/预算违背惩罚直接加进 OPSD loss。**
2. **OPD-V 已经证明 OPSD 本身就能大幅压缩**（−74.5%），但不可控。这意味着"压缩"本身不是新意；**可控性 + 视觉条件**才是。
3. **COPD 是最危险的撞车对象**：同 OPSD 接口、同 4B/9B 规模、已有 −79%/+0.6pp 的强结果；但它用文本轻/重思考提示作对比信号，不做视觉证据条件化，也明确不做预算控制。
4. **VLM 4B/9B 的"预算可控 + 视觉条件 + OPSD"三元交叉仍是空白**（截至 2026-10-21，未见已录用论文）。

## 5. 适配度分级

### 5.1 评分标准（每维 0–2 分，总分 12）

| 维度 | 2 分 | 1 分 | 0 分 |
|---|---|---|---|
| D1 视觉原生性 | VLM + 视觉信号 | VLM 但纯文本信号 | 纯文本 |
| D2 OPSD 兼容性 | token 级 on-policy teacher-student | 可改造/可作 warm start | 架构不兼容 |
| D3 信号成本 | 无额外模型/标注 | 一次额外前向或奖励模型 | 人工/GT 重 |
| D4 4B/9B 证据 | 已在 4B/9B 验证 | 3B–8B | 仅 1.5B 或 ≥14B |
| D5 压缩-准确率证据 | ≥40% 且 ≤2pp 损失/有提升 | 20–40% 或损失较大 | 证据弱 |
| D6 CVPR 适配 | 视觉会议已录用/清晰视觉故事 | 邻近 | 纯 NLP |

**级别**：A ≥9（优先验证）；B 6–8（备选/部件）；C ≤5（仅机理参考）。

## 6. 关键发现（7 条）

1. **视觉信号是分水岭。** 纯文本长度惩罚（L1、LASER、SwAP）在多模态上会删掉视觉关键 token；VIG、GRACE、C3PO、OPD-V 都把视觉证据纳入压缩信号，是更适配的方向。
2. **预算可控性是最空的轴。** COPD 明确回避固定预算，OPD-V 没有预算旋钮，CRISP/BIRD 也没有预算；L1/BudgetThinker 有预算但纯文本/1.5B。**"预算可控 + 视觉条件 + OPSD"尚未被占据。**
3. **OPSD 本身已经能压缩。** OPD-V 在 4B 上把响应从 553.8 降到 140.9（−74.5%），准确率反而升到 80.01。任何以"压缩"为唯一卖点的方案都会被问：为什么不直接用 OPD-V？
4. **压缩不等于去冗余。** ChainPrune 的"伪简洁"现象说明 token 数下降可能只是把步骤写得更短，冗余路径仍在；必须同时报告 step 数与推理结构。
5. **小模型证据薄。** 大多数方法在 1.5B/7B/8B 上验证；4B/9B VLM + OPSD 的组合几乎没有；9B 更是空白。
6. **训练时压缩不保证推理时省。** "When Compression Helps and When It Hurts"（2606.21704）指出训练时压缩不必然转化为推理时节省，Long-CoT 学生仍可能保留啰嗦习惯；评估必须在 student 采样上统计真实输出长度。
7. **CVPR 2026 已形成集群。** VideoAuto-R1、ReaGEN、Fuel Gauge、Revisiting Lengthy CoT、Tiny-R1V、VOLD 等已在视觉会议占位；CVPR 2027 审稿人默认知道这条线，必须正面比较。

## 7. 撞车风险与 novelty 评估

### 7.1 三元交叉矩阵

| 能力 | COPD | OPD-V | VIG | CRISP/BIRD | VideoAuto-R1 | 本项目目标 |
|---|---|---|---|---|---|---|
| OPSD 原生接口 | ✓ | ✓ | ✗（RL） | ✓ | ✗（GRPO） | ✓ |
| 视觉证据条件化 | ✗（文本提示） | ✓（zoom/mask） | ✓（视觉信息增益） | ✗ | ✓ | ✓ |
| 显式预算可控 | ✗ | ✗ | ✗ | ✗ | ✗（置信早退） | ✓ |
| 4B/9B VLM | ✓（2B 学生为主） | ✓ | 2/4/8B | ✗（文本） | 视频 | ✓ |

**结论**：三个二元交叉都已被占：

- OPSD × 输出压缩 = **COPD/COPSD**（预印本）；
- 视觉条件 × OPSD = **OPD-V / Vision-OPD / Where-OPD / VAG**（预印本为主）；
- 视觉会议 × 输出压缩 = **VideoAuto-R1 / Tiny-R1V / ReaGEN**（CVPR 2026）。

**未被同行评议占据的只有三元组：显式预算可控 + 视觉证据条件化 + OPSD。**

### 7.2 novelty 判断

- 仍有空间，但**很窄**；不能把"视觉条件"单独当主卖点（OPD-V 已占），也不能把"压缩"单独当卖点（COPD/OPD-V 已占）。
- 可防守的叙事：**OPSD 提供稠密 token 级监督，无需 verifier/奖励模型，因此能以远低于 RL 的成本实现"按视觉证据分配预算"的输出压缩；同一模型在多个预算下画 accuracy–token Pareto，并用 mask/zoom 反事实证明预算分配随视觉证据变化。**
- 最大 scoop 风险：COPD 作者若在下一版加入视觉条件或预算控制，我们的空间会被压缩。需尽快做小规模验证并锁定差异化。

## 8. 候选方案（供决策）

### S1（推荐）：预算条件化的视觉 OPSD

- **机制**：学生输入含预算控制 token（如 `<budget=0.5>`）；教师输入同一预算 + 特权答案/zoom 图；蒸馏 loss 只在预算内 token 上生效；用 VIG 式视觉信息增益加权 token 选择。
- **新意**：单一模型、推理时可调预算、视觉证据驱动；同时覆盖 COPD（无预算、无视觉）与 OPD-V（无预算、压缩不可控）的空白。
- **风险**：预算控制 token 需要额外训练；教师对停止边界的可靠性；实现复杂。
- **成本**：中高（改数据模板 + loss + rollout）。

### S2：视觉信息增益驱动的 OPSD token 选择

- **机制**：用"有图/无图"两次前向的熵差给每个 token 打分；在 OPD-V 的 Modality-Balance Trust Region 上再乘一个视觉信息增益权重；低增益 token 降权或跳过。
- **新意**：把 VIG 的信号引入 OPSD，不需要预算 token；实现最简单。
- **风险**：与 OPD-V + VIG 的组合较直接，novelty 偏弱；压缩幅度不可控；需要证明不是简单加权。
- **成本**：低（只改 token 权重）。

### S3：数据级压缩 warm start + OPSD

- **机制**：用 GRACE/TokenSkip 式方法构造压缩 CoT，做 SFT warm start，再做 OPSD；用 BIRD 的正确性过滤避免噪声前缀。
- **新意**：工程稳妥，适合快速出结果；novelty 最低。
- **风险**：容易被审稿人视为 BIRD/GRACE 的 VLM 复现。
- **成本**：低（数据构造 + 现有 OPSD 流程）。

**建议**：先做 S2 作为**诊断实验**（1 周内可完成，验证视觉信息增益与冗余的相关性），再用 S1 作为**主方法**；S3 作为 fallback/消融。
