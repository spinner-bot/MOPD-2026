## 2. 发现的接口断裂

### 2.1 模型审计允许伪 R 图

旧 `minimal_reasoning_graph` 校验只检查三类节点和边端点，仍会接受：单一 evidence、重复节点 ID、环路、无用孤立证据、多个 answer、声明 depth 与真实最长路径不一致。更严重的是 audit prompt 自带的 R 示例只有一个 evidence 节点，与“至少两个不同视觉证据共同进入必要链”的协议矛盾。

这会把“单点识别 + 文本改写”误标为 R，从数据入口系统性抬高文本特权看似有效的机会，直接损害 effect-first pilot 的可解释性。

### 2.2 空白审核包不可能通过终检

旧 C2 模板只有 10 个 `human_*` 字段，缺少终检已经要求的：

- `human_answer_leakage`；
- `human_external_fact_injected`；
- `human_reviewer`；
- `human_reviewed_at`；
- 新协议必要的 `human_reasoning_depth`。

旧审核指南又要求填写 `none/some/heavy`、`yes/no/ambiguous` 和自由文本推理图，而终检要求 `image_only`、真正 JSON 布尔值和结构化图。按旧指南完成的记录会被程序全部拒绝。

### 2.3 缺少“构造产物 → 人工审核”接口

旧 C2 表只含候选原问题，没有合并 W2B 生成的 guides、选项、blind/audit 判定和构造 provenance。人工审核者无法在同一记录中审查实际要进入 T-Q/T-QA 的特权内容；模型链即使成功也不能形成可操作的 100% 人工终审队列。

### 2.4 结果 provenance 只记录、不校验

W3 runner 已记录 chat-template、generation config、choice token 和 rank，但旧结果 gate 没有验证它们。它也没有把 `source_cluster_id` 传入结果和 bootstrap。若条件间 thinking、解码约束或 choice token 漂移，旧 gate 仍可能放行，不能充分支撑“唯一变化是 privileged context”的因果主张。

## 3. 已完成修复

### 3.1 单一推理图权威契约

新增 `code/data_pipeline/reasoning_graph_contract.py`，并同时接入机器 audit、人工终检和 locked manifest 校验。当前要求：

- 唯一 answer、至少一个 intermediate、至少两个 evidence；
- 节点 ID 唯一，边端点合法且无自环/重边；
- evidence 为根、answer 为汇点，图为 DAG；
- 所有节点都位于通向 answer 的祖先子图；
- answer 路径至少使用两个 evidence；
- 声明 depth 等于 evidence 到 answer 的最长边数。

audit prompt 的示例同步改为 `e1,e2 → h1 → a`。

### 3.2 人工字段和指南统一

C2 输出版本升为 `c2-v2`，空白模板补齐 15 个终检字段。`teacher_gap_review_guide.md` 已改写为精确 JSON 类型与取值规范，并明确旧 C2 表不可直接冻结、模型提议不能自动写为人工真值。

最终清单现在保留人工确认的 `reasoning_depth`，locked manifest 会再次用同一图契约核验。任何单证据、无用节点或 depth 不一致样本均 fail-closed。

冻结器还要求 constructed 的候选 ID 非空且唯一，外层 candidate/source-image ID 必须与内层记录一致，人工审核时间必须是带时区的 ISO 8601。最终 manifest 显式保留 `unique_answer=true` 与 `external_fact_injected=0`，不再只依赖笼统的 `human_verified` 标志。

### 3.3 完整人工审核队列

新增 `build_teacher_gap_human_review_queue.py`：读取 W2B 的 parsed construct 记录，再次验证 candidate、blind、audit 和 construct 四层契约，仅将 `accept_candidate` 写入队列。输出同时包含完整机器提议、模型 provenance 与全部空白人工字段，并通过 allow-list 排除 M3VQA 官方 evidence 正文和 URL。

输出状态固定为 `machine_candidate_pending_independent_human_review`，汇总固定记录 `automatically_human_verified=0`。

队列构建与最终冻结还会检查 `guides[].supports_next`：目标必须是人工确认图中存在的 intermediate/answer 节点，且整组 guides 至少支持一个 intermediate。模型写出的悬空节点名或只指回原始 evidence 的伪链不能进入冻结集。

### 3.4 冻结结果门控

W3/W4 raw record 新增 `source_cluster_id`。结果 gate 现在要求：

- 4 GPU world size、rank 与冻结 schedule 分片一致；
- schedule index 完整覆盖且无重复；
- chat template 明确 `enable_thinking=false`；
- greedy、A/B/C/D 受限生成配置一致；
- choice token 序列四项非空、互异且所有记录一致；
- model dtype、model/processor revision、code commit、shell hash 全局一致；
- 每个样本的 source image/cluster、图片、问题、选项哈希跨条件一致；
- 同一样本四个条件的 prompt hash 均非空且互异。

bootstrap 改用冻结清单中的 `source_cluster_id`，不再把源图 ID 暂代为近重复簇。
