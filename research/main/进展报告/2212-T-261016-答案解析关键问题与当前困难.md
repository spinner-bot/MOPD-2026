# 2212-T：全量答案解析的关键问题与当前困难

**记录时间：** 2026-10-16（Asia/Shanghai）  
**记录来源：** 本地工作树中的项目记录，以及 Leonardo 服务器工作仓库、Slurm 队列和工作5数据区的只读核验。  
**触发原因：** 说明当前工作5为何尚未进入统计阶段、已发生的问题及尚存困难，明确后续判断依据。

## 一、结论摘要

当前的核心问题不是“所有评测作业都失败”，而是：工作5生成的全量模型输出，需要再经本地大模型解析为可统计的选项答案；解析器还须为答案提供可在原始回答中核验的证据。历史尝试中，部分解析虽给出了正确选项，却因证据不是原回答的逐字片段而被完整性门禁拒收；另有中文选项标签识别遗漏，可能使有效答案被误判为无效。

此前发现的 Python 头文件缺失已在服务器脚本中修复。随后修复了两类解析校验问题，并通过针对性测试；但截至本次核验，30个条件×评测集分片中仍有10个未通过逐样本门禁，相关重试正在运行，自动管理器等待重试数组结束。因此答案解析阶段尚未验收，统一统计尚未启动。当前尚不能据此报告全量5S准确率或比较结论。

## 二、工作5的数据规模与处理链

工作5覆盖5种输入条件（S0、SC、S1、S2、S3）与6个评测集，共30个分片。六个评测集的样本数分别为：V* 191、ZoomBench 845、HRBench-4K 800、HRBench-8K 800、MME-RealWorld 23,609、MME-RealWorld-CN 5,917；合计每轮32,162条，五种条件共160,810条条件—样本记录。

本阶段需要区分三个层次：

1. **实验输出生成：** 按Vision-OPD评测流程，在各评测集和条件下生成模型回答及原生评分。
2. **答案解析：** 使用本地大模型从回答中判定选项，并保存模型原始判别输出、解析答案、证据及状态；既有规则判别结果保留，不能被覆盖。
3. **质量门禁与统计：** 每个分片须覆盖预期的全部唯一样本，且每个样本最新一次解析状态均为 `OK`。全部分片通过后，才适合统一汇总与分层统计。

因此，Slurm任务退出成功只代表进程正常结束，不等于解析结果已完整、可用；输出文件存在也不等于样本解析正确或通过校验。

## 三、已确认的问题及处理

### 3.1 模型初始化时缺少 Python 开发头文件

较早的答案解析数组多次以非零退出码结束。日志定位到 vLLM 检查模型架构时，Triton/GCC 编译辅助代码无法找到 `Python.h`：脚本引用的系统目录 `/usr/include/python3.11` 并不包含该头文件。服务器提供的 Python 3.11.7 模块带有开发头文件，但实际头文件位于模块自己的 `include/python3.11` 子目录；仅加载模块未自动使该目录进入 GCC 搜索路径。

服务器脚本随后加载该 Python 模块，并将正确头文件目录加入 `CPATH`。修复提交为 `5a707b3` 与 `2cf88ca`。修复后的运行日志记录了代码版本 `2cf88ca`，模型权重已加载并完成Triton预热，未再出现此前的 `Python.h` 错误。此项修复证明任务越过了初始化故障点，不代表整批解析已经完成。

### 3.2 “作业成功”与“分片通过”并不等价

解析输出以追加方式保存多次尝试。门禁按照 `sample_uid` 取每个样本最新一条记录，并要求唯一样本数达到该评测集预期数量、所有最新状态均为 `OK`。所以历史无效尝试仍留在文件中，但若样本后来得到有效的最新结果，不会单凭历史错误阻断门禁；反之，分片进程即使以 `COMPLETED/0:0` 结束，只要最新记录仍有无效状态，该分片就不能通过。

此前 S0/MME-RealWorld 的一个检查实例中，文件有23,894行历史尝试，但只有23,609个唯一样本；最新记录中23,572条为 `OK`、37条为 `INVALID_JUDGE_JSON`。这说明必须以逐样本最新状态和门禁为准，不能用原始行数或Slurm终态代替数据验收。

### 3.3 逐字证据校验与判别模型的表述差异

解析器要求大模型给出的证据能够在原回答中找到，以防仅凭选项字母或不受约束的解释接受结果。实际回答有时用Markdown强调答案，例如原文出现 `**(C)**`，判别器引用时却输出 `(C)`；语义相同但字符串不完全相同，严格子串校验会拒收该记录。

针对仅由Markdown标记造成的表面差异，已实现规范化匹配：校验时移除相关Markdown标记进行比对，同时保留判别器原始输出，并将证据校验方式标记为 `exact_substring_markdown_normalized`。这只处理格式差异，不放宽语义证据要求；真正无法对应原文的解释仍应拒收。相关代码包含测试，确保语义不匹配不会因格式规范化而被误接纳。

### 3.4 中文选项标签未被原有解析器完整识别

原有选项标签发现逻辑偏向ASCII字母A—F。在 MME-RealWorld-CN 中，题目可能使用中文序号，例如首项为“（一）”。若解析器只发现后续的B、C、D、E，判别模型给出正确的A也可能被当作不在可用标签集合内。

现有修复将原题解析出的选项标签纳入校验，并把中文序号与规范选项标签对应；不更改冻结的实验输入。修复还保留判别器原始输出。服务器上的定向测试为8项通过，工作5完整测试集为24项通过。这些测试证明对应代码路径符合设计用例，不能替代对全部160,810条记录的逐条完成门禁。

## 五、当前核心困难

1. **全量规模使尾部错误决定能否开统。** 30个分片中任何一个样本最新解析无效，都会使其所在分片不通过；总体覆盖大并不自动消除少量尾部失败。
2. **解析质量不仅是选项正确性。** 还必须同时满足输出结构、选项标签合法、证据可验证、唯一样本覆盖完整等要求。单看模型回答或部分样例无法证明数据可用于统计。
3. **历史重试记录增加审计复杂度。** JSONL追加保留历史尝试，必须正确按样本取最新记录；误用总行数会高估覆盖或重复计数。
4. **各评测集输入格式不同。** 特别是中文选项符号与文本布局差异，使单一ASCII规则不适用于全部评测集。任何格式兼容修复都必须避免改写冻结输入、误认选项或放宽证据标准。
5. **自动管理器是依赖式流程。** 当前管理器等待重试数组结束。即使任务已在队列中运行，后续是否能自动补齐仍需核实管理器实际日志、门禁结果和最终队列状态，不能只凭依赖设置推定成功。
6. **当前不能进行可信的完整统计。** 在门禁未通过前，缺失或无效判别可能造成分母不一致、条件间样本不配对及评测集比例偏差。此时汇总准确率会混合数据缺口与模型表现，不能当作全量结论。

## 六、后续验收路径

1. 等待数组 `60673459` 自然结束，保留其全部日志和历史输出，不覆盖原始实验输入及旧判别记录。
2. 重新运行工作5答案解析门禁，记录每个分片的唯一样本数、最新状态计数及缺失ID。
3. 对仍未通过的样本逐类检查原始回答、判别器原始输出、选项标签、证据及状态；区分结构错误、标签映射错误、证据格式差异、语义证据不成立及其他异常。只有有证据支持的原因才作归类。
4. 若需再次修复或重试，明确记录代码版本和判别尝试，不删除、不覆盖既有规则结果或模型原始输出；严格保持证据与标签校验边界。
5. 当30个分片全部满足唯一样本覆盖及最新状态 `OK` 的门禁后，才确认答案解析可进入统一统计。统计阶段应同时核对原生评分与LLM答案解析两条结果链，并按条件、评测集及其类别分层。
