## 1. 最直接的撞车：H-OPD（EMNLP 2026）

**H-OPD: Confidence Aware Heterogeneous Multi-Teacher Multimodal On-policy Distillation**
arXiv 2607.02592，EMNLP 2026（arXiv comment 明确标注已录用），代码已开源。

它的做法是：

- **一个学生、两个教师**：一个视觉语言（VL）教师看原图；一个纯文本教师看"问题 + 图像描述"（通过 vision-to-language description transfer 把图像内容转成文本）；
- 两个教师在**同一个学生生成的 prefix** 上打分；
- 按**预测熵**计算每个教师的置信度，做 **token 级仲裁**（λ_t 加权融合），在统一候选集上做 KL；
- 目标是**多模态推理提升**，在 11 个基准上评估。

也就是说，"一个学生两个教师 + token 级仲裁"这个架构，H-OPD 已经做了，而且是正式录用，不是预印本。

**它和您的设想的差别只有一个**：H-OPD 的文本教师是"图像描述教师"，不是"简洁教师"；它不压输出长度。

## 3. 还剩下什么缝隙

我**没有直接检索到**"视觉特权教师 + 简洁教师 + 输出压缩"这个具体组合。但它本质上是三篇已有工作的交叉：

- H-OPD 提供双教师架构和 token 级仲裁；
- CRISP 提供简洁教师；
- COPD 提供 OPSD 压缩信号。

如果只是把三者拼起来，审稿人很可能说"这是 H-OPD + CRISP"，创新性不够。要让它成立，必须有一个**新的机制**或**新的受控证据**。我能想到的两个：

### 方向 A：视觉证据门控的压缩仲裁（我倾向这个）

- 两个教师：视觉教师（zoom/mask）+ 简洁教师（be concise）；
- 仲裁不按"教师置信度"，而按"**这个 token 是否依赖视觉证据**"：
  - 视觉信息增益高的 token（物体属性、空间关系、OCR 结果）**保护起来，不压**；
  - 视觉信息增益低的 token（重复描述、自验证、套话）**交给简洁教师压**；
- 这样既利用了 OPD-V 的视觉教师，也利用了 VIG（视觉信息增益）的逐 token 信号，和您的双教师故事一致；
- 可检验的假设：单教师同时加两种特权，会在"视觉 token 该保留 vs. 简洁教师想删"上冲突；双教师 + 视觉门控能同时降 token、保 grounding。

### 方向 B：冲突的受控诊断

- 把"同一教师叠加两种特权"作为对照，量化冲突（长度、准确率、视觉 grounding）；
- 贡献是诊断和机制，但如果没有明显冲突，故事立不住。

### 方向 C：换题

- 放弃双教师，回到工作1调研里的其他缝隙（例如预算可控、评测口径、视觉 grounding 指标）；
- 但您之前已经判断纯压缩太薄，我不确定这条更好。

## 4. 我的建议：先做一个便宜的决定性实验

在投入代码之前，先花 1–2 天做一个小对照（4B、小数据、不追求 SOTA）：

1. **单教师 + 两种特权**（视觉 zoom/mask + "be concise" 指令同时给教师）；
2. **双教师**（视觉教师 + 简洁教师，按您的设想仲裁）；
3. **单教师 + 只有简洁教师**（CRISP 式）；
4. **基线**（标准 OPSD / OPD-V）。

看三件事：输出 token 长度、准确率、视觉 grounding（CHAIR/POPE 至少一个）。

- 如果单教师确实冲突、双教师确实更好，方向 A 的故事就成立，可以继续；
- 如果单教师不冲突，说明"双教师"的必要性不成立，应尽早停，避免写完代码才发现。

这个实验不需要大算力，但需要 GPU。目前服务器配额情况我还没查清（`squeue` 没有运行任务，账号 `aifac_f02_774` 没有显示显式 GPU 上限），可能需要您帮忙确认哪个额度可以用。
