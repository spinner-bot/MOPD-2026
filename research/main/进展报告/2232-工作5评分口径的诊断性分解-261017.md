# 2232-工作5 评分口径的诊断性分解

**性质**：重点文档；对工作5 三种评分来源给出可核验的分解，修正对"提示强度效果"的解释。

**创建时间**：2026-10-17 01:19（UTC+8）  
**创建作者**：Claude Code (local)  
**触发原因**：v4 统计报告（`full-five-condition-benchmark-report-v4.html`）完成了各条件的数值与配对检验，但未诊断三条评分来源是否在测量同一事物。复核其分层表与两份审计 CSV 后，发现官方分数与真实判定之间存在可精确分解的结构性差异。本文给出该分解、机制与边界。

---

## 1. 摘要

工作5 的三个评分来源在 S0→S3 对比上给出**方向相反**的估计：官方原生 **+10.68 pp**、裁判终行诊断 **−2.56 pp**、Qwen 答案抽取 **−0.97 pp**（均 p<1e-40）。

本文证明这不是估计噪声，而是**可精确分解的口径差异**：

> **官方原生 = 判官判定为对 × 判官输出格式合规**

其中"格式合规"指 Vision-OPD 原规则要求判官原始字段去除首尾空白后**严格等于 `Yes`**。六评测集的分解满足恒等式

```
Δ官方 + Δ丢弃 = Δ判定          （逐条精确成立，无例外）
```

**结论**：官方分数的"提升"全部来自**找回原本被该格式规则丢弃的正确结果**；按不依赖输出格式的两条链，真实正确数在 S3 下**全部下降**。

## 2. 数据与口径

| 项 | 内容 |
|---|---|
| 样本 | 六评测集 × 五条件，每格 32,162 条，合计 160,810 条件—样本记录 |
| 来源 | `derived/full-statistics-v4/` 下 `native_judge_format_audit.csv`、`native_judge_decision_audit.csv`、`stratified` 分层表 |
| 官方原生 | Vision-OPD `cal_acc.py` 口径：判官原始字段去空白后严格等于 `Yes` 才计为正确 |
| 终行诊断 | 仅读判官输出最后一行的精确 Yes/No（诊断性解析，非官方口径） |
| 答案抽取 | Qwen3.8-27B 文本抽取，独立于判官 |

三者对**同一批模型输出**作答，模型输出不因评分来源而改变。

## 3. 核心发现：官方分数等于格式合规数

`native_judge_format_audit.csv` 逐条件×评测集给出 `yes` 与 `non_binary` 计数。**官方准确率恒等于 `yes/(yes+non_binary)`**，验算：

| 评测集 | S0 官方 | S3 官方 | Δ |
|---|---:|---:|---:|
| hrbench-4k | 532/800 = 66.50% | 655/800 = 81.88% | **+123 条** |
| hrbench-8k | 506/800 = 63.25% | 620/800 = 77.50% | +114 |
| mme-realworld | 10,469/23,609 = 44.34% | 13,250/23,609 = 56.12% | +2,781 |
| mme-realworld-cn | 3,477/5,917 = 58.76% | 3,897/5,917 = 65.86% | +420 |
| vstar | 171/191 = 89.53% | 169/191 = 88.48% | −2 |
| **zoombench** | **0/845 = 0.00%** | **0/845 = 0.00%** | **0** |

上述 Δ 与 v4 分层表的官方逐评测集效应**逐个吻合**（如 hrbench-4k 的 +15.38 pp = 123/800）。

> **全量 160,810 条中有 74,720 条（46.5%）判官原始输出为非二元文本**（含推理后再给结论），按该规则**一律计为不正确**。

## 4. 精确分解

以终行诊断作为"判官实际判定"的代理，定义**丢弃量** = 判官判对但被格式规则计为错的条数：

| 评测集 | 判对 S0 | 判对 S3 | Δ判定 | 官方 S0 | 官方 S3 | Δ官方 | 丢弃 S0 | 丢弃 S3 | Δ丢弃 |
|---|---:|---:|---:|---:|---:|---:|---:|---:|---:|
| vstar | 173 | 170 | −3 | 171 | 169 | −2 | 2 | 1 | −1 |
| zoombench | 517 | 489 | −28 | 0 | 0 | 0 | 517 | 489 | −28 |
| hrbench-4k | 677 | 669 | −8 | 532 | 655 | +123 | 145 | 14 | −131 |
| hrbench-8k | 649 | 637 | −12 | 506 | 620 | +114 | 143 | 17 | −126 |
| mme-realworld | 17,755 | 17,212 | −543 | 10,469 | 13,250 | +2,781 | 7,286 | 3,962 | −3,324 |
| mme-realworld-cn | 4,237 | 4,009 | −228 | 3,477 | 3,897 | +420 | 760 | 112 | −648 |

**恒等式检验**（六行全部成立）：

```
hrbench-4k     : +123 + (−131) = −8    = Δ判定 ✓
hrbench-8k     : +114 + (−126) = −12   = Δ判定 ✓
mme-realworld  : +2781 + (−3324) = −543 = Δ判定 ✓
mme-realworld-cn: +420 + (−648) = −228 = Δ判定 ✓
zoombench      : 0 + (−28) = −28        = Δ判定 ✓
vstar          : −2 + (−1) = −3         = Δ判定 ✓
```

这不是统计估计，而是**算术恒等式**。

## 5. 机制

短输出使判官更容易只输出裸 `Yes`，从而提高格式合规率。

| 条件 | 输出 token 均值 | 官方 | 终行诊断 | 抽取 | 官方与抽取一致率 |
|---|---:|---:|---:|---:|---:|
| S0 | 336.9 | 47.1% | 74.6% | 70.8% | 68.6% |
| SC | 369.4 | 50.0% | 73.9% | 70.3% | 72.6% |
| S1 | 306.1 | 56.9% | 72.7% | 70.1% | 81.7% |
| S2 | 331.4 | 55.9% | 73.0% | 70.3% | 80.4% |
| S3 | 260.3 | 57.8% | 72.1% | 69.8% | 83.6% |

- 输出长度自 S0 的 336.9 降至 S3 的 260.3（**−22.7%**）
- 官方分数与输出长度**反向**变化；两条不依赖输出格式的链**同向微降**
- 官方与抽取的一致率自 68.6% 升至 83.6%——**分歧本身在系统性收窄**，与"格式合规率上升"一致

## 6. zoombench：同一问题的极端形态

zoombench 的官方分数在**全部五个条件下恒为 0.00%**（845/845 判官输出均为非二元），而终行诊断给出 57.9%–61.2% 的判对率。

**该评测集的官方分数不可用于任何比较**；其 0% 是评分路径与输出格式不兼容的产物，不是模型表现。

## 7. 对既有结论的影响

| 说法 | 判定 | 依据 |
|---|---|---|
| S3 使输出**更易被解析** | ✅ 成立 | 格式合规率自 63.1% 升至 80.2% |
| S3 提升官方原生分数 +10.68 pp | ✅ 数值成立 | 但**不可解释为正确率提升** |
| **S3 提升答题正确率** | ❌ **不成立** | 终行诊断 −2.56 pp、抽取 −0.97 pp，方向相反 |
| 两链之间高度一致 | ✅ 成立 | 一致率 96.1%–97.7% |
| 官方与两链一致 | ❌ 不成立 | 与抽取一致率仅 68.6%–83.6% |

**v4 报告已就此写入边界声明**（"不能把官方分数的变化自动解释为语义答题准确率变化"），但未量化分解；本文补齐该量化。

## 8. 方法学边界

1. **终行诊断不是金标准**。它是对判官输出的另一种解析，与被审计的官方口径同源。本分解依赖"终行解析能正确读出判官结论"这一假设。
2. **待验证**：上述分解隐含"非二元输出的结论多为 Yes"。抽样核对非二元记录的实际结论分布即可实证或否证，**该核对尚未执行**。
3. **不构成因果结论**。长度与格式合规的关联为描述性。
4. **zoombench 的 0% 未经独立确认**为管线故障；本文依据其判官输出 100% 非二元这一事实推断。
