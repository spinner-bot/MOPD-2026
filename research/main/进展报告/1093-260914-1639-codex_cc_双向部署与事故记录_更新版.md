# 6. 废弃分支为什么必须保留

这些分支虽然已经废弃，但项目明确采用“完整留痕”原则。

因此：

```text
deprecated ≠ deleted
```

分支的“废弃”只表示：

> 不再作为当前工作路线继续开发。

并不表示：

> 从历史中抹除。

保留这些 refs 有助于：

- 理解当时的实验路线；
- 恢复过去的方案；
- 对比不同方法；
- 理解后续 merge；
- 判断某些文件/代码为什么会存在；
- 防止未来 Agent 把历史成果误判为“垃圾文件”。

因此未来 Agent：

> **不得为了整理分支列表而删除这些已知历史分支。**

# 8. Reflog 提供了比 branch 列表更强的证据

最新快照包含 reflog。

这非常重要，因为：

> `git branch -a` 只能告诉我们“现在有什么 ref”，而 reflog 能告诉我们“这个 ref 曾经发生过什么变化”。

例如近期可以确认：

```text
2026-09-14 00:15:34 +0800
fetch origin:
storing head
origin/codex/r4-monitor
origin/codex/w3-hardening
```

之后本地进行了：

```text
pull origin main
commit
reset
commit
push
```

例如：

```text
2026-09-14 14:20:03
7e447c84
commit: 添加1034：W2验证子集数据规范（重点文档）

2026-09-14 14:20:52
1cf3574c
pull origin main: Merge made by the 'ort' strategy.

2026-09-14 14:23:32
093e272c
commit: 修正版本管理规范：必须使用--no-ff

2026-09-14 14:24:51
reset: moving to 7e447c84

2026-09-14 14:33:07
2ce39d9f
commit: 修正版本管理规范：必须使用--no-ff

2026-09-14 14:33:26
d30b67dd
Merge branch 'main' of github.com:spinner-bot/MOPD-2026
```

这说明本次事故期间 Git 本身也经历了相当复杂的同步、merge、reset 和版本管理调整。

因此后续如果继续取证：

> **应优先分析 reflog 中 ref 的出生、移动、merge、fetch、push 和 reset，而不是仅看当前 branch 名称。**
