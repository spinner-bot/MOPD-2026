## 1. 当前结论

1027 的 `no_repeat_ngram_size=4` 不适用于严格 JSON。它没有修复候选筛选，反而把原本可解析的固定 schema 系统性破坏。W2 科学进度仍为零：没有 audit 全量结果、没有可进入人工审核的构造结果，也没有运行 S/T 条件。

所有列入 1028 的 screen/construct 作业现已结束：screen 全部 `FAILED`，依赖的 construct 全部 `CANCELLED`，当前无 MOPD 作业在队或运行。旧档案保持不变，仅用于失败诊断。

## 2. 直接证据

### 2.1 对照

| 档案 | generation config | blind canary | 截断 |
|---|---|---:|---:|
| `20260911T1840-teacher-gap-screen-c1-128` | greedy，1024，无 repetition constraint | 7/8 schema-valid | 1/8 |
| `20260911T2215-teacher-gap-screen-fullpool-c1` | greedy，1024，无 repetition constraint | 8/8 schema-valid | 0/8 |
| 同上 full | 同上 | 2,190/2,366 schema-valid（92.56%） | 106/2,366 |
| c2/c3 与三个可运行 r2 canary | `repetition_penalty=1.05`、`no_repeat_ngram_size=4` | 均为 0/8 schema-valid | 均为 0/8 |

r2 并未因输出过长失败；其 EOS 与截断门控全部健康。失败集中在 schema 字段名，例如：

- `image_is_necesssary`、`image_is_n necessary`、`image_is_necessity`；
- `requires_unprovided_facts`；
- 缺少 `ambiguous` 的起始引号；
- `"**uncertainty**: ..."` 被生成为单个错误字段。

这些原始输出完整保存在对应 `canary/blind/rank-*.jsonl`。门控将其全部拒绝是正确行为；不得增加模糊字段名映射或宽松修复来制造通过率。

### 2.2 因果判断

`no_repeat_ngram_size` 面向自由文本去重，会禁止已经生成过的 token n-gram。严格 JSON 中字段名、标点和共同词根本来就必须按模板重复；模型为满足约束而改写 key 或破坏引号。退化与配置切换同步发生，并在互不相同的四组 canary 上复现，因果证据充分。

## 3. r3 纠正

已完成以下代码修改：

1. candidate runner 删除 `repetition_penalty` 和 `no_repeat_ngram_size` 参数及 `model.generate` 传参；
2. screen/construct sbatch 不再读取或传递这两个环境变量；
3. 保留 greedy、`enable_thinking=False`、`max_new_tokens=1536`、EOS/截断记录、严格 schema 与 fail-closed gate；
4. 保留 blind prompt 的 1–4 条不同观察、每条最多 24 词约束，以内容合约限制长度；
5. 44 项 CPU 合约测试、runner `py_compile`、两个 sbatch `bash -n` 全部通过。

对应提交：`3779577`、`c597b65`、`49352a4`。

### 3.1 排队代码漂移的追加门控

首次 r3 作业 `57568183/57568184` 提交后仍处于 PENDING，尚未执行样本。此时复核发现，旧 sbatch 只在 raw provenance 中读取启动时 `HEAD`，没有校验“提交作业时的代码”和“获得资源时的代码”一致。c2/c3 正是因此在排队期间静默采用了后来提交的 r2 参数。

为消除该变量，两个待运行作业已在零运行时间时取消，原档案保留。runner 现要求 `--code-commit`，在模型载入前与当前 `HEAD` 比较；screen/construct sbatch 同样要求 `MOPD_EXPECTED_CODE_COMMIT` 并在任何输出前 fail-closed。新增回归测试覆盖提交后代码漂移，完整测试为 45/45 通过。对应提交：`591d5dc`、`42aa9b7`、`ab2f194`。

## 4. 最小验证与继续条件

r3 只先重跑固定 C1 128 条链，使用新 run_id，绝不覆盖 r2 或已取消的首次 r3 档案：

- 首次提交后主动取消的归档：`20260913T2210-teacher-gap-{screen,construct}-c1-128-r3`；
- 固定代码提交后的有效验证：`20260913T2220-teacher-gap-{screen,construct}-c1-128-r3b`，construct 仅以 `afterok` 依赖 screen。

screen 必须依次满足：blind canary 8 条、blind full 128 条、audit canary 8 条、audit full 128 条。canary schema-valid rate 至少 75%，full 至少 90%，且任一阶段不得有 runner error 或截断/缺 EOS。通过后才允许构造；构造也执行同样的 canary/full 门控。

只有 r3 全链通过并核验产物后，才决定是否以相同配置重跑 fullpool。若 blind 仍因重复耗尽 1536 token，则优先改为多字段/受限枚举解码等结构化生成机制，不能恢复破坏 JSON 的 n-gram 约束。
