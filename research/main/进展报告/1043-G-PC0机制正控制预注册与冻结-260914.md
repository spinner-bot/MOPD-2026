## 1. 研究角色与不可越界结论

G-PC0 只问：**同一个冻结 4B 模型与输入实现，在已知存在多步状态传递、正确中间状态可由程序确定的视觉任务上，能否利用 T-QA？**

它不是 M3VQA/Vision-OPD 的数据结果，不估计自然图片的 P/R 可供性，不进入自然 G0 的 8/32/96，不构成 OPSD-v-t 训练数据，也不能支持论文中的自然场景有效性主张。无论结果好坏，B2a → B3–B5 → 自然 G0 的证据链和 1017 的 Go/Revise/Stop 门槛均不改变。

这一区分对应 1035 的三层对象：程序图本身固定提供 R 型可供性 `A(I)`；每题固定一个至少三步的任务瓶颈 `F(I,Q)`；四条件差异才测 `E(F,G,M)`。正控制只检查最后一层的实现与模型摄取能力。

## 2. 结果前冻结的 16 题

固定 seed 为 `20260914`，每类 4 题：

| 题族 | 图中信息 | 必要状态转换 | T-QA 最后不提供的步骤 |
|---|---|---|---|
| `directed_path` | 带颜色与方向的有向边、起点与节点 | 按四种颜色依次移动 | 从第三个中间节点沿最后一条边到终点 |
| `sequential_transform` | 起始整数与四个顺序运算框 | 逐步更新整数状态 | 对第三个中间值执行最后一次运算 |
| `grid_trace` | 5×5 网格、起点、四个箭头与 token key | 逐格跟踪四次位置 | 在最终位置读取 token 并映射全名 |
| `set_relation` | A/B/C 三个集合与 count→code 表 | 交集 → 去除 C → 计数 | 用可见表把计数映射为 code word |

正确标签按 `gpc0-01..16` 固定为 `A,B,C,D` 循环；因此每个题族各有一次 A/B/C/D，全包每个标签 4 次。每题保存唯一 PNG、四个不同选项、canonical answer、required evidence、最小 DAG、solution trace 和 guides。所有集合题中 C 都实际改变交集，避免把可删除证据伪装成推理步骤。

manifest 明确写入：

- `manifest_profile=g_pc0_v1`、`experiment_role=mechanism_positive_control`；
- `human_verified=false`、空 human provenance；
- `procedural_gold_verified=true`；
- `eligible_for_natural_g0=false`、`eligible_for_training=false`。

程序真值不冒充人类语义签名。自然 manifest validator 会拒绝本包；只有显式 `--manifest-profile g_pc0` 才能由共享 runner 接受。

## 3. 四条件与信息边界

沿用 1017 的同一 `COMMON_SHELL`、同一图片字节、同一问题/选项与以下条件：

1. `S`：privileged block 为空；
2. `T_Q`：只给同一组 guide questions；
3. `T_QA`：给 guide questions 及正确的中间状态；
4. `T_generic`：给不含题目实体和答案的通用检查文本。

T-QA 不给最终答案、选项字母或 canonical answer 同义词；它最多给出最终答案前的状态。manifest 中的完整 `solution_trace` 只用于合同审计，renderer 不会把该字段送入模型。

实际冻结 Qwen3.5-4B tokenizer 的 corpus median 为 T-Q 49 tokens、Generic-T 49 tokens，相对差 0；A/B/C/D 独立 token 序列为 `[32]/[33]/[34]/[35]`。运行时仍须对每个实际 chat template 复核 continuation 边界，不能只依赖这次预检。

## 5. 一次性运行与完整性门禁

本 v1 文档允许在上述冻结资产提交并推送后，使用 `submit_g_pc0.sbatch` 新建**一个** 4×A100、最长 30 分钟的 run；不得先跑 S、查看错误后替题，再跑 T。64 个 sample×condition 对由固定 manifest hash 调度并在一个 allocation 内完成。

运行固定：

- Qwen3.5-4B revision 如 §4；
- `enable_thinking=False`、`do_sample=False`；
- choice log-likelihood 与 constrained single-letter generation 同时记录；
- runner、gate 和决定器均绑定提交时 Git HEAD，关键文件 dirty 或 HEAD 漂移立即退出；
- manifest/profile、16 个图片 checksum、token 长度、64 条结果、固定 schedule、四条件 provenance、EOS/截断和 ≥99% 解析率均 fail-closed；
- 任一门禁失败只允许以同 manifest 修复配置并重跑，不读取部分条件效果。

该授权不包含第二版、复杂度调整或按结果改题。若 S ceiling，只能先形成新的编号文档，以预先规则定义 v2，再生成全新 manifest；v1 结果必须保留。

## 6. 结果读取前冻结的裁决

令 `b` 为 S 正确题数，`g` 为 S 错而 T-QA 对的题数，`r` 为 S 对而 T-QA 错的题数：

| 条件 | 决定 | 唯一解释 |
|---|---|---|
| `b ≥ 14` | `CEILING_INCONCLUSIVE` | v1 对 S 太容易，不能据此称 G 无效 |
| `b < 14` 且 `g ≥ 4` 且 `g-r ≥ 3` | `MECHANISM_PASS` | 当前模型/模板能消费高质量 reasoning states；自然 G0 仍须独立裁决 |
| `b < 14` 且不满足上一行 | `INGESTION_OR_RECIPE_FAILURE` | 在解释自然零效应前先检查模型、模板和 guide 表示 |

T-Q、T-generic 和四题族只报告 4 题分母上的描述性正确数；不作显著性检验，也不据此挑选自然题。决定器固定输出 `natural_image_claim_authorized=false` 与 `training_data_authorized=false`。
