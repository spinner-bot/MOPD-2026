# 2227-T：人工审阅导出校验工具与收尾操作说明 / Human Review Export Validator and Handoff

**记录时间 / Recorded:** 2026-10-16（Asia/Shanghai）

## 1. 缺口 / Gap

工作5的离线人工审阅页已内嵌60张原图、300条五条件配对回答和三项审阅字段。页面会将填写结果保存在浏览器localStorage，并允许导出JSON；在本次更新前，仓库没有验证导出文件是否覆盖全部60×5条记录、有没有重复或未完成字段，也没有要求“否/不确定”记录证据说明。这个人工复核步骤仍须由研究者执行，不能由模型输出或脚本替代。

The offline review packet contains 60 embedded benchmark images, 300 paired condition responses, and three review fields. Decisions are saved in browser localStorage and can be exported as JSON. Before this update, the repository lacked a validator for complete 60×5 coverage, duplicates, unfinished values, or evidence notes for negative/uncertain decisions. A researcher still needs to perform the review; neither model output nor a script can substitute for that judgment.

## 2. 校验工具 / Validator

新增 `scripts/validate_manual_review.py`，读取HTML按钮导出的 `work5-manual-review-decisions-v1.json`、冻结的 `manual-review-sample-v2.json` 及实际审阅的HTML文件。它核对：

- 恰好300条记录，覆盖60个样本与S0、SC、S1、S2、S3五种条件各一次；
- 每条记录的评测集/样本索引与冻结样本清单对应，无重复或缺失；
- `extraction_faithful`、`semantic_correct`、`judge_valid`均非待审且使用页面定义的合法取值；
- 若任一字段标为“No/否”或“Unclear/不确定”，该条必须填写说明；
- 输出记录审阅者标识、决策导出、样本清单及HTML审阅包的SHA-256。

The new `scripts/validate_manual_review.py` reads the JSON exported by the HTML button (`work5-manual-review-decisions-v1.json`), the frozen `manual-review-sample-v2.json`, and the exact reviewed HTML packet. It requires:

- exactly 300 rows, covering 60 cases once each in S0, SC, S1, S2, and S3;
- each track/case index to match the frozen manifest, with no duplicate or missing pair;
- all three fields (`extraction_faithful`, `semantic_correct`, `judge_valid`) to use an allowed non-pending value;
- an evidence note for every “No” or “Unclear” entry;
- a validation record containing reviewer identifier and SHA-256 hashes of the export, sample manifest, and HTML packet.

通过验证后输出的是审阅记录及汇总，不会自动改写原始分数、完整统计或论文结论；需研究者再检查该记录并决定是否进行敏感性分析。

Successful validation produces a review record and summary; it never automatically changes original scores, full statistics, or paper conclusions. The researcher must inspect the record and decide whether sensitivity analysis is warranted.

## 3. 自动化验证 / Automated verification

新增测试覆盖：完整300行导出通过；缺行、重复、待审字段及无证据的不确定判断被拒绝。Work5完整测试现为 **50项通过**；`git diff --check`通过。人工审阅包继续为 `report/manual-score-audit-sample-v1.html`，没有重新生成或覆盖50MB页面，浏览器内已保存的审阅状态不受影响。

New tests cover acceptance of a complete 300-row export and rejection of missing rows, duplicates, pending fields, and unexplained uncertainty. The full Work5 suite now has **50 passing tests**; `git diff --check` passes. The review packet remains `report/manual-score-audit-sample-v1.html`; the 50 MB page was not regenerated or overwritten, so any browser-local review state is unaffected.

## 4. 研究者操作步骤 / Researcher handoff

1. 在浏览器中打开 `report/manual-score-audit-sample-v1.html`，逐条检查原图、原题、参考答案、五条件模型回答及评分证据；记录抽取忠实度、语义正确性、裁判理由/标签有效性和必要的证据说明。
2. 点击页面顶部的“Download review decisions / 下载复核记录”，保存导出的JSON。浏览器localStorage不是项目归档，必须导出备份。
3. 在Work5仓库运行下列命令（将审阅者占位符替换为实际标识）：

```bash
python scripts/validate_manual_review.py \
  --decisions report/manual-review-decisions-v1.json \
  --sample-manifest audits/manual-review-sample-v2.json \
  --packet report/manual-score-audit-sample-v1.html \
  --reviewer "<reviewer-id>" \
  --output "$DATA_ROOT/judgment/manual-score-audit-validation-v1.json"
```

The researcher should open `report/manual-score-audit-sample-v1.html`, review the image, question, reference, five model responses, and scoring evidence; record all three decisions and evidence notes; click **Download review decisions** (browser localStorage is not an archive); then run `scripts/validate_manual_review.py` with the exported JSON, frozen manifest, packet, reviewer identifier, and an output under `$DATA_ROOT/judgment/`. Do not treat the browser-local state as archived project data.

验证失败时应根据错误提示补齐或核对导出，不修改分数来“通过”门禁。验证成功后，审阅者及项目负责人再讨论哪些分歧需要报告或敏感性分析；此前，本工作全量计算与统计完成，但人工审阅质量门禁仍为待完成。

On validation failure, correct or verify the export according to the error; never alter scores merely to pass the gate. After successful validation, the researcher and project lead can decide which discrepancies require reporting or sensitivity analysis. Until then, the full computational evaluation and statistics are complete, while the human-review quality gate remains outstanding.
