# 1057-自然 G0 逐题长度匹配修订预注册

**性质**：重点文档；1055 双长度控制在任何自然 manifest/结果产生前的匹配粒度修订

**创建时间**：2026-09-14 11:08（UTC+8）

**作者**：Codex (CINECA Leonardo)

**触发原因**：代码审计确认 1055 的首版实现只让每个 partition 的单一 Generic-Q/Generic-QA 分别匹配 T-Q/T-QA 的 corpus median。若 guide 数量、问题长度或中间答案长度随任务复杂度变化，同一道题内仍可能存在较大 token 差，条件效应及其 family/depth 异质性会混入长度效应。当前自然基础 manifest、rotation manifest、性能输出与 GPU 作业均为零，故应在结果前提高匹配粒度。

---

## 1. 冻结修订

自然 G0 的 Generic-Q 与 Generic-QA 改为**逐基础样本确定性生成**：

1. 对每个基础样本，用冻结实验 tokenizer 分别计算该样本 T-Q 与 T-QA privileged block 的 token 数；
2. 只依据目标 token 数、固定中性词库、固定选择算法和 tokenizer revision 构造对应 generic；不得读取题目语义、答案、guide 内容、family、模型输出或未来效果；
3. 每个样本内分别要求 `|len(Generic-Q)-len(T-Q)|/len(T-Q) ≤ 10%` 与 `|len(Generic-QA)-len(T-QA)|/len(T-QA) ≤ 10%`；任一失败即 fail-closed；
4. 相同目标 token 数允许产生相同文本。文本不需要人为制造表面多样性；多样性会引入新的语义变量；
5. base manifest 保存两项具体文本、四项 token 数、两项相对误差和生成器 provenance。rotation 只改变 displayed label，不重建 generic。

分区中位数仍作为审计摘要报告，但不再是通过门槛。通过门槛是每个样本、两个 matched pairs 全部合格。

## 2. 为什么不只控制平均长度

G0 和 G1 都是同一样本内的条件比较。若短 guide 样本获得偏长 generic、长 guide 样本获得偏短 generic，即使两组中位数相等，非线性上下文长度效应仍可能改变整体均值；更严重的是，guide 长度常与 reasoning depth 相关，分层结果会被系统性污染。逐题匹配让每个 paired contrast 自身满足长度合同，也使后续 `condition × task_family/depth` 更可解释。

这项修订不要求 token 数完全相等。中性词库按词截断时可能无法命中每个 tokenizer 长度；10% 容差沿用 1055，并由逐题 fail-closed 防止长尾偏差。实现若无法让某条通过，必须修构造算法或拒绝冻结整个 manifest，不能静默放宽容差或删除该题。

## 3. 与既有结果和统计的边界

- 历史 G-PC0 v1/label-rotation 保持原四条件和 corpus-median Generic-T，不重写 raw、manifest 或决定；
- 1055 的五条件、8/32/96 基础 N、四标签轮换、1,920 条 locked 记录、效应阈值、Holm 与 bootstrap 均不变；
- 1056 的 G1 双长度层原则继续成立；G1 的具体实现也必须在其结果前采用逐题匹配；
- 当前修订只减少长度混杂，不证明 generic 与结构化文本在语义、句法或注意力模式上完全等价。

## 4. 结果盲实现验收

实现提交必须满足：

1. 历史 `dual_control=False` 路径保持 corpus-level 行为，避免破坏 G-PC0 可复现性；
2. `dual_control=True` 报告逐样本 token 数、最大/中位相对误差与失败 sample ID；
3. finalizer 为每行独立写入 Generic-Q/Generic-QA，并保留 legacy `generic_context=generic_context_t_q` 兼容字段；
4. 测试构造“中位数通过但至少一题逐项失败”的样本，validator 必须拒绝；
5. 测试证明 generic 生成只依赖目标 token 数：语义字段改变但目标长度相同，输出不得改变；
6. 全套 CPU 测试通过；不为本修订运行 GPU。
