# B2a 离线标注包交付验收清单

**文档性质**：重点文档；供项目负责人验收 Claude 制作的离线标注工具包，并在交给真人审核者前后检查交付完整性。

**创建时间**：2026-09-14（UTC+8）  
**创建作者**：Codex (CINECA Leonardo)  
**触发原因**：B2a 标注将由无法访问 Leonardo 服务器的外部人员完成，需要把离线包的内容、匿名性、顺序绑定和回传要求固定为可检查清单，不与离线工具实现重叠。

## 1. 交付给标注人员的最小包

离线包应包含：

```text
b2a-offline-package-v1/
├── images/
│   ├── review-item-0000.jpg
│   ├── review-item-0001.jpg
│   └── review-item-0031.jpg
├── b2a-review-form.xlsx  或  b2a-review-form.csv
├── package-manifest.txt
└── README.txt
```

必须正好有 32 张图片，编号连续且一一对应。`package-manifest.txt` 至少记录匿名编号、文件名、文件 SHA-256、宽度、高度、格式和色彩模式；不得记录或暴露原始数据集名、原始图片 ID、原问题、原答案、机器 proposal、模型分数或服务器路径。

原始 B2a 包的服务器端冻结 SHA-256、真实 provenance 和原始 ID 只能由项目负责人保留，不能放入发给标注人员的包中。

## 2. 发出前验收

项目负责人应逐项确认：

- [ ] 图片数量为 32，编号为 `review-item-0000`–`review-item-0031`；
- [ ] 每个编号在图片目录和表格中恰好出现一次；
- [ ] 表格行顺序与图片编号一致；
- [ ] 图片均可用普通离线图片查看器打开；
- [ ] 图片字节没有被重新压缩、裁剪、增强或超分辨率处理；
- [ ] 图片元数据没有暴露数据集、原始 ID、服务器路径或其他来源线索；
- [ ] 表格不包含原问题、机器答案、模型结果或隐藏的提示列；
- [ ] 表格只允许人工字段，固定编号和文件名列不可修改；
- [ ] 包内没有脚本、联网组件、AI 接口或自动建议功能；
- [ ] `README.txt` 明确禁止原题检索、反向图片搜索、OCR/AI 辅助和与其他审核者交换判断；
- [ ] 包版本、文件清单和整体 SHA-256 已留档。

如果原始图片含有可能暴露来源的 EXIF 或其他元数据，不能简单删除后继续使用。应先记录风险，再由项目负责人决定是否制作显示副本，并同时保存显示副本与原始图片的像素/字节关系；不能让标注人员接触原始 provenance。

## 3. 表格验收

每行应能表达以下结果：

- 图片是否可用；
- `candidate`、`reject` 或 `ambiguous`；
- candidate 的一个目标问题和完整答案；
- `R` 或 `PR`；
- 至少两项直接视觉证据；
- 至少两步不可省略推理；
- 与直接证据完全相同的反事实必要证据；
- R/PR 对应的困难视觉证据；
- 是否需要外部知识；
- 审核者、带时区时间、备注、完成状态和人工签名。

表格不能用“通过/不通过”替代三种决定，不能把多个证据合并成一句无法拆分的描述，也不能把 reject/ambiguous 行删除。

## 4. 标注人员回传包

标注人员应回传：

```text
b2a-review-reviewer01-offline-v1/
├── b2a-review-reviewer01-offline-v1.xlsx  或  .csv
├── completed-package-manifest.txt
└── reviewer-notes.txt   （如有技术问题）
```

回传时必须保留全部 32 行，包括 reject 和 ambiguous。不得回传修改后的图片，不得改名，不得补交“精选 candidate 子集”。如果使用 Excel，项目负责人应保留原始 `.xlsx`，不要只保留导出的截图或复制粘贴文本。

## 5. 回传后服务器端验收

项目负责人负责执行以下步骤，标注人员不需要执行：

1. 只按匿名编号将离线表格与冻结 B2a 包逐行对应；
2. 检查编号、行数、图片文件名和包版本没有错位；
3. 检查所有 32 行均存在且无重复、无额外行；
4. 将离线人工字段转换为官方 reviewed JSONL；
5. 恢复服务器端原始 provenance，但不向标注人员回显；
6. 运行官方 finalizer，验证原包 SHA、不可变字段、字段类型、防火墙、语义门和 `valid_signed_reviews=32`；
7. 保存离线原件、转换结果、所有 SHA-256 和 finalizer summary；
8. finalizer 通过前，不运行 B2a 路由分析，不揭示 B1，不启动自然 G0。

离线表格通过人工检查不等于官方验收通过。任何字段错误、缺失、额外列、错位、哈希不一致或签名不完整，都应 fail-closed，不能手工“修成通过”。修正版必须另存为新版本，并保留原始回传文件。

## 6. 与科学流程的边界

本包只服务于 B2a 32 图真人盲审：

- 不产生自然 G0 结果；
- 不决定 G0 是否 Go；
- 不产生训练数据；
- 不替代 B3、B4、B5；
- 不允许使用模型结果辅助标注。

完成后，candidate 数量仍按 1039 的预注册路由解释：0、1–7、8–32。即使 32 张全部成为 candidate，也只允许进入预注册的 B3 八图 construction canary，不得直接扩展或训练。

## 7. 给 Claude 工具包的验收重点

Claude 交付工具包时，项目负责人应重点确认：

- [ ] 工具可以完全离线运行；
- [ ] 工具不会读取原问题或机器 proposal；
- [ ] 工具不会自动生成、改写或推荐人工字段；
- [ ] 工具保留匿名编号与图片的固定映射；
- [ ] 工具能导出完整 32 行，而不是只导出 candidate；
- [ ] 工具不会覆盖原始图片或空白模板；
- [ ] 工具失败时不会静默丢失已保存内容；
- [ ] 工具输出能被服务器端转换和官方 finalizer 验收；
- [ ] 工具附带离线安装/启动说明和一个不含真实语义的合成样例；
- [ ] 合成样例与真实包完全分离，不能混入真实审核结果。
