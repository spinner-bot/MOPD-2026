# 1059-T-Python 标准库模块遮蔽修复

**性质**：临时文档；测试与生产 runner 的 Python 导入路径修复记录

**创建时间**：2026-09-14 11:24（UTC+8）

**作者**：Codex (CINECA Leonardo)

**触发原因**：1057 实现后的全套测试在 `torch`/`transformers` 导入期间错误加载 `research/main/code/evaluation/statistics.py`，而非 Python 标准库 `statistics`。直接执行同目录下的 teacher-gap runner 时，该目录同样位于 `sys.path[0]`，所以这不只是测试环境现象。

---

## 1. 根因与影响

项目文件名 `statistics.py` 与 Python 标准库同名。PyTorch 的间接导入请求 `statistics` 时，脚本目录优先导致项目模块被加载；当前 `mb` 环境首先表现为该项目模块依赖的 `statsmodels` 不存在。即使安装 `statsmodels`，项目模块也不提供标准库 API，因此仍有产生后续属性错误的风险。

该模块在当前仓库没有任何 Python import 调用；全仓搜索只发现早期文档对文件路径的历史记录。因此最小安全修复是重命名，不引入兼容 shim，因为保留同名 shim 仍会继续遮蔽标准库。

## 2. 修复与验证

提交 `e67f981` 执行纯重命名：

```text
research/main/code/evaluation/statistics.py
→ research/main/code/evaluation/statistical_tests.py
```

验证分两层：

1. 把 `evaluation/` 显式置于 `sys.path[0]` 后导入 `statistics`，解析到当前 Python 环境的标准库路径；
2. 不预载入任何模块，直接运行完整测试发现链，173/173 通过：

```text
Ran 173 tests in 30.550s
OK
```

未修改统计函数内容、自然实验协议、manifest 或结果；未使用 GPU。早期 0001/0008 中的 `statistics.py` 路径是当时仓库状态记录，保留不追改；现行文件名以本报告和 Git rename 为准。
