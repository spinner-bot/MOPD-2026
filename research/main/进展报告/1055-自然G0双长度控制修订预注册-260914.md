# 1055-自然 G0 双长度控制修订预注册

**性质**：重点文档；1017 自然 G0 在任何自然 manifest/结果产生前的控制条件修订

**创建时间**：2026-09-14 10:51（UTC+8）

**作者**：Codex (CINECA Leonardo)

**触发原因**：1017 v0.3 的唯一 Generic-T 只与 T-Q 的 tokenizer 中位长度匹配，却同时用于判断更长的 T-QA 是否优于普通额外文本。冻结 G-PC0 输入的零结果依赖长度审计显示 T-Q/T-QA/Generic-T 中位数为 49/74/49 tokens，T-QA 比其控制长约 51%。自然 G0 尚无基础或轮换 manifest、性能输出及 GPU 作业，因此必须在结果前消除该混杂。

---

## 1. 冻结修订

自然 G0 从四条件升级为五条件：

| 条件 | 内容 | 匹配控制 |
|---|---|---|
| S | 空 privileged block | 基线 |
| T-Q | guide questions | Generic-Q |
| T-QA | guide questions + intermediate answers | Generic-QA |
| Generic-Q | 不含样本实体、答案和任务特定事实的通用检查文本 | tokenizer 中位长度匹配 T-Q，误差 ≤10% |
| Generic-QA | 独立的通用检查文本 | tokenizer 中位长度匹配 T-QA，误差 ≤10% |

两个 generic 文本来自同一冻结中性词库和确定性选择器；除目标 token 长度外，不得加入样本实体、最终答案、guide 内容或新事实。每个 partition 分别计算两个目标，所有样本共享该 partition 对应的冻结 Generic-Q/Generic-QA 文本。

主要结构性门槛改为成对比较：T-Q 只与 Generic-Q 比，T-QA 只与 Generic-QA 比。S 比较、0.08 semantic accuracy、0.15 nat、Holm、bootstrap、净翻转、Go/Revise/Stop 数值均不变。

## 2. 执行规模与统计单位

四个标签轮换保持不变；五条件带来的总记录为：

| 阶段 | 基础 N | rotation views | 五条件记录 |
|---|---:|---:|---:|
| canary | 8 | 32 | 160 |
| dev | 32 | 128 | 640 |
| locked | 96 | 384 | 1,920 |

有效统计单位仍为 8/32/96 个基础样本。两个控制条件不新增主要假设检验：Holm 仍只校正 T-Q−S 与 T-QA−S；matched generic 只承担原有结构性排除门槛。

## 3. 旧结果与兼容边界

G-PC0 v1/label-rotation 的四条件档案已经产生，必须保持不可变。其 Generic-T 49 tokens 只匹配 T-Q，故 1047 能支持“T-QA 改变程序化任务的语义排序”和接口健康检查，但不能单独排除 74-vs-49 token 长度差对增益的贡献。该限制不撤销 1047 的诊断决定，也不升级为自然结论。

实现必须按 manifest profile 隔离：历史 `natural`、`g_pc0`、`g_pc0_rotation` 保持四条件读取；只有尚未运行的 `natural_rotation` 使用五条件。不得重跑或重写历史 raw。

## 4. 结果盲实施要求

在任何自然 G0 条件输出前完成：

1. base manifest 同时保存 `generic_context_t_q` 与 `generic_context_t_qa`；
2. preflight 用冻结 tokenizer 分别报告两个目标和两个相对误差；
3. runner/结果 gate 按 profile 固定条件全集，拒绝四/五条件混用；
4. 聚合后每个基础样本必须具有五个语义观测；
5. 决策输出显式记录 `T_Q→T_generic_Q`、`T_QA→T_generic_QA` 的控制映射；
6. 合成端到端测试必须达到 canary 160/160，并证明不匹配控制不会被误用。

上述工程完成并通过全套 CPU 测试后，1017 协议版本升为 v0.4。自然运行仍受 B2a 真实人工签名和 B3–B5 基础清单阻塞。
