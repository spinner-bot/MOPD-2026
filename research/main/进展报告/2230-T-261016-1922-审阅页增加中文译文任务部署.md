## 1. 任务目标

在**不改变任何原始英文内容**的前提下，为其逐项补充中文译文，使审核者能够完成三项判断。

**产出为一份独立的双语版新文件，不得覆盖原件。** 原件 `manual-score-audit-sample-v1.html` 的字节内容与其 SHA-256 在报告 2218 中已有登记（当时实测 50,037,145 bytes），是审阅包的指纹。**改动原件会使该指纹失效**，故双语内容另存新文件；原件此后不再改动。

建议命名：

```
report/manual-score-audit-sample-v1-bilingual.html
```

双语版须完整继承原件的**全部功能**（每卡「保存 / Save」按钮、顶部工具栏、导出与校验兼容），即等价于「原件 + 中译」。

## 2. 翻译范围：全部内容，不只是模型输出

**所有者明确要求：所有英文内容都要译，不是只译输出。**

经逐行核对，页面中需翻译的内容如下。

### 2.1 每样本一次（60 组）

| 位置 | 内容 |
|---|---|
| `.case > h3` | `Case N` 后的 `selected stratum: ...` 分层名称 |
| `.flags` | 审计层标记，如 `long_tail_output`、`native_extraction_disagreement`、`native_terminal_disagreement` |
| 题目区 `<pre>` | **题目正文、全部选项 (A)–(F)、以及结尾的指令句**（如 `Answer with the option's letter from the given choices directly.`） |
| `Reference answer` 行 | 参考答案（多为字母，若为文本则一并译） |

### 2.2 每条件一次（300 组）

| 位置 | 内容 |
|---|---|
| `.scores` 各行的**取值** | 如 `Not correct`、`yes`、`ANSWERED`、`llm` 等（标签已双语，取值仍是英文） |
| `Evidence / 证据：` | 证据串（英文原文片段） |
| `<details>` **Model response** | 模型回答全文 |
| `<details>` **Full native judge output** | 原生裁判完整输出全文 |

### 2.3 页面级

| 位置 | 内容 |
|---|---|
| 标题下方说明段 | 已部分双语，补齐 |
| `notice` 块 | 已部分双语，补齐 |
| `Cases: 60 · paired condition views: 300 · tracks: six · seed: 20261016` | 英文说明行 |
| 导航条、按钮 | 已双语；若仍有英文残留一并补齐 |

> **说明**：页面中另有一处 `<pre>` 展示 `sample_schema` JSON 清单（机器可读的样本清单）。该块属数据而非叙述文字，**是否翻译由 Codex 自行判断并说明**；若译，必须另附原文，不得替换。

## 3. 硬性约束

### R1　由 Codex 亲自翻译，不得转交本地 LLM

**所有者明确要求。** 不得调用服务器上的 Qwen、不得调用任何本地或第三方模型接口批量生成译文。译文由 Codex 自身产出。

理由：该审阅的目的是取得**模型之外**的判断基准；若译文本身由另一个模型产出且无人核验，等于把一个未审计的模型输出插入证据链。由 Codex 亲自翻译至少使翻译责任的归属明确、可追溯。

### R2　原文必须逐字保留，译文只能并列，不得替换

这是最关键的一条。三项判断各自锚定原文：

- `extraction_faithful` 判断抽取是否忠实于**模型回答原文**；
- `judge_valid` 审计的是**裁判原文**；
- `semantic_correct` 依据的是**题目原文**与图像。

因此**英文原文一字不得改动或删除**。译文放在原文之后或折叠区中。

### R3　导出 JSON 的结构不得改变

`downloadReview()` / `buildPayload()` 产出的结构必须保持：

```json
{"schema": "work5-manual-review-decisions-v1", "rows": [{"case_title": "...", "condition": "...", "decisions": {...}}]}
```

`case_title` 仍须匹配 `^\s*Case\s+(\d+)\b`，`condition` 仍须匹配 `^\s*(S0|SC|S1|S2|S3)\s*[·|]`。校验器 `scripts/validate_manual_review.py` 依赖这两处正则，**改动标题文本会导致校验失败**。翻译不得触及 `<h3>` 与 `<h4>` 的既有文本。

### R4　页面必须保持自包含

不得引入外部 CSS/JS/字体/图片链接。图像仍以内嵌 base64 呈现，不得替换或重压缩。

### R5　双语内容另存新文件，原件作为基准保留

双语内容写入新文件（建议 `report/manual-score-audit-sample-v1-bilingual.html`），原件 `manual-score-audit-sample-v1.html` 保持不动。

理由：保留一份纯英文基准版，便于（a）译文有疑问时对照原文，（b）双语版排版或功能出问题时回退，（c）日后需要确认"某个判断当时看到的是哪个版本"时仍有一份未受翻译改动的参照。

审阅实际使用的是双语版，因此校验器 `--packet` 参数应指向双语版。

## 4. 排版要求（所有者特别提出：加中译后排版不能出问题）

现有布局要点：

```css
.question-grid { display:grid; grid-template-columns: minmax(260px,40%) 1fr; }
.conditions    { display:grid; grid-template-columns: 1fr 1fr; }
.condition     { border:1px solid #e0e4e8; border-radius:8px; padding:12px; }
pre            { white-space:pre-wrap; overflow-wrap:anywhere; max-height:480px; overflow:auto; }
```

具体要求：

1. **译文不得撑破两列网格**。`.conditions` 每行两张卡片，译文过长会使卡片高度暴涨——建议默认折叠（`<details>`），或限制可视高度并允许内部滚动。
2. **`<pre>` 内不得嵌入 HTML 标签**。译文若放在 `<pre>` 中会原样显示标签文本；应在 `<pre>` **之后**另起元素。
3. **不新增会影响既有选择器的 class 名**。新元素使用独立命名（如 `.zh-translation`），并只以新增的 `<style>` 规则描述，不得改动现有类。
4. **第 4 节（前一版）新加的元素必须保持可用**：审阅页当前已含顶部工具栏（打开/新建存档、全部保存、下载）与每张卡片底部的「保存 / Save」按钮。**新增译文不得移除或遮挡这些控件**，`data-review` 属性一个都不能少。
5. **视觉上区分译文**：建议灰底、略小字号，并统一加标记 `机器翻译 · 非权威 · 判断请以英文原文为准 / Machine translation, non-authoritative`。
