## 1. 唯一研究问题

在无需外部知识、对完整图像成立、具有至少两步不可省略证据转换的视觉问题上，冻结的 Qwen3.5-4B 是否因结构化文本特权而显著优于同一模型的无特权条件？

本轮只估计 teacher utility，不训练模型。它区分两个上界：

\[
Gap_{TQ}=Perf(I,G_Q,Q)-Perf(I,Q)
\]

\[
Gap_{TQA}=Perf(I,G_{QA},Q)-Perf(I,Q)
\]

`T-Q` 回答“引导问题本身是否能组织推理”，`T-QA` 回答“如果可靠中间状态在训练期可见，最多有多少可蒸馏信息”。两者不能合并报告。

## 2. 数据隔离与样本量

### 2.1 三个互斥集合

| 集合 | 数量 | 用途 | 是否进入主要结果 |
|---|---:|---|---|
| pipeline canary | 8 | 检查图片读取、渲染、token scoring、解析与记录完整性 | 否 |
| construction/dev | 32 个唯一 `source_image_id` | 调整筛选提示、guide/option 构造和人工审核说明 | 否 |
| locked pilot | 96 个唯一 `source_image_id` | 一次性运行冻结条件并作 Go/Revise/Stop 判断 | 是 |

三个集合按 `source_image_id` 与已知近重复簇隔离。任何在 canary/dev 中用于调试的图片不得进入 locked pilot。同一图若派生多个问题，本轮只保留一道；正式实验再按图像 cluster 处理同图多题。

提交 `040d55e` 将该要求变成 GPU 前置门禁：Slurm 必须同时提供 8/32/96 三份 manifest；CPU `validate-manifests` 逐份校验数量、人工字段和答案标签平衡，要求每份内部 `source_cluster_id` 唯一，并检查三份之间的 source image 与近重复簇完全不重叠。三份文件 SHA-256 和 gate 结果先写入 run archive，失败时不得启动 canary GPU。

### 2.2 候选不足时的处理

先从 1016 的 128 条确定性候选开始语义筛选。如果不足以形成 32 dev + 96 locked：

1. 使用同一固定规则和 seed 扩大候选清单；
2. 不降低闭世界、唯一答案或推理深度门槛；
3. 不查看任何 S/T 输出；
4. 记录每轮候选数、排除原因和 manifest hash。

### 2.3 冻结顺序

```text
候选 ID 清单
  → 外部知识依赖判定
  → 图像与问题有效性判定
  → 最小证据路径
  → guides 与四选项
  → 人工 100% 复核
  → semantic option ID 平衡与源图去重
  → 四个 displayed-label rotation 执行视图
  → locked manifest + hash
  → 冻结 prompts/model/code
  → 才允许运行 S/T 条件
```

一旦 locked manifest 生成，任何内容修订都必须建立新版本；不得在同一结果表中替换失败样本。

## 3. 闭世界筛选合约

### 3.1 三类标签

每条候选只能进入以下一个状态：

| 标签 | 定义 | 本轮处置 |
|---|---|---|
| `image_only` | 最终答案及每个必要中间结论都由当前图像或题面明确给出，可唯一作答 | 继续审核 |
| `external_required` | 至少一个不可省略命题依赖未在图像/题面中提供的事实 | 排除，但保留原因 |
| `ambiguous` | 图像分辨率、答案别名、指代或知识边界使上述判断不能可靠确定 | 排除出 locked pilot，进入后续复核池 |

“日常视觉概念识别”不自动算外部知识；但国家与地点事实、人物身份、历史事件、物种专门属性、药用、起源、百科关系、小说上下文和未写出的数学规则，只要是答案链必要节点，就标为 `external_required`。

### 3.2 判定时的信息防火墙

筛选分为两个语义视角：

1. **blind image solver** 只看 `I,Q`，输出候选答案、可见证据和不确定性；
2. **entailment auditor** 看 `I,Q,reference_answers`，但不看官方 Wikipedia evidence 正文，逐项判断参考答案是否由图像与题面蕴含。

官方 evidence 文本与 URL 只在判定完成后用于分析排除原因，绝不作为 guides、选项构造的事实源，也不提供给 teacher。模型判断只能产生候选；locked pilot 的 `image_only` 需要人工复核通过。

### 3.3 自动排除

出现任一项即不得进入 locked pilot：

- 图片缺失、损坏、路径越界或 checksum 不符；
- 问题、参考答案为空；
- 问题要求识别图中未指明人物/地点的专名，再询问其百科属性；
- 答案依赖 URL/evidence 才能成立；
- 题目存在多个图像上同样合理的答案；
- 问题从局部 crop 视角撰写，对完整图像的方位或指代不成立；
- 参考答案只是评测别名集合，无法转成唯一语义答案；
- 仅凭语言先验即可稳定作答，图像证据不是必要输入。

## 4. R/PR 与最小证据路径

本轮主要目标是 R，允许少量自然出现的 PR，但不设 PR 配额，避免为凑层而强造问题。

### 4.1 R 准入

R 必须满足：

1. 至少两个可区分的图像实体、区域或状态参与答案链；
2. 从直接视觉证据到答案至少有两步不可省略的信息转换；
3. 单一局部 crop 或单个实体属性不足以唯一回答；
4. 删除任一关键中间状态后，答案链出现歧义或断裂；
5. 推理不是把同一句话改写多次。

### 4.2 PR 准入

除满足 R 外，PR 还必须包含困难局部节点，例如小目标、遮挡、小文字或细粒度属性，并满足：

\[
A\not\Leftarrow E_{local},\quad
A\not\Leftarrow E_{global},\quad
A\Leftarrow E_{local}+E_{global}
\]

只有局部难点与全局关系处于同一条必要证据链时才是 PR。

### 4.3 记录结构

每条 accepted 样本至少保存：

- `source_image_id`、源数据 ID 与 provenance；
- `knowledge_dependency_label` 和结构化原因码；
- `task_family`、`reasoning_depth`；
- `required_evidence[]`；
- `difficult_visual_evidence[]`：R 必须为空，PR 至少一项且属于 required evidence；
- `minimal_reasoning_graph`，节点类型限 `evidence/intermediate/answer`；
- `full_image_reference_valid=true`；
- 语义模型原始输出、解析方式与人工审核记录。

`question_hop` 仅作抽样分层信息，不得直接写入最终 `reasoning_depth`。

## 5. Guide 与选择题合约

### 5.1 T-Q/T-QA 共用同一条 guide 链

每条样本生成 1–4 个 guide QA。`T-Q` 只渲染 guide questions；`T-QA` 渲染同一批 questions 及其 intermediate answers。两者的差异只能是中间答案是否可见。

每个 guide 必须：

- 能由图像或先前已给出的中间状态回答；
- 对下一节点或最终判断有局部必要性；
- 不出现正确选项字母；
- 不直接陈述、同义改写或排他性暗示最终答案；
- 不引入官方 evidence 中的外部事实；
- 删除后能明确说明哪条依赖被破坏。

`T-QA` 可以提供真正的中间状态，这是特权的定义；它不能把最终答案伪装成中间答案。

### 5.2 四选项

M3VQA 原题需要转成 A/B/C/D 后才进入 pilot。四个选项必须：

- 恰有一个被图像证据支持；
- 三个 distractor 都与问题类型一致、语义上 plausible，并能被图像证据排除；
- 不以明显长度、语法或具体程度暴露正确项；
- 不引入外部知识才能排除的 distractor；
- 最终 96 条正确标签严格平衡为 A/B/C/D 各 24 条。

语义 option ID 在基础 manifest 冻结前由确定性脚本重排。1048 的四个 displayed-label rotations 随后确定性展开；同一 rotation 的所有条件完全复用同一显示顺序。

## 6. 输入条件与控制变量

### 6.1 必做条件

| 条件 | 输入 | 地位 |
|---|---|---|
| S | `I,Q` | 配对基线 |
| T-Q | `I,G_Q,Q` | 原始 Guiding Questions 假设 |
| T-QA | `I,G_QA,Q` | reasoning-state oracle 上界 |
| Generic-Q | `I,G_{generic-Q},Q` | 与 T-Q 长度匹配的普通额外文本控制 |
| Generic-QA | `I,G_{generic-QA},Q` | 与 T-QA 长度匹配的普通额外文本控制 |

### 6.2 条件性诊断

`V-add` 与 `VT` 仅在同一 locked 样本已有经人工确认的 crop 时运行。不得为了获得视觉条件而把 locked pilot 缩减为“容易裁剪”的子集；若 crop 覆盖不足，V/VT 只作明确标注 N 的次级分析。

### 6.3 唯一允许改变的输入

四个必做条件必须共享：

- 同一 image bytes；
- 同一最终问题、语义选项集合和 rotation 映射；
- 同一 system instruction、输出格式和 scoring shell；
- 同一模型 revision、processor、precision 与 generation 参数。

条件间只替换 `<PRIVILEGED_CONTEXT>`。S 为空；T-Q 为 guide questions；T-QA 为 guide QA；Generic-Q 与 Generic-QA 都是不含样本实体、答案或任务事实的通用检查步骤，分别与 T-Q、T-QA 的 tokenizer 中位长度相差不超过 10%。二者使用同一冻结中性词库确定性填充，不针对单题结果调节。

### 6.4 推理模式

实验模型统一：

```text
enable_thinking=False
do_sample=False
```

数据生成模型是否 thinking 不影响此条。所有条件必须显式记录 chat-template 参数，禁止依赖默认值。

### 6.5 G-PC0 的工程复用边界

1043 的程序化正控制使用历史四条件、同一 `COMMON_SHELL`、4B revision、scoring 和结果完整性 gate，但通过显式 `manifest_profile=g_pc0_v1` 与自然 8/32/96 隔离。1055 后只有尚未运行的 `natural_rotation` 使用五条件；历史 G-PC0 档案和哈希不变。自然 validator 必须拒绝没有人工签名的 G-PC0；G-PC0 validator 反过来要求 `human_verified=false` 和程序化 provenance。其三分支决定只诊断 G 摄取链，不进入本协议的自然 Go/Revise/Stop 统计。

1045 已记录 G-PC0 v1 的决定为 `INGESTION_OR_RECIPE_FAILURE`，且固定字母接口存在结果后的 A/C 塌缩信号。因此自然 G0 在其原有 8/32/96 数据门禁之外，新增“文本特权消费链先通过独立健康检查”的操作门禁；这不修改本协议的自然样本、指标或阈值。

1046 已把标签先验的诊断与自然协议进一步隔离：同一语义选项遍历四个 displayed labels，再按语义汇总原始 log-likelihood。1047 的 256/256 gate-pass 结果为 S/T-Q/T-QA/Generic-T=3/3/9/2，T-QA 有 6 个错→对且 0 个反向翻转，裁决 `LABEL_INTERFACE_MASKED_G_SIGNAL`。它证明当前 G 表示可被消费，也证明原固定字母主测量不再适合自然 G0。

1048 因此在任何自然 S/T 结果前冻结标签稳健测量：基础 A/B/C/D 是语义 option ID；每个样本运行四个循环 displayed-label rotations，每个语义选项各占 A/B/C/D 一次；四次 raw label log-likelihood 映射回语义后取均值。四语义均值的 argmax 是主 accuracy，四语义内 log-softmax 的正确项是 `semantic_correct_log_prob`。四轮换只是同一基础样本的重复测量，不把 N 放大四倍。1055 进一步在零自然结果时加入双长度控制；标签轮换本身不变。

## 7. 评分与完整性门控

### 7.1 两套输出

1. **Choice scoring**：对每个基础样本运行四个循环标签映射，将 A/B/C/D 标签序列 log-likelihood 映射回语义 option ID 后跨轮换求均值；其 argmax 是主行为 accuracy，四语义内 log-softmax 是连续机制指标来源；
2. **Constrained generation**：确定性生成单个 displayed label 并映射回语义；只作接口诊断，多数票并列记 tie/abstain，不进入主裁决。

运行前必须验证四个标签的 tokenizer 序列并保存；如 token 长度不同，则对完整标签序列求和，不以单个 token 近似。

除独立编码外，runner 对每条实际 chat template 再编码 `template` 与 `template+label`，要求前者是后者的严格前缀且新增后缀恰等于冻结标签序列。这样可发现 BPE 在答案边界重分词导致的“打分标签与实际生成标签不一致”；验证结果逐条保存，任一失败使结果 gate 关闭。Qwen3.5-4B 当前模板以 assistant 换行结尾，CPU 实测 A/B/C/D 后缀分别为单 token 32/33/34/35，但运行时仍逐条复核。

### 7.2 记录字段

每条 `sample × rotation × condition` 记录：

- 四项 log-likelihood 与归一化概率；
- 生成原文、解析答案和 correctness；
- correct-answer log-prob、margin、entropy；
- 输入 token 数、生成 token 数、截断与 EOS；
- model/processor revision、prompt hash、manifest hash、code commit、precision；
- image checksum、condition、sample ID、source dataset/record/image/cluster ID；
- 冻结的 task family 与 reasoning depth，供预注册的描述性 subgroup 分析使用；
- error 与 parse method。

还必须记录 `base_sample_id`、`label_rotation`、基础 manifest SHA、rotation spec SHA、`displayed_label_to_semantic_option`、正确语义 option ID；聚合结果保存四个 `semantic_score`、语义内正确 log-prob、semantic margin 与主预测。

### 7.3 fail-closed gate

locked pilot 只有在以下条件全部满足后才能分析：

- 96 个基础样本 × 4 个 rotations × 5 个必做条件，即 1,920 条记录全部存在且键唯一；
- 每条四项 score 均有限，归一化和在容差内为 1；
- 无图片读取错误、silent fallback 或 prompt 字段缺失；
- 无截断；生成答案解析率至少 99%；
- 各条件的 manifest/model/code/prompt hash 一致性通过；
- 条件之间同一 rotation 的图像、问题和 displayed options 完全一致；四个 rotations 的语义文本集合相同且映射严格覆盖 A/B/C/D。

解析 gate 必须显式读取本阶段 frozen manifest，而非只相信 raw 内自报的 `manifest_hash`。它逐条重算并核对 manifest SHA、完整 sample ID 集合、source image/cluster、image checksum、正确选项、问题 hash 和有序四选项 hash；任一不同均保留失败 summary 且不生成 parsed 结果。这样即使另一份同规模 raw 内部完全自洽，也不能与本次 manifest 混用。

固定调度函数由 runner 与 gate 共用：gate 还按 `manifest_hash × sample_id × condition` 重算每一项的唯一 `schedule_index`，再核对 rank 分片。仅做到索引全集完整或 `rank=index mod 4` 不足以通过；任何 sample-condition 重排都视为调度漂移。

失败时只修配置并重跑相同 manifest；不得先看部分效果。

## 8. 指标与预注册判断

### 8.1 主要指标

1. `ΔSemanticAcc(T-QA − S)`：四轮换语义聚合后的 reasoning-state oracle；
2. `ΔSemanticAcc(T-Q − S)`：四轮换语义聚合后的纯引导 teacher gap；
3. `ΔSemanticCorrectLP`：四个 semantic scores 内 log-softmax 后正确语义 log-prob 的配对均值差。

次要指标包括 margin、entropy、错→对/对→错翻转和 T-Q/T-QA 对 oracle envelope 的比例。Generic-Q/Generic-QA 只用于各自匹配条件的结构性判断，不能替代 S。

### 8.2 统计方法

- accuracy 使用配对差、错→对与对→错计数、exact McNemar 单侧检验；
- semantic correct log-prob 使用按 `source_image_id` 的 10,000 次 paired bootstrap，报告均值与 95% CI；
- pilot 只有每图一题，cluster 仍保留为源图以与正式分析一致；
- T-Q 与 T-QA 两个主要对比使用 Holm 校正；
- subgroup、depth 和 PR 分析只作探索，不作为本轮 Go 的必要条件。

1040/`20260914T0408-teacher-gap-g0-power-audit` 在任何 S/T 结果产生前补做了 paired accuracy 功效审计。对 `N=96`、真实净增益 0.08 和 Holm 第一步保守单侧 `α=0.025`，若总正反翻转率 `d` 为 0.10、0.20、0.30，exact McNemar 功效分别约为 0.643、0.339、0.231。因此 96 条的定位是筛查**足够大且方向稳定**的 teacher gap，而不是对 0.08 效应普遍具有 80% 检验功效。结果必须报告正向翻转 `b`、反向翻转 `c`、`d=b+c` 和净值，不能把单次未显著解释成所有文本特权无效。

该澄清不扩大 locked N、不放宽显著性或 effect-size 门槛。若 `ΔSemanticAcc≥0.08` 但反向翻转多、Holm 后未显著，应归入下述 Revise/不稳定路径；Stop 当前配方仍须联合满足 §8.6 的 semantic accuracy、log-prob 与净翻转条件。未来确认性 N 沿用 1037：在 G0 后、读取 G1 结果前按方差与预算一次冻结。

### 8.3 强 Go：T-Q 保持主方法

同时满足：

1. `ΔSemanticAcc(T-Q − S) ≥ 0.08`；
2. Holm 校正后的 exact McNemar 单侧 `p < 0.05`；
3. `mean ΔSemanticCorrectLP ≥ 0.15 nat` 且 paired bootstrap 95% CI 下界 `> 0`；
4. T-Q 相对 Generic-Q 至少满足 `ΔSemanticAcc ≥ 0.04` 或 `ΔSemanticCorrectLP ≥ 0.10 nat` 且方向稳定；
5. 错→对数量大于对→错，人工复核未发现答案泄露或外部知识注入。

### 8.4 条件 Go：转向 T-QA 主方法

T-Q 未满足强 Go，但 T-QA 满足同样的 0.08 accuracy、0.15 nat、显著性和相对 Generic-QA 的区分条件。此时后续主张改为 **Privileged Reasoning-Path Distillation**；T-Q 保留为消融。

### 8.5 Revise

出现任一情况进入 Revise，不启动全量数据或训练：

- T-QA 的 `ΔSemanticAcc` 在 0.03–0.08 之间；
- semantic accuracy 未翻转，但 `ΔSemanticCorrectLP` 明显为正；
- T-QA 强、T-Q 弱，但泄露/中间状态质量尚不能排除；
- 对应的 Generic-Q 或 Generic-QA 接近结构化 T，无法区分普通提示效应；
- effect 只集中在少数题型或高度不稳定。

Revise 必须开新 manifest/version，允许调整一次 guides 或候选来源，再运行新的 locked pilot；旧结果完整保留。

### 8.6 Stop 当前配方

若 T-QA 同时满足：

- `ΔSemanticAcc < 0.03`；
- `ΔSemanticCorrectLP < 0.05 nat` 或其 95% CI 包含 0；
- 无稳定净错→对翻转；

则停止当前“M3VQA 闭世界题 + 当前 guide 构造”的扩大与 OPSD 训练。该判断不自动否定所有文本特权，但要求提出新的数据或 privilege 定义后再开版本。

**1054 执行澄清**：Go 与 Stop 均以 `leakage_free=true` 为解释前提。若 locked 集发现答案泄漏或外部事实注入，即使观察到近零效应，也只能返回 `REVISE` 并重审数据，不能把污染结果解释为当前 G 配方无效。提交 `353b920` 已把这一点接入固定标签和四轮换共用决策器；原数值门槛不变。

### 8.7 视觉诊断解释

若 V/VT 有足够覆盖，另报告：

\[
Interaction=Perf(VT)-Perf(V)-Perf(TQA)+Perf(S)
\]

该结果只用于判断 R/PR 的模态互补，不改变文本主 gate，也不从低覆盖 V 子集反推全体。

## 9. 盲法、泄漏与可复现性

1. 候选筛选者和人工审核者不能看到 S/T 结果；
2. 负责运行的脚本在全部条件完成前不输出按条件聚合的 accuracy；
3. 运行顺序按 `sample_id × condition` 的冻结 hash 交错，避免条件与时间/节点状态绑定；
4. 官方 M3VQA evidence 不能进入 prompt、guides 或 options；
5. 所有排除样本写入 rejects 并保留原因，不静默删除；
6. 大文件只写 Work payload，仓库只提交代码、manifest 元数据、哈希和小型汇总；
7. run archive 在输出产生前初始化，旧档案不可修改；
8. 首次结果报告编号预留为 1018，必须按本协议原样报告未达标结果。

提交 `ebd94f3` 进一步把第 7 项实现为排他写入：raw、parsed、gate summary 和最终 decision 任一目标已存在时，runner/processor 都拒绝覆盖；重跑必须使用新 run ID。Slurm 还要求显式设置 `MOPD_IMAGE_ROOT`，不再默认假设所有题来自 M3VQA，同一安全根须覆盖冻结清单中的全部来源。

冻结清单 finalizer 同样实行排他写入：`--output-dir` 已存在即在读取审核结果和 tokenizer 前失败，新输出文件使用 exclusive create；进程中断留下的部分目录也不得原地续写。construction candidate 必须显式携带非空 `source_dataset`，清单逐条原样传递，禁止从 candidate ID 猜测来源或将混合来源统一标成 M3VQA。旧 Branch A 记录若缺少该字段，不能直接进入冻结集；必须由保留真实来源的新版构题流程重新生成。

finalizer 不再在导出时丢弃 `canonical_answer_text` 和 `difficult_visual_evidence`。bundle gate 独立复验正确标签对应的 option 文本、required evidence 与 DAG evidence 的集合相等、困难节点属于必要证据、R 无困难节点、PR 至少一个困难节点，以及所有 guide 的 `supports_next` 指向 DAG 现有节点。冻结文件本身因此包含重验 R/PR 与答案映射所需的最小 provenance。

仅核对 `git rev-parse HEAD` 不能发现运行文件存在未提交修改。Slurm 因此在 bundle gate 前、canary 后、locked 前后和最终 decision 前反复检查六个关键 tracked files 与 `EXPECTED_COMMIT` 是否一致；runner 还在每条 raw record 中写入四个实际加载模块的 SHA-256，结果 gate 要求所有 rank/条件完全一致。仓库其他历史日志或 data/models 软链接状态不参与这项代码检查。
