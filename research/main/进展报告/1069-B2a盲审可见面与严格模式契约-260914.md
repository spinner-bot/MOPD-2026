# B2a 盲审可见面与严格模式契约

**性质**：重点文档；在真实人工标签产生前冻结 B2a 第一阶段界面的最小可见面与审核文件严格模式。

**创建时间**：2026-09-14 12:18（UTC+8）  
**创建作者**：Codex (CINECA Leonardo)  
**触发原因**：等待 Claude C4-R 独立复核期间，Codex 对 C4 做内部静态审计，发现来源身份仍通过浏览器 API 暴露，且额外值为 `null` 的未知 JSON 键可绕过基于 `dict.get()` 的不可变字段比较。图片端点也应校验实际响应字节，而不是读取后再次打开路径校验可能已经变化的文件。

---

## 1. 问题与证据风险

B2a 的目标是在不知道 M3VQA 原问题和机器 proposal 的条件下，只依据图片构造自然、闭世界、唯一答案的 R/PR 目标。当前界面虽然不返回问题内容，却向浏览器返回并显示 `source_dataset` 和 `source_image_id`。这两个字段不是完成判断所需的信息，还可能让审核者定位原数据记录；因此“问题文本未直接出现在页面”不足以构成最强盲法。

当前草稿与 finalizer 的不可变字段比较使用 `original.get(key) != reviewed.get(key)`。当 reviewed 文件额外加入一个原包不存在、值恰为 JSON `null` 的键时，两侧 `get()` 都返回 `None`，该键可能不被报告。这不会自动生成标签，但会允许冻结 schema 之外的来源、问题别名或其他未声明字段进入已接受工件，削弱防火墙的可审计性。

当前图片端点先读取响应 payload，再重新打开文件计算哈希。若文件在两次读取之间变化，第二次哈希不能严格证明第一次读出的响应字节等于冻结字节。风险很窄，但可用直接对 payload 求哈希消除。

## 2. 冻结契约

在任何真实 B2a 人工审核开始前，C4 与 finalizer 必须满足：

1. 浏览器 API 的单条记录只暴露 `calibration_record_id`、审核进度、图片内容、图片技术元数据和可编辑人工字段；不暴露 `source_dataset`、`source_image_id`、`image_candidate_id`、`image_path` 或其他可用于反查原题的来源身份。
2. 冻结原包在服务端仍保留来源身份，用于 ID 对齐、图片校验和后续锁后联结；隐藏只改变第一阶段的人类可见面，不删除 provenance。
3. reviewed/draft 每条记录的键集合必须与对应原包完全相同。缺键或任何额外键均 fail-closed；禁止用 `null`、空字符串或其他值绕过。
4. finalizer 核心必须独立执行同一严格 schema 检查，不能依赖 UI 已经校验；CLI 编辑的 reviewed 文件与 UI 草稿接受同一门禁。
5. 图片响应必须对即将发送的 payload 本身计算 SHA-256，并与冻结记录比较；不一致时不得发送图片。
6. 上述修复不得读取图片语义、生成或填写 `human_*` 字段，不改变 candidate/R/PR 的语义判据与 0、1–7、8–32 路由。

## 3. 验收断言

- API/HTML 不出现来源数据集和来源图片 ID；审核者仍能用随机化的 `calibration_record_id` 导航。
- 加入任意额外 `null` 键的 draft 在启动时失败；同类 reviewed 文件在 finalizer 中进入 invalid，不可能成为 accepted。
- 删除任一原包字段同样失败。
- 服务启动后修改图片字节，图片 payload 读取 fail-closed。
- 既有完整合成审核仍可得到全量 valid；冻结真实包及其 SHA-256 不变。
- 全套单元测试通过；真实人工签名仍报告 0/32。

**实现状态**：`174bc6e` 已完成全部断言；验证与边界见 1070。

## 4. 科学边界

本契约提高的是盲法和工件身份强度，不提供关于 M3VQA 图像可供性、自然 teacher gap 或 T/V 特权效果的新增结果。B2a 仍需 spinner-bot 或其指定的真实审核者逐图完成。Claude code (local) 仍只执行 1038 已分配的 C4-R 独立复核；本文不增加其任务范围。
