# 2209-T：large 分区两个快照仓库的失效状态

**创建时间**：2026-10-16 04:51（UTC+8）  
**创建作者**：Claude Code (local)  
**触发原因**：报告 2202、2204 核验服务器克隆布局时，在数据分区 `/leonardo_scratch/large/` 下发现两个 `MOPD-2026` 相关目录。经查明二者为**浅层单提交快照**，其 HEAD 指向改写后已不存在的提交。所有者决定保留，故本文仅记录其失效状态，供后续查阅者免于误用。

## 1. 位置与形态

| 路径 | 体积 | `.git` |
|---|---:|---|
| `/leonardo_scratch/large/userexternal/rqian000/MOPD-2026` | 316 K | 目录（独立克隆） |
| `/leonardo_scratch/large/userexternal/rqian000/MOPD-2026-work5` | 6.5 M | 目录（独立克隆） |

两者均为：

```console
$ git config --get remote.origin.partialclonefilter
blob:none
$ [ -f .git/shallow ] && echo shallow
shallow
```

即 **浅克隆（`--depth=1`）+ blobless（`--filter=blob:none`）**：

| 特征 | 实测 |
|---|---|
| 提交数 | 各 **1** 条 |
| 是否 shallow | **是** |
| 缺失对象类型 | 全部 blob（文件内容按需拉取） |

**因此它们不是完整克隆**——不含历史，也不含文件内容，这是体积仅有几百 KB 的原因。

## 2. 失效状态

两者的 HEAD 均为同一个提交：

```
1c0df3d  Create Work5 full benchmark evaluation protocol
作者: Codex (local)
时间: 2026-10-14 01:04:08 +0800
```

**该提交在报告 2202 的历史改写后已不存在于仓库中。** 改写改变了 2026-10-13 19:20 之后全部提交的哈希，`1c0df3d` 属于其中的改写对象。

后果：

| 项 | 状态 |
|---|---|
| 与远端 `main` 的关系 | 无共同可达提交（改写后哈希全变） |
| 能否 `git pull` | 不能——本地与远端无共同祖先 |
| 能否作为工作副本 | **不能** |
| 是否含 `Rui Qian` 署名 | 否（0 条，其唯一提交不在受影响范围内） |

## 3. 来源判断

创建时间：

```
MOPD-2026         2026-10-13 19:14:15 (CEST)
MOPD-2026-work5   2026-10-13 19:15:39 (CEST)
```

**相隔 84 秒**，为脚本批量创建，非人工操作。

**无设计依据**：报告 1063 与工作5 README 均未提及将仓库副本置于数据分区；README 明确的分工是「脚本/Git 工作树放 `fast`，数据放 `large`」。故这两个目录偏离既有约定。

## 4. 与数据目录的区别

同层另有真正的数据目录，命名带 `-data` 后缀：

```
/leonardo_scratch/large/userexternal/rqian000/
├── MOPD-2026              316K   ← 本文所述快照（无 -data 后缀）
├── MOPD-2026-work5         6.5M   ← 本文所述快照（无 -data 后缀）
└── MOPD-2026-work5-data    ...    ← 数据目录（README 约定位置）
```

**识别方法：看有无 `-data` 后缀。**
