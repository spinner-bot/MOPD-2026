# 1056-G1 文本对照的双长度层契约

**性质**：重点文档；尚未运行的 G1 正式机制确认实验之文本因果对照增量契约

**创建时间**：2026-09-14 11:03（UTC+8）

**作者**：Codex (CINECA Leonardo)

**触发原因**：1055 在零自然结果时确认 T-Q 与 T-QA 的实际长度层显著不同。1037 和正式方案正文仍让单一 Generic-T 同时控制两者，这会在 G1 中重新引入相同混杂。G1 尚未解锁、无 manifest、无条件输出，因此现在可以在结果盲状态下固定原则。

---

## 1. 裁决

G1 不再使用一个 Generic-T 跨两个文本层。最小文本条件改为：

| 主条件 | 对应普通提示控制 | 主要排除对象 |
|---|---|---|
| T-Q | Generic-Q | guide questions 相对同长度普通检查文本的具体内容效应 |
| T-QA | Generic-QA | guide questions + intermediate states 相对同长度普通检查文本的具体内容效应 |

两项 generic 均不得包含样本实体、guide 内容、最终答案、选项标签或新事实。它们来自同一冻结中性词库与确定性选择器，并按 1057 在每个基础样本内分别匹配对应条件的 tokenizer 长度，误差上限为 10%。单一 generic 不得跨长度层复用。

相对 S 的 teacher gap 仍回答“增加该 privileged payload 后模型是否改善”；matched-control 对比回答“改善能否超过等长度普通提示”。两者是不同证据，必须同时报告：

\[
Gap_Q(f)=Perf(TQ,f)-Perf(S,f),
\]

\[
Specific_Q(f)=Perf(TQ,f)-Perf(GenericQ,f),
\]

\[
Gap_{QA}(f)=Perf(TQA,f)-Perf(S,f),
\]

\[
Specific_{QA}(f)=Perf(TQA,f)-Perf(GenericQA,f).
\]

`Gap>0` 但对应 `Specific≈0` 时，只能说明更长或更强的普通提示有帮助，不能归因于结构化 guide 内容。

## 2. G1 最小条件与互补分析

1037 的 G1 最小条件现为 S、V、T-Q、T-QA、Generic-Q、Generic-QA、VT-QA。VT-QA 使用与 T-QA 完全相同的文本 payload，再加入 V；PR 互补项以 T-QA 为文本边：

\[
Interaction_{PR}=Perf(VTQA,PR)-Perf(V,PR)-Perf(TQA,PR)+Perf(S,PR).
\]

T-Q 与 T-QA 的 specialization 分开报告，不允许在看到 G1 结果后择优命名为主结果。若 G0 在结果前规则下选定一个进入训练的主 T 配方，G1 仍保留另一配方作为预定机制对照。

## 3. Random 与 shuffle 控制

若 G1 纳入正式方案中的 random/shuffle 消融：

- Random-Q 与 Random-QA 分别匹配 T-Q/T-QA 的长度层；优先使用同图但与最终答案路径无关、经验证真实的 QA，避免把胡言乱语退化当成结构效应；
- Shuffled-Q 或 Shuffled-QA 必须由对应原 payload 确定性打乱，保持其 token multiset，只破坏顺序或依赖结构；
- 所有控制与主条件使用同一批 locked 题、相同 label rotations 和结果 gate；不得为某控制另选更容易的题。

Generic 控制排除普通提示与 token 数，random 控制排除“额外获得同图信息”，shuffle 控制检验结构顺序。三者不能互相替代。

## 4. 当前冻结边界

本次只冻结控制配对原则，不提前冻结 G1 的最终 N、具体中性句、random QA、shuffle 算法或多重检验族。它们依赖 G0 的独立方差和最终 G1 设计，必须在任何 G1 条件输出前另行冻结。无论以后采用何种精确实现，都不能退回单一 Generic-T 跨层比较。

1055 的自然 G0 五条件实现和 168 项测试不因本文改变。历史 G-PC0 四条件结果保持不可变，其 49/74/49 token 局限继续按 1055 解释。
