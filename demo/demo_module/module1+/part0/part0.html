OPD 的严格定义

🎯 OPD = C1 + C2 (AwesomeOPD 标准)
C1 (学生自采样)：学生在训练期间采样自己的轨迹 y∼π_S(·|x)
C2 (教师在线监督)：教师在这些学生样本上提供逐 token / 序列级监督
OPSD：C1+C2，但教师=同一模型(特权上下文)

PAPER 1 · arXiv: 2306.13649 · ICLR 2024
GKD — On-Policy Distillation of Language Models
R. Agarwal, N. Vieillard et al. · Google DeepMind
一句话核心贡献：在 LLM 时代正式命名 OPD (On-Policy Distillation) 的奠基论文。证明学生在自生成 rollout 上的蒸馏在 token 效率上同时击败 SFT 和 RL，奠定了整个 OPD 领域的范式基础。
📄 P1 · S2/5

背景动机 · 问题定义

🔴 离线蒸馏的致命缺陷

传统 KD: 教师生成固定数据集→学生训练。但训练-推理分布不匹配：学生训练时看到的状态(教师数据分布)与推理时自己生成的状态(学生分布)不同→性能损失。这一问题在 LLM 中因自回归生成而尤为严重。

🟡 GKD 的解决方案

让学生自己生成 rollout (满足 C1)→教师在这些学生样本上提供逐 token logit 监督 (满足 C2)→学生的训练分布 = 推理分布→消除分布不匹配。

📄 P1 · S3/5

核心方法 · GKD 训练流程

$$\mathcal{L}_{GKD} = \mathbb{E}_{x\sim\mathcal{D}, y\sim\pi_S(\cdot|x)}\left[ D_{KL}(\pi_T(\cdot|y_{
① 从数据集采样 prompt x → ② 学生自回归生成完整响应 y → ③ 教师对每个 token 位置提供 logit 分布 → ④ 用 KL 散度训练学生匹配教师分布 → ⑤ 学生分布随训练逐渐向教师靠拢。GKD 同时支持 Forward KL 和 Reverse KL 两种模式。
📄 P1 · S4/5

实验与关键结果

核心实验发现：
• GKD 在 相同 token 预算下，显著优于 SFT 蒸馏和纯 RL
• 在线采样 (学生自采样) 是性能提升的关键——分布匹配收益 > 教师数据质量
• Reverse KL 在大多数任务上优于 Forward KL——模式追寻更适合 LLM 蒸馏
• 学生规模越小，GKD 相对于 SFT 的优势越显著
📄 P1 · S5/5

局限 · 审视 · 影响

⚠️ 作者自述

• 每次迭代需教师前向→计算开销高
• 仅白盒场景(教师 logits 可访问)
• RKL 的模式坍缩风险未充分解决

🔍 历史地位

GKD 是 OPD 的"宪法"——后续所有白盒 OPD 工作 (DistiLLM/REOPOLD/G-OPD 等) 都在其框架下改进。ICLR 2024 接收标志着学术界对 OPD 范式的正式认可。

📄 P2 · S1/5
PAPER 2 · arXiv: 2306.08543 · ICLR 2024
MiniLLM — Knowledge Distillation of Large Language Models
Y. Gu, L. Dong et al. · Microsoft / 清华大学
一句话核心贡献：比 GKD 早几天发表的"OPD 鼻祖"。首次使用Reverse KL + Policy Gradient实现在线蒸馏——学生在自生成 rollout 上通过策略梯度直接优化 Reverse KL 散度。ICLR 2024。
📄 P2 · S2/5

背景动机 · 方法

🔴 标准 KD 的局限

标准 KD 使用Forward KL——要求学生覆盖教师的所有模式。但学生能力有限→无法同时覆盖→分布过于分散→生成质量下降。MiniLLM 选择 Reverse KL: 学生只需集中在教师高概率区域。

🔑 Reverse KL + PG

$$\nabla_\theta \mathcal{L} = \mathbb{E}_{y\sim\pi_S}[-\nabla_\theta \log\pi_S(y) \cdot D_{KL}(\pi_S\|\pi_T)]$$使用 Policy Gradient 直接优化 Reverse KL——因为 Reverse KL 对 π_S 的梯度不能直接通过参数求导。

📄 P2 · S3/5

实验 · 局限

关键发现：MiniLLM 在指令遵循和文本生成上显著优于标准 KD——Reverse KL 的模式追寻更适合 LLM。
局限：① Reverse KL 的模式坍缩风险 (后来 REOPOLD 专门解决) ② PG 训练的方差较大 ③ 需要教师实时前向→计算开销高。
📄 P2 · S4/5

GKD vs MiniLLM 对比

两大奠基论文的差异：
• KL 方向：GKD 同时支持 FKL/RKL；MiniLLM 只用 RKL
• 优化方法：GKD 用标准梯度；MiniLLM 用 Policy Gradient
• 历史地位：GKD 命名了 OPD 并建立通用框架；MiniLLM 率先证明了 RKL+PG 在 LLM 蒸馏中的有效性
• 共同遗产：两者共同开启了白盒 OPD 的范式——学生自采样 + 教师逐 token 监督
📄 P2 · S5/5

影响与后续

MiniLLM 的 RKL+PG 方案直接启发了后续一整条技术线：DistiLLM (Skewed-KL 混合 FKL/RKL)→Entropy-Aware OPD (动态 KL 方向)→REOPOLD (解决 RKL 的模式坍缩/近零奖励/重尾负奖励)。从 MiniLLM 到 REOPOLD，KAIST 团队用了 3 年完成了 RKL 从"有用但不稳定"到"生产就绪"的进化。

PAPER 3 · Thinking Machines Lab · 2025.10
On-Policy Distillation Blog — "swap KL ref for stronger teacher"
thinkingmachines.ai/blog/on-policy-distillation
一句话核心贡献：被 AwesomeOPD 评为"最清晰的 OPD 单页解释"。用一句话概括 OPD 本质："把 KL 正则化中的参考策略换成一个更强的教师"。将 OPD 的核心直觉浓缩为可立即理解的类比。
📄 P3 · S2/5

背景 · OPD 与 RL 的关系

标准 RL 训练中，KL 正则项 −β·D_KL(π_θ‖π_ref) 用于防止策略偏离太远。OPD 的巧妙之处：把 π_ref 换成更强的教师策略 π_T。原本用于"约束"的 KL 项瞬间变成了"学习"的驱动力——不需要额外的蒸馏步骤。
📄 P3 · S3/5

核心洞察：为何 OPD 同时击败 SFT 和 RL

SFT：学生只在教师见过数据上训练→分布不匹配→泛化差
纯 RL：学生自己探索但奖励稀疏→效率极低
OPD：学生自己探索(在线采样) + 教师提供密集逐 token 信号(KL 监督)→两全其美

PAPER 4 · arXiv: 2603.25562 · 2026.03
Revisiting OPD — 诊断 3 种失效模式
CASIA (中科院自动化所)
核心贡献：系统诊断 OPD 在实践中失败的三种具体原因，补充了 UIUC (P7) 未覆盖的维度。
📄 P4 · S2/5

三大失效模式

① 单token信号不平衡

关键决策 token 和填充 token 被同等对待→关键信号稀释。与 REOPOLD 问题二同源。

② 前缀不可靠

学生劣质前缀污染教师输入→恶性循环。与 UIUC (P7) 一致。

③ tokenizer不匹配

师生不同 tokenizer 时 KL 失去意义。CASIA 首次诊断此问题。

📄 P4 · S3/5

与 UIUC (P7) 的互补关系

UIUC 诊断：分布不匹配 + 优化不稳定 + PI-free 限制
CASIA 诊断：token 信号不平衡 + 前缀不可靠 + tokenizer 不匹配
两者覆盖了不同层面的问题：UIUC 偏宏观机制，CASIA 偏 tokenization 和信号层面的系统性问题。共同构成OPD 失效的完整诊断体系。
📄 P4 · S4-5/5

🔧 S4: 修复建议

针对三个失效模式分别提出：token重要性加权 / Stop-Gradient 保护教师输入 / 跨tokenizer对齐机制。

⚠️ S5: 局限

诊断性论文——提出问题和修复方向，但未在统一框架下验证修复的联合效果。

📄 P6 · THUNLP Rethinking
PAPER 6 · arXiv: 2604.13016 · 2026.04
THUNLP Rethinking OPD — 两个成功条件
清华大学

✅ 条件一

兼容思维模式：学生必须有能力覆盖教师的推理空间。教师策略与学生能力不兼容时 OPD 失效。

✅ 条件二

真正新的教师能力：教师必须在学生薄弱的维度上更强。学生已掌握的技能→OPD 无增益。

OPD 反思 Blog — 三个失败机制 (Li Jiang)

⚠️ 局部教师噪声

教师某些 token 上 logits 噪声→OPD 放大→学生学到错误信号。

⚠️ 覆盖衰减

学生分布偏移→教师覆盖下降→信号持续衰减。

⚠️ 短视梯度

逐 token KL 忽略长期后果→早期决策梯度被后期稀释。
