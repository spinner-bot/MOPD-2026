RL 基础概念

在深入三篇论文之前，先掌握强化学习的基本词汇—— 后面所有公式和算法都建立在这些概念之上。

R · 奖励信号 任务 · Task π · 策略 Q · 价值函数 神经网络表示
DAG位置：最顶层基础节点 → 向下支撑所有论文节点

📚 RL 核心概念 — R, 任务, π, Q

💬 讨论

🎯 R (Reward) — 即时奖励

智能体每执行一个动作，环境返回的数字分数。
例：机器人往前走一步 → R=+1；摔倒 → R=−10。
Rᵢ(s,a) = 在第i个任务中，状态s下做动作a的即时奖励。

📋 任务 (Task) — 由奖励函数定义

任务 = 要达成什么目标，由怎么给分来决定。
任务1 (走路)：速度越快R越高。
任务2 (导航)：离目标越近R越高，撞障碍R负。

🧭 π (Policy) — 策略，决策大脑

π(a|s) = 给定状态s，选择动作a的概率分布。
它是智能体的"行为准则"——看到什么状态，该做什么动作。

📊 Q(s,a) — 价值函数，未来预言

Q(s,a) = 从状态s执行动作a后，按照某策略继续走，未来能拿到的累积折扣奖励之和。
Q值告诉你：这个动作在长远来看有多好？

💡 在OPD中：每个任务i有自己的Rᵢ → 训练出πᵢ → πᵢ的Q值反映其"局部智慧" → 蒸馏到共享π₀

🤖 为什么π和Q要用神经网络表示？

💬 讨论

❌ 为什么不能手写？

实际RL场景中，状态s是高维连续向量（如机器人关节角度×速度×触地传感器 = 数百维）。可能的(s,a)对是天文数字，完全无法靠人列表格或写死规则。

✅ 神经网络的方案

神经网络是一种万能函数近似器，从数据中自动学习映射。
• 策略网络 π_φ(a|s)：输入s → 输出动作概率
• 价值网络 Q_θ(s,a)：输入s和a → 输出一个预期回报数值
可以内插推广：见到相似状态也能给出合理输出。

💡 理解了这个，才能明白后面"基座/backbone"、"网络共享"、"列/column"等概念

🔄 RL 核心循环 — 智能体与环境的对话

💬 讨论
🧠 智能体 Agent 策略 π + 价值 Q

观察状态 → 做出决策

动作 a →
← 状态 s, 奖励 R
🌍 环境 Environment MDP / 物理世界

接收动作 → 返回状态+奖励

每个时间步 t：
① 智能体观察状态 sₜ → ② 根据策略 π 选择动作 aₜ → ③ 环境执行 aₜ →
④ 环境返回新状态 sₜ₊₁ 和即时奖励 Rₜ → ⑤ 智能体用 (sₜ, aₜ, Rₜ, sₜ₊₁) 更新策略
目标：找到最优策略 π*，使累积折扣奖励 ΣγᵗRₜ 最大化

🤖 具体例子：训练机器人走路

💬 讨论

🎯 任务 1：学会走路

状态 s：关节角度、速度、触地传感器
动作 a：每个马达的力矩（连续值）
奖励 R：前进速度越快→R越高，能耗低→加分
策略 π："看到这个身体姿态，该用什么力度蹬腿"
Q值："在这个姿态下蹬这一腿，长远来看能走多远"

🎯 任务 2：学会导航

状态 s：位置坐标、障碍物距离、目标方向
动作 a：转向角 + 移动速度
奖励 R：离目标越近→R越高，撞障碍→R=−10
策略 π："看到障碍物在左前方，该往右绕"
Q值："在这个位置选择向右绕，长远能避开多少麻烦"

💡 关键观察：同一个机器人，任务1和任务2的奖励函数R不同，行为就完全不同。 在OPD中，每个任务i有自己专属的Rᵢ和策略πᵢ——这就是Distral公式里下标i的含义。 但问题来了：如果我们需要机器人学会跑、跳、翻滚，而这些动作的奖励函数很难人工编写（你很难用数学公式描述"什么是跑"），怎么办？这将是Part 2要解决的核心问题。

🔧 π 和 Q 具体怎么用神经网络实现？

💬 讨论

🧭 策略网络 π_φ(a|s)

输入：状态向量 s（关节角度、速度等拼接）或图像像素
离散动作（左/右/前进）：

s → FC → ReLU → FC → Softmax → [p₁,p₂,p₃]
每个动作一个概率，和为1

连续动作（马达力矩）：

s → FC → ReLU → FC → μ, σ (Gaussian)
从 N(μ,σ) 中采样实际动作值

训练：用策略梯度 / PPO 最大化期望累积奖励

📊 价值网络 Q_θ(s,a)

输入：状态 s + 动作 a（拼接为一个向量）
输出：一个标量数字 = 从(s,a)开始的累积折扣奖励预测

[s; a] → FC → ReLU → FC → 标量 Q(s,a)

训练：最小化 TD 误差 — 让 Q(s,a) ≈ r + γ·max_{a'} Q(s',a')

💡 为什么能内插推广？
神经网络见到训练中从未出现的 (s,a) 组合时，也能给出合理的近似值——这是查表法永远做不到的。

Distral (2017)

"理论家" — 蒸馏作为多任务通信协议

DAG位置：汇聚节点 — Policy Distillation + Actor-Mimic 两条支线在此汇合，形成统一框架。以下4页展开其核心内容。

🧠 Distral — 联合目标函数 J(π₀, {πᵢ})

两个层级：共享中心策略 π₀（捕获通用行为）+ 任务策略 πᵢ（专门解决第i个任务）

$$J(\pi_0, \{\pi_i\}) = \sum_i \mathbb{E}_{\pi_i}\left[\sum_{t \ge 0} \gamma^t R_i - c_{\text{KL}} \gamma^t \log\frac{\pi_i}{\pi_0} - c_{\text{Ent}} \gamma^t \log \pi_i\right]$$
①
标准RL奖励
ΣγᵗRᵢ
完成自己的任务
最大化累积回报
②
KL惩罚项
−c_KL·log(πᵢ/π₀)
别离中心策略太远
实现知识共享
③
熵奖励项
−c_Ent·log πᵢ
保持策略随机性
鼓励探索新动作

👆 点击展开公式拆解 (1/3)

🌊 软 Q 学习视角 — "硬选最大" vs "软分布"

💬 讨论

核心思想：把探索和偏离惩罚"揉"进奖励，让智能体追求一种"软"版本的最优动作

🔴 传统 Q 学习（硬）

目标：只最大化 ΣγᵗR
最优动作：a* = argmax_a Q(s,a)
策略：确定的——永远选Q值最高的
问题：没有探索机制，容易陷入局部最优

// 硬最大：只选最高的
a* = argmax(Q[s,:])

🟢 软 Q 学习（软）

目标：最大化 Σγᵗ(R + α·H(π))
最优动作：按 exp(Q/β) 的玻尔兹曼分布采样
策略：概率分布——高Q值的动作概率高，但低Q值的也有机会
软贝尔曼方程：V_soft = β·log Σ exp(Q/β)

// 软最大(LogSumExp)：概率分布
p(a) ∝ exp(Q[s,a] / β)

🔗 在 Distral 中的体现：
最优策略 πᵢ ∝ π₀^α · exp(Qᵢ/β) 就是软 Q 学习的直接推论——它不仅对 Q 值取 Softmax，还把先验 π₀ 作为额外权重因子。
好处：将带有多约束（探索 + 知识迁移 + 保持风格）的复杂策略优化，转化为标准的软 Q 迭代问题，可直接用 Q 学习工具求解。

🔍 KL散度深入 — 那把测量"差距"的尺子

💬 讨论
$$D_{KL}(P \| Q) = \sum_a P(a) \log\frac{P(a)}{Q(a)}$$

📐 核心性质

• 如果P和Q完全一样 → KL=0
• 只要有一点点不同 → KL > 0
• 不对称：D_KL(P‖Q) ≠ D_KL(Q‖P)
• 我们用的是前向KL：要求P覆盖Q的所有行为

🎯 在Distral中的作用

−c_KL · D_KL(πᵢ ‖ π₀) → 惩罚πᵢ偏离π₀
最大化J → 必须最小化KL散度 → πᵢ被迫靠近π₀。
这就是知识共享的数学机制。

🪢 比喻：家长划的"活动圈"

中心策略π₀ = 家长给孩子划的安全玩耍范围。
孩子(πᵢ)可以在圈内自由探索，但跑出圈外会被KL惩罚"拉回来"。圈的大小由c_KL调节。

🔑 关键理解

KL正则化 = "软"约束：不是禁止偏离，而是偏离了会扣分。算法自行权衡利弊——这正是不确定性下灵活决策的精髓。

🎯 最优策略闭式解 & 贝叶斯直觉

最大化J后，πᵢ的最优形式（可直接用Q学习迭代求解）

$$\pi_i(a|s) \propto \pi_0(a|s)^{\alpha} \cdot \exp\!\left(\frac{Q_i(s,a)}{\beta}\right)$$

α = c_KL/(c_KL+c_Ent) · β = c_KL+c_Ent

📜先验 Prior π₀^α · 集体智慧
×
🎯似然 Likelihood exp(Qᵢ/β) · 任务价值
=
✅后验 Posterior πᵢ · 最优任务策略
α
先验强度
α大 → 保守，紧跟中心
α→0 → 纯Q值驱动，不用先验
β
温度参数
β大 → 随机，偏探索
β小 → 贪婪，偏利用

💡 这就是软Q学习视角：不是硬选Q最大的动作，而是通过exp(Q/β)形成概率分布——"软"就软在这里

🔄 "蒸馏作为通信" — 双向知识循环

📥 蒸馏 Distill
π₁ → π₀ ← π₂

子策略把经验"上交"给中心
π₀ = argmin Σᵢ D_KL(πᵢ ‖ π₀)
汇聚共性智慧 → 集体笔记

🧑‍🏫 子策略=教师，中心=学生

⇄
循环
📤 广播 Broadcast
π₀ → π₁, π₂

中心把通用行为"广播"回去
通过KL正则 πᵢ∝π₀^α·exp(Qᵢ/β)
约束子策略，引导探索方向

🧭 中心=文化约束/行为锚点

关键洞察：蒸馏不再是单向教→学，而是双向、社会化的知识共享。π₀一开始可能是空的——它靠吸收所有πᵢ的经验成长，同时立刻广播回去影响πᵢ的探索。互为师生，共同进化。

Actor-Mimic (2016)

"工程师" — 条件蒸馏 + 特征回归 + 行为克隆

DAG位置：右侧分支 — RL基础 → Actor-Mimic → 汇入Distral。其"硬压缩"与KL的"软约束"形成对比。

🔬 条件蒸馏 — 只学教师"有把握"的状态

$$\mathcal{L}_{\text{distill}}(s) = \begin{cases} D_{KL}(p_T\|p_S) & \text{if } \max_a Q_T(s,a) > \theta \\ 0 & \text{otherwise} \end{cases}$$
✅ max Q_T(s,a) > θ
蒸馏！模仿教师

教师有把握 → 值得学

❌ max Q_T(s,a) ≤ θ
跳过，损失=0

教师也困惑 → 不学垃圾

🎯 Q值截断直觉

类比：只总结学霸有把握的解题方法，不学他们瞎蒙时的做法。防止噪声污染共享知识库。

🔗 特征回归

L_feature = ‖f_T(s) − W_r·f_S(s)‖²。不仅模仿"做什么"（动作输出），还模仿"怎么看"（中间层特征表征）。

🎓 专家策略 & 行为克隆 — "先揉到一起，再各自优化"

💬 讨论

👑 什么是"专家策略"？

先为每一个任务单独训练一个高性能智能体。这些训练好的π₁*, π₂*, ...就是专家策略——各自任务的"老手"，已经拿到很高奖励。它们被冻结，用作监督标签。

📝 什么是"行为克隆"？

用监督学习让学生网络π_multi(a|s,i)去模仿专家输出。损失=交叉熵（离散动作）或MSE（连续动作）。不需要环境交互，纯粹地模仿专家的动作分布。

🔀 Actor-Mimic 两步走

步骤一：多任务模仿（揉到一起）
学生网络输入(state, task_id)，模仿所有专家的行为 → "什么都会一点"的泛化策略。

步骤二：各自微调（各自优化）
以学生网络为初始化，每个任务单独用RL微调。因为起点已经很合理，微调所需样本远少于从头训练。

💡 这就是"先培养全能天才，再让他成为各领域专家"

⚖️ 软约束 vs 硬约束 — KL正则化 vs 行为克隆

💬 讨论

这一对比揭示了 OPD 设计中一个核心哲学选择：给不给策略"讨价还价"的空间？

🪢 KL正则化 — "软"约束

机制：目标函数中加惩罚项 −c_KL·D_KL(πᵢ‖π₀)
特点：允许偏离，但偏离了要扣分。算法自动权衡"多拿奖励"和"别走太远"。
比喻：橡皮筋拉着你——可以撑开走远，只是越来越费力。
结果：πᵢ可以超越π₀，只要有足够的任务奖励支撑。

🔒 行为克隆 — "硬"压缩

机制：监督学习——学生输出必须和专家一模一样。
特点：没有"适度偏离"的余地，强行复制专家行为。
比喻：抄作业——只能原样照抄，不能有自己的解法。
结果：学生能力上限 ≤ 专家。但作为初始化很好用。

在DAG中的位置：KL软约束来自Distral，硬压缩来自Actor-Mimic——两条线最终都汇入OPD的技术工具箱，各有适用场景。

🏗️ 基座网络 & 共享特征 — 多任务学习的结构基础

🧱 什么是基座 (Backbone)？

多个任务共享的那部分网络层。
前面几层（靠近输入的）学通用特征：如边缘、纹理、运动原语。后面每个任务各自接一个"头"做特定输出。基座可以硬共享（强制共用）或软共享（参数相近但不完全一样）。

📊 为什么需要共享基座？

• 样本效率：通用特征一次学习，所有任务受益
• 知识迁移：任务A学到的边缘检测自然用于任务B
• 与OPD的关系：蒸馏出的π₀本质上就是一个"行为基座"——捕获所有任务共有的动作模式

软/硬共享对比：KL正则 → 基座的"软共享"（允许偏离但惩罚）。Actor-Mimic的行为克隆 → 基座的"硬共享"（强制复制）。这和我们Slide 17讨论的软vs硬约束是同一哲学的不同体现。

🏛️ Progressive Nets — 另一条解决路径

💡 核心思想

学新任务时不动旧网络参数，新增一整套路网络（称为一"列"），并通过横向连接把之前所有旧列的特征都接进来。彻底解决灾难性遗忘。

progressive_net.py
# 列1 (任务1) → 冻结
col1_l1 → col1_l2 → col1_l3 → output1
   ↘ adapter
# 列2 (任务2) → 可训练
concat(col2_l1, col1_l1) → col2_l2 → ...
# 每一列 = 一整套网络（多层）

⚠️ 参数增长问题

1个任务 = 100万参数。10个任务 = 1000万+参数（线性增长）。任务多了存不下、跑不动。

后续优化方向：
• PackNet：剪枝+复用空置权重
• EWC：用Fisher信息矩阵保护重要权重
• PathNet：固定大小的模块库，按需组合
• 趋势：从全量硬增长 → 灵活模块化复用

🔗 与OPD的关系

KL正则 → "软"约束。Actor-Mimic → "硬"压缩。Progressive Nets → 第三种路径：不约束也不压缩，直接扩展。它的扩展性局限直接引出了后续更灵活的模块化方法。

🔮 UNREAL (2016) — 辅助预测头：让特征"理解世界"

💬 讨论

❓ 问题：蒸馏只学了"做什么"

在 Actor-Mimic 的蒸馏中，中心策略只模仿了子策略的动作概率分布 p_T。但这忽略了一个关键：环境的运转规律——球推一下滚多远、踩地摩擦力如何、开关按下灯会亮——这些"世界模型"没有被蒸馏。

💡 UNREAL 的解决方案

在 A3C 基础网络上并行挂多个辅助预测头，与主 RL 任务同时训练：
• 像素控制头：预测动作后画面哪些像素会变
• 奖励预测头：预测接下来几步的奖励序列
• 价值回放头：对历史经验再做价值估计训练

🔧 如何影响模型？

辅助头不是死输出——每个头都有自己的损失函数。总损失 = 主RL损失 + λ₁·像素损失 + λ₂·奖励损失 + ...。

通过反向传播（梯度下降），辅助任务的梯度分量也流入共享基座层，强制基座在提取特征时编码环境动态信息。

📈 效果：样本效率

用更少的数据达到同等性能。因为基座已经对"世界怎么运转"有了内部模型，主任务不需要从零摸索所有因果。在OPD语境下，把这种特征蒸馏进π₀ → 中心策略不仅"知道该做什么"，还"知道世界怎么运转"。

🌿 支线的支线 — Progressive Nets 参数增长问题的替代方案

仅了解

以下三种方法各自解决了"参数随任务数线性增长"的问题，但走的是不同的路。 此处仅作概念了解，不做深入展开。

✂️ PackNet

策略：训练完一个任务后剪枝（去掉不重要的权重），冻结剩余。下一个任务只用空出来的权重。
优势：参数总量恒定不变。
代价：任务间不共享特征表达，每个任务占用独立子空间。

🧲 EWC

策略：用Fisher信息矩阵识别对旧任务重要的权重，给这些权重的变化施加惩罚——重要参数锁定，不重要参数自由调整。
优势：所有任务共用一个网络，参数不增长。
代价：难以完美平衡新旧任务的性能。

🧩 PathNet

策略：预定义一堆小型模块（模块库大小固定），每个任务通过进化算法或梯度学习选择哪些模块组合最适合自己。
优势：模块库不随任务增长，自然支持模块复用。
代价：模块路由的学习本身有开销。

🔀 趋势：从 Progressive Nets 的"全量硬增长" → PackNet的"剪枝复用" → EWC的"受控遗忘" → PathNet的"模块化组合"。 核心方向：灵活复用 > 线性扩展

🤖 支线·桥梁 · SECTION 4.5

缺口：当奖励信号缺失时

萌芽期框架的致命前提——必须有Rᵢ才能启动

DAG位置：桥梁节点 — 连接Part 1的"有奖励蒸馏"到Part 2的"无奖励技能发现"

🤖 机器人的困境 — 有些技能，R函数根本写不出来

💬 讨论

✅ 容易写 R 的技能

• 走路：前进速度 → R = 速度×Δt − 能耗×c
• 导航：距离目标 → R = −distance(target, pos)
• 抓取：物体是否被拿起 → R = +1 if grasped else 0
这些都有明确的数学定义。

❌ 极难写 R 的技能

• 跑：怎么用数学定义"跑"vs"走"？速度阈值？太粗暴
• 跳：四足离地？那摔倒也算"跳"吗
• 翻身：角度变化？用哪个轴？
• 跳舞：基本无法用公式描述
这些需要无监督方法。

🔥 这就是萌芽期框架的致命缺口：Distral 要求每个任务都有明确的奖励函数 Rᵢ。但现实中，大量有价值的技能根本没有清晰的奖励定义。
如果不能解决这个问题，OPD 的技能库就被限制在"人能写清楚奖励"的狭窄范围内。

🔮 预览：无监督技能发现 — 不靠R也能"玩"出技能

💬 讨论

🔑 核心思路 (DIAYN, 2018)

① 随机分配技能编号 z（z=0,1,...,K−1）
② 训练判别器 D(z|s)：根据机器人状态猜它正在执行哪个技能
③ 伪奖励 = log D(z|s)：如果判别器能轻松识别出技能z，就给高分
④ 同时最大化策略熵：防止技能坍缩为同一个动作

结果：不同z自动演化出不同运动模式——跑、跳、翻身，完全不需要人定义"什么是跑"。

🔗 如何与OPD衔接？

这些无监督发现的技能，就可以作为Distral里的"教师策略"πᵢ——即便它们根本没有任务奖励Rᵢ。

中心策略π₀从这些"自己玩出来的技能"中蒸馏出通用运动基座，以后微调到具体任务（如追赶目标）时速度极快。

这填补了"没有奖励信号怎么办"的缺口。

🛠 工程实践

K个技能通常设得比目标动作多（如设50个），自由分化后人工筛选（看视频选出"最像跑"的z*）。选出后用真实奖励R微调，或用KL约束保持原始技能风格——最终把它打磨成真正可用的技能。

🔬 K-means 类比 — 技能发现 vs 静态聚类

💬 讨论

📊 K-means（静态聚类）

• 对已有的数据点分组
• 需要人工定义特征维度
• 分配标签后不改变数据本身
• 聚类质量取决于初始中心点

🤖 DIAYN 技能发现（动态生成）

• 智能体主动修改数据生成过程
• 维度由传感器硬件决定（关节角度/速度/触地）
• 神经网络自动抽取区分特征
• 策略被驱动使簇间差异最大化

💡 本质区别：K-means 是对已存在数据贴标签；DIAYN 是让智能体主动改变自己的行为来产生更容易被区分的状态轨迹。这是"被动分类"和"主动塑造"的根本不同。

📐 互信息 I(S;Z) — 技能多样性的数学保证

💬 讨论
$$I(S; Z) = H(S) - H(S|Z)$$

🔑 三个核心概念

H(S)：状态总不确定性—所有技能混合在一起时，状态分布有多"乱"

H(S|Z)：已知技能编号后的剩余不确定性—知道是哪个技能后，还能猜中状态吗？

I(S;Z)：互信息—知道技能编号能减少多少状态的不确定性。越大 → 技能之间越容易区分

🎯 最大化 I(S;Z) 的效果

强迫 H(S|Z) 尽可能小 = 给定技能编号就能猜出状态
→ 不同技能必须访问不同的状态区域
→ 自然涌现可区分的运动模式

📊 状态访问分布 d^π(s)

策略 π 长期运行时，处于各状态的概率分布。"跳"的状态分布在关节高频震荡区，"走"在低频摆动区。统计依赖：两个变量不独立，知道一个就能预测另一个——互信息是量化这种依赖的最高指标。

💡 伪奖励 log D(z|s) — 判别器猜得越准→互信息越大→技能越多样化→自然分簇

🔧 选出技能后，如何精细优化？— 三种微调方法

💬 讨论

无监督发现的技能只是"接近"目标，需进一步精炼。K个技能设得比目标多（如50个），人工筛选后微调。

🎯 1. 微调 + 任务奖励 R

为选出的技能设计真实奖励函数（如"速度越快分越高"）。以无监督策略为初始化，用RL（PPO/SAC）继续训练。
优势：起点已经很接近，只需少量样本。

👁️ 2. RLHF (人类反馈)

写不出R时，让人当评判：看视频 → 选"更像跑"的那段 → 用偏好信号训练奖励模型 → 用奖励模型微调策略。
优势：把模糊的人类感觉变成可优化的目标。

🔒 3. KL 约束微调

微调时加 KL 散度项约束新策略不要偏离原始无监督策略太远。
优势：防止为追求高奖励而动作变形，保持技能原有"风格"——这正是Distral框架思想的延续。
